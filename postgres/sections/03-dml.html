❓ 03.1 · 如何一条 SQL 完成“插入或更新并立刻拿到修改后的整行数据”，彻底告别应用层先查后改？

⚡ 03.1 生产力三剑客：RETURNING + ON CONFLICT (UPSERT) + LATERAL JOIN

🐘 upsert_and_returning.sql · 原子写入与返回 
-- 1. RETURNING：插入/更新/删除后直接把结果当 SELECT 返回
INSERT INTO users (email, status)
VALUES ('alice@example.com', 'active')
RETURNING id, created_at;

-- 2. 原子 UPSERT：唯一键冲突则更新（EXCLUDED 代表本次试图插入的新行）
INSERT INTO users (email, status)
VALUES ('alice@example.com', 'vip')
ON CONFLICT (email) DO UPDATE
  SET status = EXCLUDED.status,
      updated_at = now()
RETURNING *;

-- 若冲突时什么都不做（幂等去重插入）：
INSERT INTO users (email) VALUES ('alice@example.com')
ON CONFLICT (email) DO NOTHING;

-- 3. DELETE + RETURNING：一行代码实现“弹出并删除任务”
DELETE FROM job_queue WHERE id = 42 RETURNING *;

🔗 五种标准 JOIN + PG 特色 LATERAL 横向关联

JOIN 类型 集合语义与典型用途
INNER JOIN 交集 $A \cap B$：仅返回左右两表都能匹配上的行
LEFT JOIN 保留左表全集：右表无匹配则补 NULL（配合 WHERE b.id IS NULL 可查差集）
RIGHT JOIN 保留右表全集，左表无匹配补 NULL
FULL OUTER JOIN 并集 $A \cup B$：左右两表全部保留，各自无匹配处补 NULL（MySQL 不支持原生 FULL JOIN，PG 原生支持，对账神器！）
CROSS JOIN 笛卡尔积 $A \times B$：无连接条件，生成所有组合
⭐ LEFT JOIN LATERAL 横向子查询关联：允许右侧子查询直接引用左表当前行的列（如“为左表每个用户走索引直接取最新的 3 笔订单”），比全表窗口函数快数倍！
❓ 03.2 · 窗口函数和 GROUP BY 有什么本质区别？如何用一句 SQL 查出无限级部门树？

👑 03.2 面试必考王牌：窗口函数（Window Functions）与递归 CTE

普通聚合 GROUP BY 会把每个分组的多行“压扁成一行”，丢失明细行；而窗口函数（OVER (PARTITION BY ... ORDER BY ...)）在不减少原表行数的前提下，为每一行开启一个滑动视窗计算排名、累计值或前后行差值。

📊 1. 窗口函数对比与分组取 Top-1 经典模板

窗口函数 并列处理与典型场景
row_number() 连续唯一行号（1, 2, 3, 4）：即使数值并列也强行分先后，常用于“每组只取严格 1 条最新记录”。
rank() 并列跳号排名（1, 1, 3, 4）：奥运奖牌榜逻辑（两个并列第一，下一个是第三名）。
dense_rank() 并列不跳号排名（1, 1, 2, 3）：适合“取每个部门薪水前 3 档的所有员工”。
lag(col, 1) / lead(col, 1) 取同组前一行 / 后一行的值：无需自连接即可计算日环比增长率、相邻两次登录时间差。
sum(col) OVER (...) 若不带 ORDER BY 算组内总和（算占比）；若带 ORDER BY 则算从头到当前行的滚动累加值！

🌲 2. 窗口函数 + WITH RECURSIVE 递归 CTE 实战

🐘 window_and_recursive_cte.sql 
-- 经典题 1：取每个用户金额最高的一笔订单（CTE + row_number）
WITH ranked_orders AS (
  SELECT id, user_id, amount,
         row_number() OVER (
           PARTITION BY user_id ORDER BY amount DESC, id DESC
         ) AS rn
  FROM orders
)
SELECT id, user_id, amount FROM ranked_orders WHERE rn = 1;

-- 经典题 2：WITH RECURSIVE 递归查询部门树（向下查所有子孙部门）
WITH RECURSIVE dept_tree AS (
  -- ① 锚点成员 (Anchor)：先找出根节点（id = 1）
  SELECT id, name, parent_id, 1 AS depth, name::text AS path
  FROM dept WHERE id = 1
  UNION ALL
  -- ② 递归成员 (Recursive)：拿上一轮结果 sub 关联子表 d
  SELECT d.id, d.name, d.parent_id, sub.depth + 1,
         sub.path || ' > ' || d.name
  FROM dept d
  JOIN dept_tree sub ON d.parent_id = sub.id
)
SELECT * FROM dept_tree;
❓ 面试自测：为什么不能直接写 WHERE row_number() OVER (...) = 1？SQL 各子句的真实执行顺序是什么？

SQL 引擎的逻辑执行顺序为：
① FROM / JOIN ➔ ② WHERE（行级过滤）➔ ③ GROUP BY（分组聚合）➔ ④ HAVING（组级过滤）➔ ⑤ 窗口函数 OVER(...) ➔ ⑥ SELECT 投影 ➔ ⑦ DISTINCT ➔ ⑧ ORDER BY ➔ ⑨ LIMIT / OFFSET。
因为 WHERE 在第 ② 步执行时，连分组和第 ⑤ 步的窗口函数都还没有计算出来（而且窗口函数的结果高度依赖 WHERE 过滤后剩下哪些行），所以必须在子查询或 WITH (CTE) 里先算出 rn，再在外层查询写 WHERE rn = 1。
