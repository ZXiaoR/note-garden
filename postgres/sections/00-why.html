💡 从第一性原理出发：同样是关系型数据库，PostgreSQL 和 MySQL 到底分道扬镳在哪里？

很多同学学完 MySQL 再看 PostgreSQL（简称 PG），会觉得：“不都是建表、写 SQL、建 B+ 树索引、开事务么？为什么要多学一套？”
但只要进入复杂业务、AI 向量检索、GIS 地理空间、海量 JSON 文档或高并发更新场景，你会发现两者的底层脾气截然不同——因为它们在设计之初做出了三个最根本的底层架构抉择：

  • 抉择一：表数据怎么存？（堆表 Heap vs 索引组织表 IOT）
    MySQL InnoDB 的表本身就是一棵主键 B+ 树（聚簇索引），数据行按主键顺序存在叶子节点里，二级索引存的是主键值（查二级索引要再查一遍主键树，即回表）；而 PostgreSQL 的表是无序追加的堆表（Heap Table），每一行有一个物理坐标 ctid = (页号, 页内槽位号)，主键和普通索引平起平坐，统统直接存 ctid 指向堆表物理位置。
  • 抉择二：改一行数据时，旧版本放哪？（追加新元组 vs Undo Log 回滚段）
    MySQL InnoDB 原地修改数据页，把旧版本写进独立的 Undo Log；而 PostgreSQL 采用追加写多版本（Append-Only MVCC）：UPDATE = 把旧行标上失效事务号 xmax + 在堆表里直接插入一条新版本行 (xmin)！这样事务回滚几乎是 O(1) 瞬间完成（不用重放 Undo），但也直接导致了 PG 最具辨识度的运维核心：死元组（Dead Tuple）堆积 → 表膨胀（Bloat）→ 必须靠 VACUUM 清道夫回收与 Freeze 防事务 ID 回卷。
  • 抉择三：数据库只存简单标量，还是允许扩展一切？（ORDBMS 对象-关系型底座）
    PostgreSQL 把自己设计成一个可扩展的类型与索引框架：原生内置 JSONB、数组、范围类型，提供 6 大索引引擎（B-tree / GIN / GiST / SP-GiST / BRIN / Hash），还能通过扩展（PostGIS 空间地理、pgvector 向量数据库）直接生长出新物种。

⚔️ 一表打通：PostgreSQL vs MySQL (InnoDB) 10 大核心架构差异对照

对比维度 🐘 PostgreSQL (14 / 16 / 17) 🐬 MySQL (8.0 / 8.4 InnoDB)
1. 并发连接模型 多进程模型：主进程 postmaster 为每个连接 fork 独立 backend 进程；隔离性极强，但高并发需配 PgBouncer 连接池 多线程模型：单进程内每个连接对应一个线程（企业版/Percona 支持线程池），单连接内存开销较小
2. 表存储结构 堆表（Heap Table，无序组织）：数据行按追加写入位置存放，靠物理坐标 ctid=(页号,槽位) 寻址；无聚簇索引 索引组织表（IOT，聚簇索引）：表本身就是按主键排序的 B+ 树，主键叶子节点直接存完整数据行
3. 二级索引与回表 所有索引（含主键）都是二级索引，叶子存 ctid 直接一步跳回堆表物理页；但未命中的 HOT 更新需额外更新全表所有索引 二级索引叶子存主键值，回表需拿主键值再去主键 B+ 树做二次树搜索；但非主键列更新若不改该二级索引列则无需动它
4. MVCC 多版本实现 页内追加新版本（xmin/xmax）：UPDATE = 旧行标 xmax + 插新行，旧版本留在堆表里 → 回滚极快（O(1)），但产生死元组与表膨胀，靠 VACUUM 回收 原地更新 + Undo Log 回滚段：数据页只留最新版本，旧版本通过 roll_pointer 串在独立 Undo Log 中，由后台 Purge 线程清理
5. 默认页大小 默认 8 KiB（编译期可配，常见 8KB） 默认 16 KiB
6. 默认隔离级别与实现 默认 Read Committed (RC)；RR 级别直接靠事务级快照挡掉幻读；Serializable 采用无读锁的 SSI（可串行化快照隔离） 默认 Repeatable Read (RR)；快照读靠 MVCC ReadView，当前读靠 Next-Key Lock（记录锁 + 间隙锁 Gap Lock）防幻读
7. 索引丰富度 6 大原生索引引擎：B-tree、GIN（JSONB/数组/全文倒排）、GiST（空间/范围排他）、SP-GiST、BRIN（超小块范围）、Hash；支持部分索引与表达式索引 以 B+ 树 为绝对主力（另支持全文索引与 R-Tree 空间索引；8.0+ 支持函数索引，但不支持 WHERE 部分索引）
8. DDL 事务安全性 支持事务性 DDL：绝大多数 CREATE / ALTER / DROP 可包裹在 BEGIN ... ROLLBACK 中原子回滚，迁移脚本极安全 DDL 隐式提交（Implicit Commit）：执行 DDL 会强制提交当前事务，无法通过 ROLLBACK 回滚
9. 复杂查询与优化器 支持 Hash Join / Merge Join / Nested Loop 全套连接算法、并行查询、完整窗口函数、递归 CTE、RETURNING、物化视图 8.0 才补齐窗口函数、CTE 与 Hash Join，复杂多表分析查询与统计成本估算相比 PG 略逊一筹
10. 杀手级扩展生态 插件化内核扩展：PostGIS（行业标准 GIS）、pgvector（AI 向量检索）、TimescaleDB（时序）、Citus（分布式分片） 架构相对封闭，侧重传统 OLTP 稳定读写与主从高可用生态（MHA / Orchestrator / MGR / Canal）
