00.1 · 核心定位：对象-关系型数据库（ORDBMS）的设计特点与适用场景

00.1 PostgreSQL 的设计特点与常见应用领域

PostgreSQL（常简称为 PG 或 Postgres）诞生于加州大学伯克利分校的 POSTGRES 项目，是目前功能最完备的开源对象-关系型数据库管理系统（ORDBMS）。它在传统关系型二维表（行与列）的基础上，原生融合了对复杂数据类型、高级分析查询以及插件扩展的支持：

特点 ① · 标准与严谨 SQL Standard
高度遵循 SQL 标准与事务安全

完整支持窗口函数、递归公共表表达式（WITH RECURSIVE）、全外连接（FULL OUTER JOIN）以及可包裹在事务中安全回滚的事务性 DDL（BEGIN ... ALTER ... ROLLBACK）。

特点 ② · 丰富数据类型 Rich Types
原生内置 JSONB、数组与范围类型

除了数值、文本和时间戳外，直接支持二进制结构化文档 jsonb、一维或多维数组 text[]、时间区间 tstzrange，并可针对内部元素建立倒排索引。

特点 ③ · 可扩展底座 Extensions
通过插件平滑扩展专业领域能力

无需额外部署多套异构存储，即可通过 PostGIS 处理地理空间坐标、通过 pgvector 实现 AI 向量相似度检索、通过 TimescaleDB 处理时序监控数据。

对比维度 PostgreSQL (14 / 16 / 17) MySQL (8.0 / 8.4 InnoDB)
日常开发体感 类型校验严格，原生支持 RETURNING（修改后直接返回行）、FULL JOIN、数组与 JSONB 倒排检索，复杂多表报表与分析查询能力强。 语法相对宽松，侧重高并发简单点查与常规 OLTP 增删改查，主从复制与生态工具成熟。
表结构变更 (DDL) 支持事务性 DDL：绝大多数建表、改表操作可放在 BEGIN ... ROLLBACK 事务块中原子回滚，执行数据库迁移脚本更安全。 执行 ALTER / CREATE / DROP 会触发隐式提交（Implicit Commit），中途报错无法回滚已执行的 DDL 步骤。
自增主键写法 使用 SQL 标准语法 bigint GENERATED ALWAYS AS IDENTITY（底层关联序列对象 SEQUENCE）。 在列定义后附加 AUTO_INCREMENT 属性。
典型适用场景 复杂业务建模、SaaS 多租户系统、金融账务、含动态 JSON 属性的业务、GIS 地理服务、AI 知识库向量检索（pgvector）。 传统电商交易流水、高并发简单键值/主外键读写、已有成熟 MySQL 运维体系的业务。
00.2 · 全平台环境搭建：Docker / macOS / Linux / Windows 安装、首次初始化与排障

00.2 全平台环境安装、首次初始化与服务管理

PostgreSQL 支持在所有主流操作系统上运行，服务端默认监听 TCP 5432 端口。针对本地开发与服务器部署，下面按 Docker 容器、macOS、Linux（Ubuntu / RHEL）、Windows 四种环境给出从安装、环境变量配置到首次建库建用户的完整命令闭环：

方式一 · Docker 与 Docker Compose（跨平台隔离首选） 
# A. 单命令快速启动 PostgreSQL 16（指定时区、UTF8 编码与持久化数据卷）
docker run -d \
  --name pg16 \
  -p 5432:5432 \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=mydb \
  -e TZ=Asia/Shanghai \
  -v pg16_data:/var/lib/postgresql/data \
  postgres:16-alpine

# B. 探测容器数据库是否就绪，并进入交互式 psql 终端
docker exec pg16 pg_isready -U postgres
docker exec -it pg16 psql -U postgres -d mydb

# C. 推荐：使用 docker-compose.yml 编排 PG 16 与健康检查
cat << 'EOF' > docker-compose.yml
services:
  postgres:
    image: postgres:16-alpine
    container_name: pg16
    restart: unless-stopped
    ports:
      - "5432:5432"
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: mydb
      TZ: Asia/Shanghai
    volumes:
      - pg16_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres -d mydb"]
      interval: 5s
      timeout: 3s
      retries: 5
volumes:
  pg16_data:
EOF
docker compose up -d
🍎 方式二 · macOS 安装（Homebrew 命令行 / Postgres.app） 
# 1. 使用 Homebrew 安装 PostgreSQL 16
brew install postgresql@16

# 2. 【关键】postgresql@16 为 keg-only 包，必须将 bin 目录加入 PATH
# 否则终端直接输入 psql 会提示: zsh: command not found: psql
# Apple Silicon (M1/M2/M3/M4) 芯片路径：
echo 'export PATH="/opt/homebrew/opt/postgresql@16/bin:$PATH"' >> ~/.zshrc
# Intel 芯片 Mac 请改为：/usr/local/opt/postgresql@16/bin
source ~/.zshrc && psql --version

# 3. 启动后台服务（开机自启）并查看运行状态
brew services start postgresql@16
brew services list

# 4. 【关键】Homebrew 默认仅创建与 macOS 当前用户名同名的超级用户，
# 并未自动创建名为 postgres 的角色。首次需先免密连入默认 postgres 库，
# 手动补建通用的 postgres 超级用户与练习库 mydb：
psql postgres -c "CREATE ROLE postgres WITH SUPERUSER LOGIN PASSWORD 'secret';"
psql postgres -c "CREATE DATABASE mydb OWNER postgres;"

# 5. 此后即可使用标准的 postgres 账号连接：
psql -h localhost -p 5432 -U postgres -d mydb

# 附：若偏好图形化状态栏管理，也可直接安装原生桌面版 Postgres.app：
brew install --cask postgres-unofficial
方式三 · Linux 安装（Ubuntu / Debian 与 RHEL / Rocky） 
# ========= A. Ubuntu / Debian 系列 =========
# 1. 添加官方 PGDG 软件源并安装 PostgreSQL 16（含 contrib 常用扩展包）
sudo apt update && sudo apt install -y postgresql-common
sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh -y
sudo apt install -y postgresql-16 postgresql-contrib-16

# ========= B. RHEL / Rocky / AlmaLinux / CentOS 系列 =========
# 1. 安装 RPM 包后，必须手动执行一次 initdb 初始化数据目录
sudo dnf install -y postgresql16-server postgresql16-contrib
sudo /usr/pgsql-16/bin/postgresql-16-setup initdb
sudo systemctl enable --now postgresql-16

# ========= C. Linux 安装后首次初始化（必做） =========
# Linux 安装后会自动创建操作系统用户 postgres，且默认开启 peer 同名认证。
# 首次必须先切换到系统用户 postgres 进入 psql，设置密码并创建业务库：
sudo -i -u postgres psql
-- 在 psql 提示符下执行以下两条 SQL 命令：
ALTER USER postgres WITH PASSWORD 'secret';
CREATE DATABASE mydb OWNER postgres;
\q

# 完成后即可通过 TCP 密码方式正常连接本机数据库：
psql -h 127.0.0.1 -p 5432 -U postgres -d mydb
方式四 · Windows 安装（EDB 官方安装包 / Winget / Scoop） 
# ========= A. 使用 Windows 官方 Winget 一键安装（或从官网下载 .exe） =========
# 安装过程中会提示设置超级用户 postgres 的密码，端口保持默认 5432，
# 区域（Locale）建议选择 "C" 或 "Chinese (Simplified), China"
winget install PostgreSQL.PostgreSQL.16

# ========= B. 将命令行工具目录加入系统 PATH（PowerShell 管理员执行） =========
# 解决在 CMD / PowerShell 中输入 psql 提示“不是内部或外部命令”的问题：
[Environment]::SetEnvironmentVariable(
  "Path",
  [Environment]::GetEnvironmentVariable("Path", "Machine") + ";C:\Program Files\PostgreSQL\16\bin",
  "Machine"
)

# ========= C. 重启终端后验证版本、管理服务并连接建库 =========
psql --version
# 查看 / 启动 / 停止 Windows 后台服务（服务名通常为 postgresql-x64-16）：
Get-Service postgresql*
net start postgresql-x64-16

# 连接默认 postgres 库（回车后输入安装时设置的密码）并创建 mydb：
psql -h localhost -p 5432 -U postgres -d postgres -c "CREATE DATABASE mydb;"
psql -h localhost -p 5432 -U postgres -d mydb

安装后首次连接 3 大高频报错排查与随附命令行工具

首次连接常见报错信息 触发原因 一步解决命令
command not found: psql 或 'psql' 不是内部或外部命令 安装了服务端，但尚未把包含 psql 的 bin 目录加入系统环境变量 PATH macOS 将 /opt/homebrew/opt/postgresql@16/bin 加入 ~/.zshrc；Windows 将 C:\Program Files\PostgreSQL\16\bin 加入系统 Path。
FATAL: role "postgres" does not exist（macOS 常见） macOS Homebrew 初始化时，默认只创建了与当前 Mac 登录用户名同名的超级用户，没有创建 postgres 用户 先直接运行 psql postgres（默认以当前系统用户名免密登录），再执行 CREATE ROLE postgres WITH SUPERUSER LOGIN PASSWORD 'secret';。
FATAL: Peer authentication failed for user "postgres"（Linux 常见） Linux 本地 Socket 默认启用 peer 认证，要求操作系统当前用户名必须与数据库用户名一致 切换系统用户登录：sudo -i -u postgres psql 设置密码后，改用带 -h 127.0.0.1 的 TCP 方式连接（走密码认证而非本地 Socket）。
connection to server at "localhost" (127.0.0.1), port 5432 failed: Connection refused 后台数据库服务未启动，或者跨机器访问时服务端仅监听了本地回环地址 127.0.0.1 先用 pg_isready -h localhost -p 5432 检查存活；若需局域网/远程连接，在 postgresql.conf 设置 listen_addresses = '*' 并在 pg_hba.conf 放行网段（详见下一章 01.3）。

00.3 psql 高频元命令与第一个 SQL 脚本

进入 psql 终端后，输入分为两类：一类是以反斜杠 \ 开头的客户端快捷命令（称为元命令 Meta-Commands，由 psql 直接解析，无需加分号）；另一类是标准 SQL 语句（必须以分号 ; 结尾才会发送给服务端执行）。

元命令 功能说明 元命令 功能说明
\l 列出当前实例下的所有数据库（Database） \c 库名 切换连接到指定的数据库（相当于 MySQL 的 USE）
\dn 列出当前数据库下的所有模式（Schema） \dt 列出当前搜索路径下的所有数据表
\d 表名 查看指定表的字段类型、默认值、主键、索引与外键引用 \d+ 表名 在 \d 基础上额外显示列注释、存储策略与表占用空间
\di / \dv 列出当前模式下的所有索引（Index） / 视图（View） \du 列出所有数据库角色（Role / User）及其权限属性
\x 切换竖排扩展展示模式（字段很多、单行折行错乱时非常实用） \timing 开启或关闭每条 SQL 语句执行后的精确毫秒耗时统计
\df / \dx 查看自定义函数列表 / 查看已安装的扩展插件（Extension） \i 文件.sql / \q 执行外部 SQL 脚本文件 / 退出 psql 终端
first_steps.sql · 创建第一张表并完成增删改查 
-- 1. 创建一张图书表 books
CREATE TABLE books (
  id           bigint        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  title        text          NOT NULL,
  price        numeric(10,2) NOT NULL DEFAULT 0.00,
  published_at timestamptz   NOT NULL DEFAULT now()
);

-- 2. 插入两条记录，并用 RETURNING 直接拿回自动生成的 id
INSERT INTO books (title, price)
VALUES ('PostgreSQL 实战指南', 79.50),
       ('数据库系统概念', 128.00)
RETURNING id, title, price;

-- 3. 条件查询与价格更新
SELECT id, title, price FROM books WHERE price < 100;

UPDATE books SET price = 69.00 WHERE id = 1 RETURNING *;
逐行语法拆解（初学者必读对照）
  • bigint GENERATED ALWAYS AS IDENTITY：声明 id 列为 8 字节长整型，并由数据库按顺序自动生成唯一递增编号（从 1 开始），无需在 INSERT 时手动传入。
  • PRIMARY KEY 与 NOT NULL：PRIMARY KEY（主键）标识每一行的唯一身份，自动包含非空与唯一约束；NOT NULL 要求该字段必须有值，禁止存入空值 NULL。
  • text 与 numeric(10,2)：在 PostgreSQL 中，变长字符串直接使用 text 即可；numeric(10,2) 表示总位数最多 10 位、其中小数占 2 位的精确十进制数，专门用于存储金额。
  • timestamptz DEFAULT now()：timestamptz 是带时区的时间戳类型；DEFAULT now() 表示插入数据时若未指定该列，自动填入当前事务的开始时间。
  • 单引号 '...' 与 RETURNING：SQL 标准中字符串字面量必须使用单引号（双引号 "..." 仅用于包裹区分大小写的表名或列名）；末尾的 RETURNING 子句会在写入完成后直接把受影响的行像 SELECT 一样返回给客户端，省去再查一次数据库的步骤。
