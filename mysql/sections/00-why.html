🧭 00.1 · 核心定位：关系型数据库管理系统（RDBMS）的设计特点与版本演进

🧭 00.1 MySQL 的核心设计特点与 5.7 → 8.0 → 8.4 演进对照

MySQL 是全球应用最广泛的开源关系型数据库管理系统（RDBMS）。它采用“Server 层 + 可插拔存储引擎层”的双层架构，默认使用支持完整 ACID 事务、行级锁与崩溃自动恢复的 InnoDB 存储引擎。在现代企业生产环境中，MySQL 8.0 与 MySQL 8.4（最新 LTS 长期支持版） 已全面取代旧版 5.7：

特点 ① · 聚簇索引存储 Index-Organized
表即索引（主键 B+ 树直接存整行）

InnoDB 采用索引组织表（IOT）设计，整张表的数据行直接存放在主键 B+ 树的叶子节点中，按主键等值点查与主键范围扫描的 I/O 路径极短。

特点 ② · 读写并发隔离 MVCC + Row Lock
Undo 版本链与细粒度行锁协同

原地更新数据页并把旧版本写入独立的 Undo Log 回滚段，配合 ReadView 快照实现普通 SELECT 不加锁，读写互不阻塞。

特点 ③ · 成熟高可用生态 WAL + Binlog
两阶段提交与一主多从 / MGR 复制

通过引擎层 Redo Log 与 Server 层 Binlog 的两阶段提交保证单机崩溃恢复与主从复制严格一致，配套 Canal / CDC 生态完善。

核心能力维度 旧版 MySQL 5.7（已停止维护） 现代 MySQL 8.0 / 8.4 LTS（当前主流标准）
默认字符集與排序规则 默认为 latin1，中文需手动改 utf8（且仅支持 3 字节，存 Emoji 会报错） 默认即为真 4 字节 UTF-8 utf8mb4，排序规则默认为 utf8mb4_0900_ai_ci，原生支持生僻字与 Emoji 表情。
查询缓存（Query Cache） 保留鸡肋的 Server 层 Query Cache（表一旦有写入即整表缓存失效，锁争用严重） 彻底移除 Query Cache 模块及参数；数据页缓存全部由 InnoDB 引擎层的 Buffer Pool 承担。
现代 SQL 与执行算子 不支持窗口函数与 CTE；无索引等值连接只能走慢速 Block Nested-Loop (BNL) 完整支持 窗口函数 OVER (...)、递归公共表表达式 WITH RECURSIVE、Hash Join、直方图统计信息、函数索引与不可见索引。
数据字典与 Online DDL 元数据散落在 .frm 等外部文件中，DDL 中途崩溃易留残余；加列往往需重建表 消除 .frm 文件，元数据统一存入 InnoDB 事务表并支持原子 DDL；新增 ALGORITHM=INSTANT 秒级加列/删列（仅修改元数据，无需拷贝大表）。

🛠️ 00.2 全平台环境安装、首次初始化与服务管理

MySQL 服务端默认监听 TCP 3306 端口（MySQL X Protocol 扩展协议端口为 33060）。下面按 Docker 容器、macOS、Linux（Ubuntu / RHEL）、Windows 四种环境给出从安装、环境变量配置到首次登录建库的完整命令：

🐳 方式一 · Docker 与 Docker Compose（跨平台隔离首选） 
# A. 单命令启动 MySQL 8.4 LTS（指定 utf8mb4 字符集、东八区时区与持久化卷）
docker run -d \
  --name mysql84 \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=Secret_2026 \
  -e MYSQL_DATABASE=mydb \
  -e TZ=Asia/Shanghai \
  -v mysql84_data:/var/lib/mysql \
  mysql:8.4 \
  --character-set-server=utf8mb4 \
  --collation-server=utf8mb4_0900_ai_ci

# B. 探测容器内 MySQL 是否就绪，并进入交互式 mysql 终端
docker exec mysql84 mysqladmin ping -h 127.0.0.1 -u root -pSecret_2026
docker exec -it mysql84 mysql -u root -pSecret_2026 mydb

# C. 推荐：使用 docker-compose.yml 编排 MySQL 8.4 与健康检查
cat << 'EOF' > docker-compose.yml
services:
  mysql:
    image: mysql:8.4
    container_name: mysql84
    restart: unless-stopped
    ports:
      - "3306:3306"
    environment:
      MYSQL_ROOT_PASSWORD: Secret_2026
      MYSQL_DATABASE: mydb
      TZ: Asia/Shanghai
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_0900_ai_ci
    volumes:
      - mysql84_data:/var/lib/mysql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 5s
      timeout: 3s
      retries: 10
volumes:
  mysql84_data:
EOF
docker compose up -d
🍎 方式二 · macOS 安装（Homebrew 命令行 / 官方 DMG） 
# 1. 使用 Homebrew 安装最新稳定版 MySQL（或指定版本 brew install mysql@8.4）
brew install mysql

# 2. 若安装的是带版本号的 mysql@8.4（keg-only），需将 bin 目录加入 PATH：
# Apple Silicon (M1/M2/M3/M4) 路径为 /opt/homebrew/opt/mysql@8.4/bin
echo 'export PATH="/opt/homebrew/opt/mysql@8.4/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc && mysql --version

# 3. 启动 MySQL 后台服务并查看运行状态
brew services start mysql
brew services list

# 4. 【关键】Homebrew 初装后 root 默认为空密码，首次免密登录并设置安全密码：
mysql -u root -e "ALTER USER 'root'@'localhost' IDENTIFIED BY 'Secret_2026';"
mysql -u root -pSecret_2026 -e "CREATE DATABASE IF NOT EXISTS mydb DEFAULT CHARSET utf8mb4;"

# 5. 也可运行官方安全初始化向导（交互式设置密码强度、清理匿名用户与测试库）：
mysql_secure_installation

# 6. 使用密码连接本地 mydb 数据库：
mysql -h 127.0.0.1 -P 3306 -u root -p mydb
🐧 方式三 · Linux 安装（Ubuntu / Debian 与 RHEL / Rocky） 
# ========= A. Ubuntu / Debian 系列 =========
# 1. 更新软件源并安装 MySQL Server 8.0+，安装完成后服务会自动启动
sudo apt update && sudo apt install -y mysql-server
sudo systemctl enable --now mysql

# 2. 【关键】Ubuntu 初装后 root 默认启用 auth_socket 插件（仅允许 sudo 免密登录），
# 直接执行 mysql -u root -p 会报错 Access denied。首次需用 sudo 登录并改为密码认证：
sudo mysql
-- 在 mysql> 提示符下执行：
ALTER USER 'root'@'localhost' IDENTIFIED WITH caching_sha2_password BY 'Secret_2026';
CREATE DATABASE IF NOT EXISTS mydb DEFAULT CHARSET utf8mb4;
EXIT;

# ========= B. RHEL / Rocky / AlmaLinux / CentOS 系列 =========
# 1. 安装 mysql-server 并启动服务
sudo dnf install -y mysql-server
sudo systemctl enable --now mysqld

# 2. 若使用官方 MySQL Yum 源安装，首次启动会在日志中生成临时随机密码，用 grep 提取：
sudo grep 'temporary password' /var/log/mysqld.log
# 拿到临时密码登录后立即执行 ALTER USER 'root'@'localhost' IDENTIFIED BY '新密码';
🪟 方式四 · Windows 安装（MySQL Installer / Winget） 
# ========= A. 使用 Windows Winget 安装（或从官网下载 .msi 安装包） =========
winget install Oracle.MySQL

# ========= B. 将 MySQL bin 目录加入系统 PATH（PowerShell 管理员执行） =========
# 解决在 CMD / PowerShell 中输入 mysql 提示“不是内部或外部命令”的问题：
[Environment]::SetEnvironmentVariable(
  "Path",
  [Environment]::GetEnvironmentVariable("Path", "Machine") + ";C:\Program Files\MySQL\MySQL Server 8.4\bin",
  "Machine"

# ========= C. 若通过免安装版 .zip 解压，需管理员执行一次初始化与注册服务 =========
mysqld --initialize-insecure --user=mysql --console
mysqld --install MySQL84

# ========= D. 启停 Windows 后台服务并连接建库 =========
net start MySQL84
mysql -h localhost -P 3306 -u root -p -e "CREATE DATABASE IF NOT EXISTS mydb DEFAULT CHARSET utf8mb4;"

🩺 安装后首次连接 4 大高频报错排查对照表

首次连接常见报错信息 触发原因 一步解决命令
ERROR 1698 (28000): Access denied for user 'root'@'localhost'（Ubuntu 最常见） Ubuntu 初装默认对本地 root 使用 auth_socket 插件，只认系统 sudo 身份，不认密码 先运行 sudo mysql 免密进入，再执行 ALTER USER 'root'@'localhost' IDENTIFIED WITH caching_sha2_password BY '你的密码';。
Authentication plugin 'caching_sha2_password' cannot be loaded 或 Public Key Retrieval is not allowed MySQL 8.0+ 默认加密插件为 caching_sha2_password，旧版客户端驱动未开启 SSL 或公钥拉取 在客户端连接串追加参数 allowPublicKeyRetrieval=true&useSSL=false；或在服务端将该账号改为兼容模式：ALTER USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY '密码';。
ERROR 2002 (HY000): Can't connect to local MySQL server through socket '/tmp/mysql.sock' MySQL 服务尚未启动，或者不带 -h 时客户端尝试找本地 Unix Socket 文件但路径不匹配 先确认服务已启动（brew services list 或 systemctl status mysql）；连接时显式指定 TCP 回环地址 mysql -h 127.0.0.1 -P 3306 -u root -p。
command not found: mysql 或 'mysql' 不是内部或外部命令 未将 MySQL 的 bin 目录加入环境变量 PATH（注意区分端口参数是大写 -P 3306，小写 -p 代表密码） 将 macOS 的 /opt/homebrew/opt/mysql@8.4/bin 或 Windows 的 C:\Program Files\MySQL\MySQL Server 8.4\bin 加入系统 PATH。

📝 00.3 mysql 终端高频命令与第一个 SQL 脚本

连接进入 mysql> 交互式提示符后，你可以通过内置的 SHOW / USE / DESC 命令查看库表结构，也可以直接执行标准 SQL 语句（普通语句以分号 ; 结尾；当返回列特别多导致终端折行错乱时，用 \G 代替分号即可切换为清晰的竖排键值对卡片展示）：

终端命令 功能说明 终端命令 功能说明
SHOW DATABASES; 列出当前实例下的所有数据库 USE mydb; 切换到指定数据库（无需加分号也可执行）
SHOW TABLES; 列出当前数据库下的所有表 DESC users; 查看 users 表的列名、类型、是否允许 NULL 与索引标志
SHOW CREATE TABLE users\G 查看该表完整的建表 DDL 语句、引擎与字符集（极力推荐） SHOW INDEX FROM users; 查看指定表上的所有索引列、唯一性与基数（Cardinality）
SELECT ... \G 将查询结果按每行一张竖排卡片打印（替代末尾的 ;） SOURCE /path/init.sql; 在当前会话中批量执行外部 .sql 脚本文件
STATUS;（或 \s） 查看当前服务端版本、当前用户、连接字符集与运行时长 SHOW PROCESSLIST; / \q 查看当前所有活跃会话正在执行的 SQL / 退出终端
🐬 first_users.sql · 创建贯穿全文的 users 表并完成 CRUD 
-- 1. 创建用户表 users（InnoDB 引擎 + utf8mb4 字符集）
CREATE TABLE `users` (
  `id`         BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '自增主键ID',
  `name`       VARCHAR(50)     NOT NULL COMMENT '用户姓名',
  `age`        TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '年龄',
  `city`       VARCHAR(50)     NOT NULL COMMENT '所在城市',
  `balance`    DECIMAL(12,2)   NOT NULL DEFAULT 0.00 COMMENT '账户余额(元)',
  `created_at` DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_city_age` (`city`, `age`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户账户表';

-- 2. 批量插入 3 条测试数据（id 由 AUTO_INCREMENT 自动生成 1, 2, 3）
INSERT INTO `users` (`name`, `age`, `city`, `balance`) VALUES
  ('小林', 20, '杭州', 100.00),
  ('小周', 25, '杭州', 200.00),
  ('小陈', 30, '上海', 300.00);

-- 3. 条件过滤查询与按主键更新余额
SELECT `id`, `name`, `balance` FROM `users` WHERE `city` = '杭州' AND `age` >= 20;
UPDATE `users` SET `balance` = `balance` + 50.00 WHERE `id` = 1;
📖 逐行语法拆解（初学者对照指南）
  • 反引号 `...` vs 单引号 '...'：在 MySQL 中，反引号 `users` 用于包裹表名或列名（防止字段名恰好与 order / status / desc 等 SQL 保留字冲突）；而单引号 '杭州' 用于包裹字符串字面量值，两者不可混用。
  • BIGINT UNSIGNED NOT NULL AUTO_INCREMENT：BIGINT 为 8 字节整数，UNSIGNED 表示无符号非负数（上限翻倍且禁止负数 ID），AUTO_INCREMENT 让数据库在插入时自动按顺序递增编号；插入后可通过 SELECT LAST_INSERT_ID(); 获取刚生成的自增 ID。
  • DECIMAL(12,2)：表示总有效位数最多 12 位、其中小数部分固定占 2 位的精确十进制数，专门用于存储账户余额与订单价格，避免 FLOAT / DOUBLE 二进制浮点数的精度丢失。
  • ON UPDATE CURRENT_TIMESTAMP：MySQL 的实用特性，每当该行记录的任何列发生数值变更时，数据库会自动将 updated_at 刷新为当前修改时刻，无需业务代码手动维护。
  • KEY idx_city_age (city, age)：在建表时直接为 (city, age) 两列建立联合二级索引（KEY 与 INDEX 在此完全同义），加速按城市与年龄的组合检索。
