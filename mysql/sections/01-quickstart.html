01.1 Docker 一行启动与客户端连接

日常学习与本地开发推荐使用 Docker 容器启动（不污染本机环境，且适用于 MySQL 8.0 与最新长期支持版 LTS，Long-Term Support，即 MySQL 8.4）。MySQL 默认监听 TCP 3306 端口；macOS / Linux / Windows 原生安装包方式放在本章末尾的折叠附录中按需查阅。

quickstart.sh · Docker 一行启动 MySQL 8.4（8.0 仅需把镜像改为 mysql:8.0） 
# 1. 一行启动 MySQL 8.4 LTS（自动创建 shop_db 库、配置 utf8mb4 字符集与东八区时区）
docker run -d --name mysql84 -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=Secret_2026 \
  -e MYSQL_DATABASE=shop_db \
  -e TZ=Asia/Shanghai \
  -v mysql84_data:/var/lib/mysql \
  mysql:8.4 \
  --character-set-server=utf8mb4 \
  --collation-server=utf8mb4_0900_ai_ci

# 2. 等待约 5~10 秒初始化完成后，进入容器内的 mysql 交互终端
docker exec -it mysql84 mysql -u root -pSecret_2026 shop_db
图形化客户端（GUI）连接与逻辑目录认知
  • 选一个顺手的 GUI（Graphical User Interface，图形用户界面）工具：免费跨平台首选开源的 DBeaver Community（或 JetBrains DataGrip / TablePlus）。新建 MySQL 连接填入 Host: 127.0.0.1、Port: 3306、Database: shop_db、User: root、Password: Secret_2026 即可。
  • 首次连接若提示 Public Key Retrieval is not allowed：这是因为 MySQL 8.0+ 默认使用更安全的 caching_sha2_password 认证插件，在 GUI 连接属性的驱动参数中把 allowPublicKeyRetrieval 设为 true 即可连上。
  • 理清一个高频术语：在 MySQL 中，Database 与 Schema 是完全同义词（CREATE SCHEMA shop_db; 等价于 CREATE DATABASE shop_db;），逻辑层级只有三层：实例（Instance）→ 数据库（Database）→ 数据表（Table）。

01.2 · 第一个会话：建表 DDL 与最小增删改查（CRUD）完整脚本拆解

01.2 第一个建表与 CRUD 脚本（适用 MySQL 8.0 / 8.4）

把下面这段 SQL 直接复制粘贴进刚才打开的 mysql> 终端或 DBeaver 查询窗口，即可跑通电商用户表的建表与完整的 CRUD（Create, Read, Update, Delete，增删改查） 闭环：

first_users.sql · 创建电商用户表并完成增删改查 
-- 1. 建表（DDL，Data Definition Language，数据定义语言）
CREATE TABLE IF NOT EXISTS `users` (
  `id`         BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT COMMENT '自增主键ID',
  `name`       VARCHAR(50)      NOT NULL COMMENT '买家昵称',
  `age`        TINYINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '年龄',
  `city`       VARCHAR(50)      NOT NULL COMMENT '收货城市',
  `balance`    DECIMAL(12,2)    NOT NULL DEFAULT 0.00 COMMENT '钱包余额(元)',
  `created_at` DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP,
  `updated_at` DATETIME         NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  KEY `idx_city_age` (`city`, `age`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='买家账户表';

-- 2. 新增（Create）：批量插入 3 位买家（id 由 AUTO_INCREMENT 自动生成 1, 2, 3）
INSERT INTO `users` (`name`, `age`, `city`, `balance`) VALUES
  ('小林', 20, '杭州', 100.00),
  ('小周', 25, '杭州', 200.00),
  ('小陈', 30, '上海', 300.00);

-- 3. 查询（Read）与修改（Update）、删除（Delete）
SELECT `id`, `name`, `balance` FROM `users` WHERE `city` = '杭州' AND `age` >= 20;
UPDATE `users` SET `balance` = `balance` + 50.00 WHERE `id` = 1;
DELETE FROM `users` WHERE `id` = 3;
逐行语法拆解（避开新手第一天的坑）
  • 反引号 `...` vs 单引号 '...'：在 MySQL 中，反引号 `users` 用于包裹表名或列名（防止表名叫 order、列名叫 status / desc 时与 SQL 保留关键字冲突报错）；而单引号 '杭州' 用于包裹字符串值，两者不可混用。
  • BIGINT UNSIGNED NOT NULL AUTO_INCREMENT：BIGINT 是 8 字节整数，UNSIGNED 表示无符号非负数，AUTO_INCREMENT 让数据库自动递增编号；插入后同一连接执行 SELECT LAST_INSERT_ID(); 即可拿到刚生成的自增主键。
  • DECIMAL(12,2)：最多 12 位有效数字、其中小数固定占 2 位的精确十进制类型，存金额不会出现二进制浮点数的精度误差。
  • ON UPDATE CURRENT_TIMESTAMP：只要该行记录任意字段的值发生了变动，MySQL 会自动把 updated_at 刷新为当前时刻，无需业务代码每次手传更新时间。
  • KEY idx_city_age (city, age)：建表时顺手为 (city, age) 建立联合二级索引（此处 KEY 与 INDEX 完全同义），加速按收货城市和年龄的组合查询。
01.3 · 后端代码接入：Go 与 Node.js 连接池初始化及防 SQL 注入参数化查询

01.3 用后端代码连上 MySQL（Go 与 Node.js 示例）

在业务代码中访问 MySQL 有两条基本规范：① 进程启动时全局创建一个连接池（Connection Pool）复用长连接，绝不要每个 HTTP 请求进来都新建和销毁 TCP 连接；② 任何外部传入的变量都必须使用 ? 占位符做参数化查询（Prepared Statement，预编译语句），严禁用字符串拼接 SQL（如 "SELECT * FROM users WHERE name = '" + input + "'"，一旦攻击者传入 ' OR '1'='1 就会触发 SQL 注入漏洞拖走全表数据）。

main.go · Go 标准库 database/sql + go-sql-driver/mysql 
// 安装驱动：go get github.com/go-sql-driver/mysql@v1.8.1
package main

import (
  "context"
  "database/sql"
  "fmt"
  "log"
  "time"

  _ "github.com/go-sql-driver/mysql"
)

func main() {
  // DSN 必带 parseTime=true 与 loc=Asia%2FShanghai，否则 DATETIME 会差 8 小时
  dsn := "root:Secret_2026@tcp(127.0.0.1:3306)/shop_db?charset=utf8mb4&parseTime=true&loc=Asia%2FShanghai"
  db, err := sql.Open("mysql", dsn)
  if err != nil {
    log.Fatal(err)
  }
  defer db.Close()
  db.SetMaxOpenConns(25)
  db.SetMaxIdleConns(10)
  db.SetConnMaxLifetime(5 * time.Minute)

  ctx, cancel := context.WithTimeout(context.Background(), 3*time.Second)
  defer cancel()

  // 1. 参数化写入：使用 ? 占位符传参，安全防 SQL 注入
  res, err := db.ExecContext(ctx,
    "INSERT INTO users (name, age, city, balance) VALUES (?, ?, ?, ?)",
    "小赵", 26, "深圳", "500.00",
  )
  if err != nil {
    log.Fatal(err)
  }
  newID, _ := res.LastInsertId()

  // 2. 参数化单行查询
  var name, balance string
  err = db.QueryRowContext(ctx,
    "SELECT name, balance FROM users WHERE id = ?", newID,
  ).Scan(&name, &balance)
  if err != nil {
    log.Fatal(err)
  }
  fmt.Printf("新增买家 id=%d, name=%s, balance=%s\n", newID, name, balance)
}
quickstart.mjs · Node.js (mysql2/promise) 连接池与参数化查询 
// 安装驱动：npm install mysql2
import mysql from 'mysql2/promise';

// 1. 创建全局连接池（decimalNumbers: true 避免金额或大整数精度问题可按需配置，
// 涉及精确金额运算推荐保留默认字符串返回，交给 decimal.js 计算）
const pool = mysql.createPool({
  host: '127.0.0.1',
  port: 3306,
  user: 'root',
  password: 'Secret_2026',
  database: 'shop_db',
  charset: 'utf8mb4',
  timezone: '+08:00',
  connectionLimit: 20,
  maxIdle: 10,
  idleTimeout: 60000,
});

// 2. 参数化写入：调用 pool.execute() 自动走服务端预编译 ? 占位符
const [insertRes] = await pool.execute(
  'INSERT INTO users (name, age, city, balance) VALUES (?, ?, ?, ?)',
  ['小孙', 24, '杭州', '188.50']
);
console.log('新增自增 ID:', insertRes.insertId);

// 3. 参数化多行查询：按城市过滤
const [rows] = await pool.execute(
  'SELECT id, name, balance FROM users WHERE city = ? AND age >= ?',
  ['杭州', 20]
);
console.table(rows);

await pool.end(); // 脚本退出前关闭连接池（常驻 Web 服务无需调用）

附录 B：为什么选 MySQL 8.0 / 8.4 LTS？（对比已停维的旧版 5.7 四大升级）
核心能力维度 旧版 MySQL 5.7（已停止官方维护） 现代 MySQL 8.0 / 8.4 LTS（当前主流生产标准）
默认字符集与排序规则 默认为 latin1，中文需手动改 utf8（且最多 3 字节，存 Emoji 会报错） 默认即为真 4 字节 UTF-8 utf8mb4，排序规则默认为 utf8mb4_0900_ai_ci，原生支持生僻字与 Emoji 表情。
查询缓存（Query Cache） 保留 Server 层 Query Cache（表一旦有任何写入即整表缓存清空，锁争用严重） 彻底移除 Query Cache 模块及配置项；数据页缓存全部由 InnoDB 引擎层的 Buffer Pool 承担。
现代 SQL 与执行算子 不支持窗口函数与 CTE；无索引等值连接只能走慢速嵌套循环 完整支持窗口函数 OVER (...)、递归公共表表达式 WITH RECURSIVE、Hash Join、函数索引与不可见索引。
数据字典与 Online DDL 表结构散落在外部 .frm 文件中；加字段往往需要锁写重建整张表 消除 .frm 文件，元数据统一存入 InnoDB 事务表支持原子 DDL；新增 ALGORITHM=INSTANT 毫秒级加列/删列。

本章即时场景题（先想答案，再点击展开）

1. Go 后端往 MySQL 的 DATETIME 字段插入北京时间 15:00，读出来却变成了 23:00 或相差 8 小时，问题出在哪？

连接串漏配了时区参数。Go 的 go-sql-driver/mysql 在未指定 loc 参数时默认按零时区（UTC）解析 DATETIME 字面量。只需在连接串（DSN）末尾补齐 parseTime=true&loc=Asia%2FShanghai（Node.js mysql2 对应配置 timezone: '+08:00'），全链路读写即可严格对齐东八区时间。

2. 同事为了省事用模板字符串写了 `SELECT * FROM users WHERE phone = '${req.query.phone}'`，会有什么风险？怎么改？

存在高危 SQL 注入漏洞。攻击者只要传入 phone = "' OR '1'='1"，拼出来的 SQL 就变成 SELECT * FROM users WHERE phone = '' OR '1'='1'，条件恒为真从而一次性泄漏整张用户表。必须改为 ? 占位符参数化查询：pool.execute('SELECT id, name FROM users WHERE phone = ?', [req.query.phone])，由驱动把参数与 SQL 语法结构分开传输。

3. 订单表有一列叫 order 或 desc，建表时直接写 order INT NOT NULL 为什么会报语法错误？

ORDER 和 DESC 都是 SQL 的保留关键字（ORDER BY ... DESC），解析器看到裸写的 order 会误以为你要写排序子句。日常建表一要尽量避开保留字命名（改叫 sort_order、remark），二要养成用反引号 `order` 包裹表名和列名的习惯。

背后的原理：想了解执行 CREATE TABLE 与 INSERT 后，数据在磁盘 .ibd 表空间文件中如何拆成 16 KiB 数据页存储，可按需查阅 《 核心原理篇 · 00.1 表空间与 16KB 页布局》。
