Docker · 核心原理篇：Linux 隔离机制、Overlay2 存储、虚拟网络与运行时内核

Linux 内核里其实并没有名为“容器”的实体对象——所谓容器，本质上是一个同时挂载了多重 Namespace 视图、受 Cgroups 配额约束、根目录切到 Overlay2 联合挂载点上的普通宿主机进程。本篇从内核系统调用出发，依次拆解视图隔离、CPU 节流与 OOM 查杀、写时复制与 OCI 寻址、veth + docker0 + iptables 数据包路径，以及 containerd-shim / runc 与内核安全沙箱。

现代 Docker 引擎早已不是单个臃肿的守护进程，而是按 OCI（Open Container Initiative，开放容器倡议） 标准拆分为五级流水线：docker CLI 经 Unix Socket 调 dockerd，再经 gRPC 调高级运行时 containerd，每个容器拉起一个常驻的垫片进程 containerd-shim，由它调用一次性底层运行时 runc 完成 Linux 内核隔离初始化后即刻退出：
