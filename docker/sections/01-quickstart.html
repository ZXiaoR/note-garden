01.1 · 扫清最大拦路虎：解决连接 Docker Hub 超时（Client.Timeout exceeded）

01.1 先确认环境就绪，并配好镜像拉取加速

如果你本机还没安装 Docker，macOS 用户推荐安装轻量快速的 OrbStack（或官方 Docker Desktop），Windows 与 Linux 原生安装命令已整理在本章末尾的折叠附录中。装好后，国内网络直接执行 docker pull 经常卡在 context deadline exceeded——原因是默认去海外官方仓库 registry-1.docker.io 拉取。按下面对应方式配置即可解决（适用 Docker Engine 24 ~ 27+）：

Linux 服务器修改 /etc/docker/daemon.json（桌面端在设置面板填） 
# 1. 先检查 Docker 客户端与后台守护进程（Daemon）是否正常运行
docker version

# 2. Linux 服务器写入镜像加速与日志防爆盘配置（macOS/Windows 打开客户端
#    Settings -> Docker Engine，把下面 JSON 里的 registry-mirrors 合并进去点 Apply）
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<-'EOF'
{
  "registry-mirrors": [
    "https://<你的阿里云或云厂商专属加速前缀>.mirror.aliyuncs.com",
    "https://docker.1ms.run"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "3" }
}
EOF

# 3. 重新加载配置并重启守护进程，核验 Registry Mirrors 已生效
sudo systemctl daemon-reload && sudo systemctl restart docker
docker info | grep -A 4 "Registry Mirrors"
镜像拉取受阻时的 3 种可靠备选方案
  • 方案 ①（本机有代理）：注意终端里设 export HTTPS_PROXY=... 对 docker pull 无效！因为真正发起网络下载的是后台 dockerd 守护进程，不是前台命令行。桌面端直接在 Docker Desktop / OrbStack 设置里开启系统代理即可秒拉；Linux 服务端配在 /etc/systemd/system/docker.service.d/http-proxy.conf。
  • 方案 ②（云厂商个人专属加速或 ACR 转存）：开通免费的阿里云容器镜像服务个人版，用 GitHub Actions 把常用基础镜像同步推一份到自己的私有仓库拉取，稳定不限速。
  • 方案 ③（离线导入导出）：在能联网的机器跑 docker pull mysql:8.4 && docker save -o mysql84.tar mysql:8.4，拷到目标内网机器执行 docker load -i mysql84.tar 即可离线加载。
01.2 · 第一个动手实验：5 条命令走通 Nginx 容器启动、进入交互终端、查看日志与清理

01.2 先用 5 条命令走通一个容器的完整一生

first_container.sh · 复制到终端逐条运行体验 
# 第 1 步：后台启动一个轻量级 Nginx 网页服务器，把本机 8080 端口转发到容器里的 80 端口
docker run -d --name hello-web -p 8080:80 nginx:1.27-alpine

# 第 2 步：在宿主机验证网页已跑通（或浏览器打开 http://localhost:8080）
curl -I http://127.0.0.1:8080

# 第 3 步：进入正在运行的容器内部，把默认首页改成我们自己的中文页面
docker exec -it hello-web sh -c "echo '<h1>Hello from Docker!</h1>' > /usr/share/nginx/html/index.html"
curl http://127.0.0.1:8080

# 第 4 步：查看容器刚才打印的访问日志
docker logs --tail 10 hello-web

# 第 5 步：实验结束，停止并彻底删除该容器（宿主机干干净净，没有任何残留文件）
docker rm -f hello-web
01.3 · 命令活体解剖：一眼读懂 MySQL / Redis / Kafka 的 docker run 启动参数

01.3 拆解一条标准 docker run 命令的每个开关

回看我们在 MySQL 笔记 01.1 里写的那行启动命令：docker run -d --name mysql84 -p 3306:3306 -e MYSQL_ROOT_PASSWORD=Secret -v mysql84_data:/var/lib/mysql --restart unless-stopped mysql:8.4 --character-set-server=utf8mb4。其实所有中间件启动命令都是由下面 7 个固定积木拼出来的：

参数写法 英文原意 真实作用与新手最容易搞反的细节
-d --detach（后台分离运行） 让容器在后台静默运行并返回容器 ID；如果不加 -d，容器日志会直接占住你当前的终端窗口，Ctrl + C 就可能把容器关掉。
--name mysql84 指定自定义容器名 给容器起个好记的唯一名字，后续 docker stop / logs / exec 直接填 mysql84 即可；不加则随机生成如 quirky_darwin 的名字。
-p 8080:80 --publish（端口映射） 左外右内：宿主机端口 : 容器内监听端口（千万别写反！）。例如 -p 13306:3306 表示容器里面的 MySQL 依然监听 3306，但你在宿主机连接时填端口 13306，这样一台机器就能同时跑多个不同端口的 MySQL。
-e KEY=VAL --env（注入环境变量） 向容器内传入配置项（如数据库的 MYSQL_ROOT_PASSWORD、容器时区 TZ=Asia/Shanghai）。
-v 卷名:/容器内路径 --volume（挂载持久化卷） 同样是左外右内：把容器内 /var/lib/mysql 目录映射到宿主机管理的持久化卷 mysql84_data 上，保证删掉容器升级版本时数据一字不丢（详见 03.1）。
--restart unless-stopped 崩溃或开机自动重启策略 进程意外崩溃或宿主机断电重启后，Docker 自动帮你把该容器重新拉起来（除非你手动执行过 docker stop）。
镜像名:标签 及其后的参数 位置分界线（非常关键） 写在 mysql:8.4 前面的参数是传给 docker run 的；写在 mysql:8.4 后面的参数（如 --character-set-server=utf8mb4）是原样传给容器内启动程序 mysqld 的！把 -p 写到镜像名后面会直接报错。

本章即时场景题（先想答案，再点击展开）

1. 本机 3306 端口已经被以前装过的旧版 MySQL 占用了，我想用 Docker 再跑一个测试用的 MySQL 8.4，-p 参数该怎么写？

记住“左宿主机、右容器内”：写成 -p 3307:3306（或 -p 13306:3306）。容器里面的 MySQL 完全不用改配置，照常监听它自己的 3306；你在本机客户端（如 DBeaver 或 Go 代码）连 127.0.0.1:3307 即可，跟本机原有的 3306 互不冲突。

2. 新手写了 docker run redis:7.2 -d -p 6379:6379，为什么不仅没在后台跑，反而报 Fatal error, can't open config file '-d'？

把 Docker 自身的参数写到了镜像名后面。命令行解析以镜像名 redis:7.2 为分界线：镜像名后面的 -d -p 6379:6379 被当成了传给容器内 redis-server 程序的启动参数，redis-server 不认识 -d 就当成配置文件路径报错退出了。调整顺序为 docker run -d -p 6379:6379 redis:7.2 即可。

3. 敲 docker ps 时报错 Cannot connect to the Docker daemon at unix:///var/run/docker.sock. Is the docker daemon running?，是什么原因？

Docker 采用客户端/服务端（C/S）分离架构：docker 命令行只是轻量客户端，真正干活的是后台守护进程 dockerd。出现该报错说明后台服务没启动（macOS/Windows 打开 OrbStack 或 Docker Desktop 图标；Linux 执行 sudo systemctl start docker）。

背后的原理：敲下 docker run 的那一秒，docker 客户端、dockerd、containerd 和 runc 之间经历了哪五步交接？可按需查阅 《 核心原理篇 · 04.1 OCI 运行时五级调用链》。
