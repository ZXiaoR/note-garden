08.1 · 实战闭卷检验：10 道最高频开发打包与线上排障题（点击展开解析）

08.1 综合场景自测 10 题

01. 把后端代码打成容器后，连同一台机器上的 MySQL 容器报 connect ECONNREFUSED 127.0.0.1:3306，怎么解决？如果是连宿主机上没容器化的老数据库呢？

报错根因：每个容器有独立的网络命名空间，容器里写 127.0.0.1 指的是业务容器自己。
① 连旁边的 MySQL 容器：放进同一个自定义 Bridge 网络（或同一份 compose.yaml），连接地址改为 mysql容器名:3306；
② 连宿主机裸跑的服务：地址填 host.docker.internal:3306（Linux 宿主机需在启动容器时补加 --add-host=host.docker.internal:host-gateway）（回顾 03.2）。

02. 在 MacBook (M3 芯片) 上 docker build 打出的镜像本地跑得好好的，推到阿里云 ECS (x86_64) 上一启动立刻退出报 exec format error，怎么修？

根因：Apple Silicon Mac 默认构建出的是 linux/arm64 架构镜像，无法在 x86_64 (linux/amd64) CPU 上执行。
修法：改用 docker buildx build --platform linux/amd64,linux/arm64 -t 仓库/镜像:版本号 --push . 构建双架构镜像（或指定 --platform linux/amd64）（回顾 06.6）。

03. 每次只改了一行 JS/Go 业务代码，执行 docker build 却都要重新花 3 分钟下载一遍全部第三方依赖包，Dockerfile 哪写错了？

错在把 COPY . . 写在了装依赖指令（npm ci / go mod download）的前面，导致任何源码改动都击穿了依赖安装层的构建缓存。
修法：① 先只 COPY package.json package-lock.json ./（或 go.mod go.sum）；② 执行 RUN npm ci；③ 最后再 COPY . . 拷源码，并配齐 .dockerignore 排除 .git 与 node_modules（回顾 04.2）。

04. 第一次执行 docker compose up -d 时，虽然写了 depends_on: [mysql]，但后端容器还是因连不上数据库报错退出了，怎么彻底解决？

普通列表式 depends_on 只等 mysql 容器进程启动（service_started），不等里面的 mysqld 完成初始化开口监听端口。
标准解法：给 mysql 服务配置 healthcheck（mysqladmin ping），并在后端服务的 depends_on 中声明 condition: service_healthy，同时给后端配 restart: unless-stopped 双重兜底（回顾 05.1 / 05.2）。

05. Go 服务用多阶段构建打进 alpine 镜像后，体积只有 20MB，但上线一调第三方 HTTPS 接口就报错、打出的日志时间也慢了 8 小时，漏了什么？

极简的 alpine 镜像默认不含根证书库和时区数据包。在最终运行阶段加上 RUN apk --no-cache add ca-certificates tzdata 并设置 ENV TZ=Asia/Shanghai 即可同时修好 HTTPS 证书校验与东八区时间（回顾 06.2）。

06. 服务器磁盘报警 100% 满，定位到某个容器的 *-json.log 占了 60GB，运维直接敲 rm 删掉了这个文件，为什么 df -h 看磁盘还是 100%？怎么治标又治本？

原因：后台 dockerd 仍持有该日志文件的打开句柄，直接 rm 不会释放底层磁盘块。
① 在线治标（免重启秒释放）：用 sudo truncate -s 0 日志文件路径 将文件截断清零；
② 永久治本：在 /etc/docker/daemon.json（及 compose.yaml 的 logging.options）配齐 "max-size": "50m", "max-file": "3" 日志自动轮转（回顾 06.7 / 07.2）。

07. 线上容器偶发自动重启，docker ps -a 看到上一次退出状态为 Exited (137)，这是什么信号、怎么查证和修复？

137 = 128 + 9 (SIGKILL)，表示进程被系统强杀。执行 docker inspect 容器名 --format '{{.State.OOMKilled}}'，若为 true 说明触发了容器内存上限 OOM：需排查代码大对象内存泄漏、适当调大容器 memory 限额，并将语言运行时堆上限（如 Node --max-old-space-size）设为容器内存的 75% 左右预留堆外缓冲（回顾 02.2 / 07.2）。

08. 发版停旧容器时，代码里明明监听了 SIGTERM 做优雅停机，却根本没触发，每次都硬等 10 秒被强杀导致正在处理的请求报错，怎么排查？

排查 Dockerfile 的 CMD / ENTRYPOINT：① 是否写成了字符串 Shell 格式 CMD node server.js（包了一层不转信号的 /bin/sh -c）；② 是否用了 CMD ["npm", "start"]（npm 吞信号）；③ 若通过 entrypoint.sh 启动脚本拉起服务，脚本最后一行是否漏写了 exec（必须写 exec node server.js 让业务进程接替成为 PID 1）（回顾 06.3 / 07.4）。

09. 云主机已经开了 ufw 防火墙只放行 80/443，为什么 compose.yaml 里给 MySQL 写了 ports: ["3306:3306"] 还是被公网扫到了？

Docker 设置宿主机端口映射时修改的是 Linux 内核 iptables 的 PREROUTING (DNAT) 转发链，优先级早于 ufw 所在的 INPUT 过滤链，导致防火墙形同虚设。
正确做法：生产环境内部数据库/缓存删掉 ports: 字段（仅通过 Compose 内部网络供后端容器访问），或者显式绑定回环地址 127.0.0.1:3306:3306（回顾 06.5 / 原理篇 03.2）。

10. 想把线上的 Docker Compose 服务停下来改个网络配置再启动，敲 docker compose down 和 docker compose down -v 有什么天壤之别？

docker compose down 只销毁容器与虚拟网络，所有命名数据卷（如 mysql_data）安全保留；一旦手滑多敲了 -v（--volumes），Docker 会把该项目声明的所有命名卷连同里面的数据库表文件彻底物理抹除！线上运维严禁加 -v（回顾 05.3）。

08.2 · 复习速查卡：Docker 15 个核心问题一句话速记表

08.2 Docker 15 题一句话速记表

核心问题 一句话标准答案（含实战篇与原理篇双跳转）
1. 容器与传统虚拟机的本质区别？ 虚拟机虚拟出一套硬件并运行完整 Guest OS（秒~分钟级启动、占 GB 内存）；容器直接共享宿主机 Linux 内核，靠 Namespace 隔离视图、靠 Cgroups 限制资源，本质是一个受限宿主机进程（毫秒级启动）（00.2 / 原理篇 00.1）。
2. -p 8080:80 与 -v a:b 左右顺序？ 统一「左外（宿主机）: 右内（容器内）」；且所有传给 Docker 自身的开关必须写在镜像名之前，镜像名之后的参数是传给容器内启动程序的（01.3）。
3. Alpine、Slim 与 Distroless 怎么选？ Node/Python 生产首选 -slim（带标准 glibc 不踩原生扩展兼容坑）；纯静态 Go / Nginx 选 alpine 或 distroless（体积最小、无多余攻击面）；生产禁裸用 :latest（02.1）。
4. 命名卷（Volume）与绑定挂载（Bind Mount）怎么选？ 数据库持久化目录一律用命名卷（mysql_data:/var/lib/mysql）；向容器注入单文件配置（my.cnf:ro）或本地开发热更新源码用绑定挂载（03.1）。
5. 容器之间、容器与宿主机怎么互通？ 同自定义网桥（或同一 Compose）直接填 容器服务名:容器原始端口（靠内置 127.0.0.11 DNS）；容器调宿主机进程填 host.docker.internal（03.2 / 原理篇 03.1）。
6. COPY vs ADD、ARG vs ENV 区别？ 日常拷贝一律用透明的 COPY（ADD 会自动解压 tar）；ARG 仅构建期存在，ENV 持久带入运行期容器（敏感密码两者都别放，改用运行期注入）（04.1）。
7. 怎么让 docker build 最快、打出的镜像最小？ ① 配 .dockerignore；② 先拷锁文件装依赖、最后 COPY . . 拷源码保住层缓存；③ 用多阶段构建（COPY --from=builder）只把编译产物拷进精简运行底盘；④ 同层 RUN 内用 && 顺手清理缓存（04.2 / 04.3）。
8. ENTRYPOINT 与 CMD 为什么要写 JSON 数组？ Exec 数组格式（["node", "server.js"]）直接启动目标进程作为 PID 1，能正常接收 docker stop 发来的 SIGTERM 优雅停机；裸字符串 Shell 格式会包一层 /bin/sh -c 吞掉信号导致卡死 10 秒强杀（04.1 / 07.4）。
9. Compose 怎么防应用抢跑连不上数据库？ 给数据库配 healthcheck 探针，并在业务容器配 depends_on: mysql: condition: service_healthy，等数据库真正可读写后再启动业务进程（05.1）。
10. Linux Namespace 隔离了哪 6 个维度？ PID（进程号）、NET（网卡端口路由）、MNT（挂载点目录树）、UTS（主机名）、IPC（进程间通信）、USER（用户 UID 映射）（原理篇 00.2）。
11. Cgroups 限制 CPU 和内存超限时表现有何不同？ CPU 超配额不会杀进程，而是触发 CFS 周期节流（Throttling 暂停等待下一周期，表现为接口延迟毛刺）；物理内存超 memory.max 则直接触发内核 OOM Killer 强杀进程（Exit 137）（07.2 / 原理篇 01.1）。
12. Overlay2 联合文件系统是怎么工作的？ 底层多个只读镜像层（lowerdir）多容器共享，顶层挂一层容器独占可写层（upperdir），合并挂载在 merged；修改底层文件时触发写时复制（Copy-on-Write）拷到顶层再改，删除文件则在顶层生成 Whiteout 遮罩文件（原理篇 02.1）。
13. 同宿主机两个容器发包在内核里怎么走？ 每个容器插着一对跨命名空间的虚拟网线 veth pair，一头是容器内 eth0，另一头插在宿主机虚拟交换机网桥（docker0 / br-xxx）上直接二层转发；对外访问与 -p 映射则靠 iptables NAT（原理篇 03.1）。
14. 为什么重启 dockerd 时正在跑的容器不会挂？ 现代架构拆分为 dockerd -> containerd -> containerd-shim -> runc：runc 拉起容器后即退出，由独立的轻量 containerd-shim 垫片进程担任容器父进程接管 stdio 与退出状态，与 dockerd 解耦（原理篇 04.1）。
15. 生产上线前哪 4 项配置绝对不能漏？ ① USER 切非 root 运行；② 数据库不向公网裸露 -p；③ 配齐 memory / cpus 资源上限；④ 配齐 json-file 日志轮转（max-size + max-file）防爆盘（07 章全景）。
