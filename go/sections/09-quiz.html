09.1 独立思考后再点开参考方案

01. 服务跑一天后监控显示 goroutine 数量从 40 一路涨到 5 万不回落，怎么查出是哪行代码漏了？

排查步骤：通过内网诊断端口执行 go tool pprof -http=:9090 http://127.0.0.1:6060/debug/pprof/goroutine（或直接 curl /debug/pprof/goroutine?debug=1），看计数最多的那组调用栈停在哪一行。
三大高频元凶：① 子协程向无缓冲通道写结果，但主协程因超时已提前返回没人读（改为缓冲容量 1 或加 select + <-ctx.Done()）；② 调用外部接口用了无超时的 http.DefaultClient 永久挂在读套接字上；③ 消费者等待一个因异常提前退出而忘了 close 的通道（回顾 06.5 / 08.6）。

02. 需要并发请求 100 个下游商品接口汇总结果，怎么限制同时最多跑 10 个，且整体超 2 秒或任一报错就取消其余请求？

最简方案（context.WithTimeout + errgroup）：
① 先建 2 秒超时上下文：timeoutCtx, cancel := context.WithTimeout(parentCtx, 2*time.Second); defer cancel()；
② 派生编排组并设并发上限：g, egCtx := errgroup.WithContext(timeoutCtx); g.SetLimit(10)；
③ 预分配长度 100 的结果切片 res := make([]Item, len(ids))，在循环中 g.Go 把 egCtx 传给 http.NewRequestWithContext，按各自独立下标 res[i] = item 写入（互不冲突免加锁），最后判断 if err := g.Wait(); err != nil 即可（回顾 06.4）。

03. 订单列表接口没查到数据时，前端拿到了 null 而不是 [] 导致页面报错；有数据时 19 位订单号末两位在前端变成了 00，怎么一起修？

① 修 null 变 []：声明结果切片时不要写零值 var list []Order（nil 切片序列化为 null），改为初始化非空表头 list := make([]Order, 0) 或 []Order{}。
② 修大整数丢精度：JS 的 Number 最大安全整数仅 16 位（253 - 1），在结构体字段标签加上 ,string，即 OrderID int64 `json:"order_id,string"`，自动序列化为字符串传输（回顾 04.3）。

04. 从本地热榜缓存切片 hot（含 10 条商品）截取前 3 条 top := hot[:3]，随后执行 top = append(top, adItem) 插入广告，为什么把原缓存第 4 条覆盖掉了？

原因：hot[:3] 只是复制了 24 字节切片表头，和 hot 共享同一块底层数组，此时 top 的 len=3 但剩余容量 cap=10。执行 append 时容量充足未触发扩容搬家，新元素直接写进了共享底层数组的下标 [3] 格，当场覆盖了 hot[3]。
解法：截取后若需修改或追加，一律先做独立拷贝 top := slices.Clone(hot[:3])，或用三下标语法 hot[:3:3] 锁死容量迫使 append 分配新数组（回顾 03.3）。

05. 线上晚高峰偶发整个容器直接退出重启，日志报 fatal error: concurrent map writes，明明挂了 RecoverMiddleware 为什么没拦住？

原因：Go 普通 map 并发读写触发的是运行时底层的 runtime.throw（fatal error），不属于普通 panic，任何 recover() 都无法捕获，进程必退出。
解法：用 sync.RWMutex（读用 RLock、写用 Lock）封装该共享字典，并在 CI 中跑 go test -race ./... 扫描全局状态并发读写（回顾 03.3 / 06.3）。

06. 调外部短信网关时直接用了 http.Post(...)，某天短信商机房故障卡住不回包，为什么 30 秒内把我们的登录注册主服务也彻底拖死了？

原因：标准库快捷函数 http.Get / http.Post 使用的 http.DefaultClient 默认 Timeout = 0（永不超时）。短信网关一卡死，每进来一个登录请求就永久卡住一个协程与连接句柄，迅速把本机资源耗光引发级联雪崩。
解法：① 全局复用显式设好 Timeout（如 3s）与 MaxIdleConnsPerHost 的自定义 *http.Client，并用 http.NewRequestWithContext 绑定请求超时；② 发短信这类非核心动作进一步扔进消息队列异步解耦（回顾 07.4）。

07. 在 HTTP Handler 返回前启动异步协程 go writeAuditLog(r.Context(), logData) 写库，为什么几乎每次都报 context canceled？

原因：r.Context() 的生命周期与当前这次 HTTP 请求强绑定——一旦主 Handler 执行完 return 把响应发给客户端，net/http 框架就会立刻取消 r.Context()；此时后台协程刚准备拿这个 ctx 查写 MySQL，当场撞上已取消报错。
解法：在 Go 1.21+ 中传入 bgCtx := context.WithoutCancel(r.Context())（保留里面的 TraceID 但剥离父级取消关联），再为后台写库单独包一层合理的超时 context.WithTimeout(bgCtx, 3*time.Second)，并用 SafeGo 包裹 recover() 防子协程崩溃（回顾 05.4 / 06.3）。

08. 每次发版滚动更新容器时，总有几十个正在执行中的接口报 502 错误或数据库事务只跑了一半，怎么做到无感平滑发版？

原因：进程未捕获 SIGTERM 信号做优雅停机，收到信号直接硬退出切断了在途连接。
解法：① 用 signal.NotifyContext 监听 SIGINT / SIGTERM；② 收到信号后先把就绪探针 /readyz 置为 503 让网关摘流，随后调用 srv.Shutdown(drainCtx) 停止接收新连接并留出 10~15 秒 让正在跑的在途请求执行完毕；③ 等 Shutdown 返回后，再依次关闭 MQ 消费者和 MySQL / Redis 连接池（回顾 08.3）。

09. 用 database/sql 查列表 rows, err := db.QueryContext(ctx, sql) 后忘了写 defer rows.Close()，跑几分钟后所有新请求全部超时卡死，为什么？

原因：在 database/sql 中，只要 rows 没有读到末尾且没调 rows.Close()，这条底层 TCP 数据库连接就会一直被该结果集独占而无法归还给连接池。一旦泄漏次数达到 SetMaxOpenConns(50) 上限，第 51 个请求就会一直在池外排队等待空闲连接直到 Context 超时。
规范：检查 if err != nil 通过后的下一行立刻写 defer rows.Close()；开启事务 BeginTx 通过后的下一行立刻写 defer tx.Rollback()（回顾 07.1）。

10. 写 AI 流式对话 SSE 接口时，每收到大模型一个词就 fmt.Fprintf(w, "data: %s\n\n", word)，为什么前端卡了 12 秒才一次性蹦出整段话？用户中途关网页怎么停掉计费生成？

① 卡住不实时推出：一是因为没在每次写入后调用 http.NewResponseController(w).Flush() 刷出服务端缓冲区；二是因为前置 Nginx 反向代理默认开启响应缓冲，需在响应头加上 X-Accel-Buffering: no 与 Content-Type: text/event-stream。
② 客户端断连即停：将 r.Context() 一路透传给调用下游大模型的 http.NewRequestWithContext(r.Context(), ...) 并在推送循环里监听 <-r.Context().Done()，用户一关页面 TCP 断开会自动取消 Context，下游流式连接随即立刻中断（回顾 07.5）。

09.2 · 附录（按需展开查表）：Go 全部 25 个保留关键字与三类预声明内置标识符

附录：25 个保留关键字与预声明标识符速查表

展开查看：Go 语言全部 25 个保留关键字四分类表 + 预声明内置类型与函数清单 [Go 1.22+]

Go 语言自诞生至今一共只有 25 个保留关键字（不能用作变量名或函数名），按用途分为四类：

分类（共 25 个） 保留关键字清单 替代了其他语言的什么语法
1. 包与声明（6 个） package、import、var、const、type、func • 无 public / private / export：直接通过标识符首字母大小写控制跨包可见性；
• 无 enum：通过 const 配合 iota 定义常量枚举。
2. 复合类型（4 个） struct、interface、map、chan • 无 class / extends / implements：用 struct 聚合字段与匿名组合，用 interface 非侵入式约定方法契约。
3. 流程控制（12 个） if、else、switch、case、default、for、range、break、continue、goto、fallthrough、return • 无 while / do：统一用 for；
• switch 默认自动跳出无需写 break（确需向下穿透才显式写 fallthrough）；
• 无 try / catch / finally：错误作为普通返回值显式返回。
4. 并发与延迟（3 个） go、select、defer • go 启动轻量级协程；select 多路监听通道；defer 在当前函数退出前逆序清理资源。
三类预声明标识符（Predeclared Identifiers / builtin 包）：
平时常用的 int、true、nil、make、len 等并不属于保留关键字，而是语言内置预声明的标识符：
1. 内置类型与泛型约束（22 个）：bool、byte（uint8 别名）、rune（int32 别名）、int / int8 / int16 / int32 / int64、uint / uint8 / uint16 / uint32 / uint64 / uintptr、float32 / float64、complex64 / complex128、string、error、any（Go 1.18+ 空接口别名）、comparable（Go 1.18+ 可判等约束）；
2. 内置常量与零值（4 个）：true、false、iota（常量块行计数器）、nil（指针/切片/字典/通道/函数/接口的空值）；
3. 内置函数（18 个）：make、new、len、cap、append、copy、delete、close、clear（Go 1.21+ 清空 map 或将 slice 置零值）、min / max（Go 1.21+）、complex / real / imag、print / println、panic、recover。
