01.1 · 环境准备：安装官方工具链、配置 GOPROXY 国内镜像与编辑器插件

01.1 安装 Go、配置 GOPROXY 与编辑器

Go 官方安装包已经打包了编译器、标准库、格式化工具与包管理器。本地装好后只需必配一行 GOPROXY 国内镜像，防止后续安装编辑器补全插件和第三方库时网络超时：

Step 1 · 三大操作系统安装 Go（推荐 1.22+） 
# 【macOS】使用 Homebrew 安装（或从 go.dev/dl 下载 .pkg 安装包）
$ brew install go

# 【Windows】使用 Winget 安装（自动写入系统 PATH 环境变量）
$ winget install GoLang.Go

# 【Linux】解压官方压缩包至 /usr/local/go 并加入 PATH
$ sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.24.0.linux-amd64.tar.gz
$ export PATH=$PATH:/usr/local/go/bin
Step 2 · 验证版本并永久写入国内模块代理（必配） 
# 1. 确认版本（本笔记代码基线为 Go 1.22+）
$ go version
go version go1.24.0 darwin/arm64

# 2. 配置国内加速代理（类似 npm config set registry，永久生效）
$ go env -w GOPROXY=https://goproxy.cn,direct

# 3. 查看关键环境变量：GOROOT(编译器路径) / GOPATH(依赖缓存目录 ~/go)
$ go env GOROOT GOPATH GOPROXY
IDE（Integrated Development Environment，集成开发环境）与工作目录说明：
• VS Code：扩展商店安装 Google 官方出品的 Go 插件 → 按 Cmd+Shift+P（Windows 按 Ctrl+Shift+P）执行 Go: Install/Update Tools，全选安装语言服务 gopls，保存文件时即可自动补全导包并格式化代码。JetBrains GoLand 则开箱即用。
• 项目放哪都行：早期老教程要求把代码放进 GOPATH/src，现代 Go 使用 go.mod 管理项目（类似 Node.js 的 package.json），你可以在电脑任意文件夹新建项目，~/go 仅用来缓存下载好的第三方包。
01.2 · 第一个程序：package main 入口结构与 go run / go build 流程

01.2 第一个 Go 程序：go run 与 go build

随便新建一个空文件夹，创建 main.go。每一个可独立运行的 Go 程序都必须同时具备 package main 包声明和无参数无返回值的 func main() 入口函数：

main.go · 最小可运行程序 [Go 1.22+] 
// 1. 声明所属包名：只有 main 包才能编译成独立可执行程序
package main

// 2. 导入官方标准库格式化输出包 fmt（未使用的 import 编译会直接报错）
import "fmt"

// 3. 程序唯一启动入口
func main() {
    fmt.Println("Hello, Go!")
}
Terminal · 本地快速运行 vs 编译打包可执行文件 
# 1. 开发调试：在系统临时目录编译并立即运行，当前目录不留二进制产物
$ go run main.go
Hello, Go!

# 2. 打包上线：在当前目录生成独立可执行二进制 app，直接运行无需 Go 环境
$ go build -o app main.go
$ ./app
Hello, Go!

本章即时场景题（先想答案，再点击展开）

1. 在 VS Code 里装完 Go 插件后，右下角弹窗安装 gopls 一直报 connect: connection timed out，怎么解决？

因为默认代理 proxy.golang.org 在国内无法直连。打开终端执行 go env -w GOPROXY=https://goproxy.cn,direct 写入国内镜像后，重启 VS Code 再执行一次 Go: Install/Update Tools，几秒就能装完。

2. 写代码调试时随手加了一行 import "os" 和一个临时变量 tmp := 1 暂时没用上，为什么连 go run 都跑不起来？

不同于 JS / ESLint 只报黄色 Warning，Go 编译器把「未使用的导入包（imported and not used）」和「未使用的局部变量（declared and not used）」直接定为编译错误，以此杜绝大型项目积攒死代码与膨胀编译耗时。配好编辑器保存自动运行 goimports 后，未使用的 import 会在按保存时自动帮你删掉。
