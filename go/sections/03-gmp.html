📍 03.1 · 值与指针：为什么有时候传普通变量，有时候传指针 *T？

📍 03.1 值传递与指针（& 取地址与 * 解引用）

在 Go 语言中，把一个变量传给函数时，默认都是把变量的值复制一份交给函数（即“值传递”）。因此，在函数里直接修改普通参数，改的只是复印件，不会影响外面的原变量。
如果我们希望在函数内部直接修改外部变量的值，或者后面学到的结构体字段很多、不想每次传参都完整复制一遍，就可以使用指针（Pointer）：

  • &v（取地址）：获取变量 v 在内存中的存放地址，得到一个指向它的指针（类型为 *T）；
  • *p（解引用）：顺着指针 p 记录的地址找到原变量，直接读取或修改原变量的值。
🐹 pointer_basic.go · 传普通值 vs 传指针修改原变量 
// 1. 传普通值：函数收到的是复印件，修改后不影响外部的 num
func addByValue(x int) {
    x = x + 10
}

// 2. 传指针 (*int)：函数收到的是原变量的地址，通过 *p 可直接修改原变量
func addByPointer(p *int) {
    *p = *p + 10
}

func main() {
    num := 5
    addByValue(num)
    fmt.Println("传值调用后 num =", num)   // 输出: 5 (原变量未变)

    addByPointer(&num)                     // 传入 &num (num 的地址)
    fmt.Println("传指针调用后 num =", num) // 输出: 15 (原变量被成功修改)
}

🏗️ 03.2 结构体（struct）：自定义类型、方法与 JSON 标签

Go 语言没有 class（类）关键字，而是用 结构体（struct） 把多个不同类型的数据字段打包成一个整体，并通过在函数名前加上接收者（Receiver）来为结构体绑定方法：

🐹 struct_method.go · 结构体定义、初始化与绑定方法 
// 1. 定义结构体：首字母大写的字段可被外部包访问（包括 json 包）
type User struct {
    ID   int64
    Name string
    Age  int
}

// 2. 为结构体绑定方法：在 func 与方法名之间写上接收者
// • 值接收者 (u User)：只读取字段、不修改原结构体时使用
func (u User) Greet() string {
    return "你好, 我是 " + u.Name
}

// • 指针接收者 (u *User)：需要修改结构体字段，或结构体较大时使用（最常用）
func (u *User) GrowUp() {
    u.Age++ // Go 会自动帮指针解引用，直接写 u.Age 即可，无需写 (*u).Age
}

func main() {
    u := User{ID: 1, Name: "Alice", Age: 18}
    u.GrowUp() // 编译器会自动转换为 (&u).GrowUp()
    fmt.Println(u.Greet(), "年龄:", u.Age) // 输出: 你好, 我是 Alice 年龄: 19
}
🐹 struct_embed_json.go · 组合嵌套与 JSON 标签序列化 
import (
    "encoding/json"
    "fmt"
)

// 1. 组合复用（匿名嵌入）：没有 extends 继承，直接把 Base 嵌入 Admin
type Base struct {
    CreatedAt string `json:"created_at"`
}

// 2. 字段右侧用反引号标注 Struct Tag，指定转成 JSON 时的字段名：
type Admin struct {
    Base                       // 匿名嵌入 Base，直接获得 CreatedAt 字段
    Username string `json:"username"`
    Password string `json:"-"` // json:"-" 表示转 JSON 时忽略该敏感字段
}

func main() {
    a := Admin{Base: Base{CreatedAt: "2026-01-01"}, Username: "root", Password: "123"}
    data, _ := json.Marshal(a) // 结构体 -> JSON 字节切片
    fmt.Println(string(data))
    // 输出: {"created_at":"2026-01-01","username":"root"}
}
💡 结构体配合 map 使用的小技巧：
当我们需要把结构体存进字典（如按用户名存用户信息）并且经常修改里面的字段时，推荐把字典定义为结构体指针类型 map[string]*User：
users := map[string]*User{"alice": {Name: "Alice", Age: 18}}，这样后续就可以直接写 users["alice"].Age = 20 修改字段了。

🔌 03.3 接口（interface）与泛型函数

① 什么是接口？interface 用来约定一组行为（方法签名）。Go 的接口采用非常灵活的“非侵入式（鸭子类型）”设计：不需要在结构体上写 implements 关键字，只要一个类型实现了接口里要求的全部方法，它就自动实现了这个接口。
在实际开发中，接口最常用于业务解耦——比如订单服务需要发通知，我们只需定义一个 Notifier 接口，不管是发短信还是发邮件都能无缝切换：

🐹 interface_demo.go · 用接口实现多种通知方式切换 
// 1. 定义接口：只约定“能发送消息 Send”，不关心具体怎么发
type Notifier interface {
    Send(msg string)
}

// 2. 邮件实现与短信实现：只要带有 Send(string) 方法，即自动满足 Notifier 接口
type EmailSender struct{ Address string }
func (e EmailSender) Send(msg string) {
    fmt.Println("[发邮件至", e.Address, "]:", msg)
}

type SMSSender struct{ Phone string }
func (s SMSSender) Send(msg string) {
    fmt.Println("[发短信至", s.Phone, "]:", msg)
}

// 3. 业务函数只接收 Notifier 接口，传入哪种实现就调用哪种
func NotifyUser(n Notifier, content string) {
    n.Send(content)
}
🐹 any_and_generics.go · 空接口 any 与 Go 1.18+ 泛型函数 
// 1. 空接口 any（即 interface{}）：不包含任何方法，因此可以装任意类型的值
var box any = "hello"
// 使用 x.(T) 类型断言取出里面的具体类型：
if str, ok := box.(string); ok {
    fmt.Println("取出的字符串:", str)
}

// 2. Go 1.18+ 泛型函数：当算法逻辑相同、仅数据类型不同时，
// 用 [T 类型约束] 编写一套通用代码，同时保留编译期类型检查：
func Sum[T int | int64 | float64](nums []T) T {
    var total T
    for _, v := range nums {
        total += v
    }
    return total
}
// 调用时可直接传 []int 或 []float64：Sum([]int{1, 2, 3}) -> 6

🏛️ 03.4 Go 项目开发核心技巧：用 interface 与设计模式构建高扩展性功能

在真实的 Go 工程开发中，最经典的设计思想就是围绕小巧的 interface 进行多渠道扩展与功能编排，并遵循社区推崇的 “接收接口，返回具体结构体（Accept interfaces, return structs）” 原则。下面展示实际项目中最常用的三大设计模式与实用技巧：

🧩 pattern_strategy.go · 技巧1：策略模式 + 注册表（零 if-else 扩展新渠道） 
// 1. 定义统一支付接口：无论微信、支付宝还是银行卡都实现该接口
type PayChannel interface {
    Pay(orderID string, cents int64) error
}

type WeChatPay struct{}
func (w *WeChatPay) Pay(id string, cents int64) error { return nil }

// ★ 工程小技巧：一行代码让编译器在编译期静态检查 WeChatPay 是否完整实现了接口
// （不分配任何运行时内存；若漏写方法或写错签名，编译当场报错！）
var _ PayChannel = (*WeChatPay)(nil)

// 2. 用 map 维护策略注册表：后续新增“支付宝/ApplePay”只需注册，无需改业务 if-else
var channels = map[string]PayChannel{
    "wechat": &WeChatPay{},
}

func Checkout(channelName, orderID string, cents int64) error {
    ch, ok := channels[channelName]
    if !ok {
        return fmt.Errorf("不支持的支付渠道: %s", channelName)
    }
    return ch.Pay(orderID, cents)
}
🧩 pattern_decorator.go · 技巧2：装饰器模式（不改原代码无感加上日志/重试） 
// 想要给任意 PayChannel 自动加上耗时统计和审计日志，但又不想污染微信/支付宝的核心代码？
// 解法：定义一个同样实现 PayChannel 接口的“包装结构体（Decorator）”：
type LoggingPay struct {
    next PayChannel // 内部持有一个真正的 PayChannel 接口
}

func (l *LoggingPay) Pay(orderID string, cents int64) error {
    fmt.Printf("[日志] 开始支付订单 %s, 金额 %d 分\n", orderID, cents)
    err := l.next.Pay(orderID, cents) // 转发给底层真实实现
    fmt.Printf("[日志] 订单 %s 支付结果: err=%v\n", orderID, err)
    return err
}

🧩 pattern_options.go · 技巧3：函数式选项模式（Functional Options） 
// Go 没有默认参数和函数重载。当初始化客户端有很多可选配置时，
// 工业界（如 gRPC、zap）标准做法是使用 WithXxx 函数式选项模式：
type Client struct {
    addr    string
    timeout int
    retries int
}

// 1. 定义修改配置的函数类型 Option
type Option func(*Client)

func WithTimeout(sec int) Option { return func(c *Client) { c.timeout = sec } }
func WithRetries(n int) Option   { return func(c *Client) { c.retries = n } }

// 2. 构造函数先填好合理默认值，再遍历执行调用方传入的 Option
func NewClient(addr string, opts ...Option) *Client {
    c := &Client{addr: addr, timeout: 3, retries: 1} // 默认超时3秒、重试1次
    for _, opt := range opts {
        opt(c)
    }
    return c
}
// 调用极清爽：cli := NewClient("127.0.0.1:8080", WithTimeout(10), WithRetries(3))
💡 Go 接口设计的三条黄金工程准则
  • 准则 1：接口越小越好（推荐 1~3 个方法）。像标准库的 io.Reader 只有 1 个 Read(p []byte) (int, error) 方法，却能同时适配文件、网络连接、内存缓冲和加密流；需要复杂能力时用小接口组合（如 io.ReadCloser）。
  • 准则 2：在调用方（Consumer）所在包按需定义接口。不要像传统面向对象语言那样先写一个包含 20 个方法的大接口再去实现；而是业务层需要用到哪两个方法，就在业务包里定义一个只含这两个方法的接口，方便单元测试时随时传入内存 Mock 实现。
  • 准则 3：编译期静态校验。写完接口实现后，随手加一行 var _ 接口名 = (*结构体名)(nil)，让编译器帮你守住接口契约。
