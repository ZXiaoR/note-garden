🔧 04.1 函数特性：多返回值、可变参数与闭包

Go 语言中的函数是一等公民（可以赋值给变量、作为参数传递或作为返回值）。日常开发中最常用的三个特性是多返回值、可变参数 ...T 与匿名闭包函数：

🐹 func_multi_varargs.go · 多返回值与可变参数 
// 1. 多返回值：Go 函数最常见的模式是同时返回 (结果, 错误)
func Divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("除数不能为 0")
    }
    return a / b, nil
}

// 2. 可变参数 (...int)：允许调用者传入任意个数的参数，函数内部将其视为切片 []int
func SumAll(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}
// 调用方式：SumAll(1, 2, 3) 或将切片展开传入 SumAll(slice...)
🐹 func_closure.go · 函数作为参数与闭包 
// 闭包（Closure）：内部匿名函数引用了外部函数的局部变量 count，
// 只要返回的匿名函数还在使用，count 的生命周期就会一直延续：
func NewCounter() func() int {
    count := 0
    return func() int {
        count++
        return count
    }
}

func main() {
    next := NewCounter()
    fmt.Println(next(), next(), next()) // 输出: 1 2 3
}
⏱️ 04.2 · 延迟调用 defer：先进后出（LIFO）调用栈、return 三步执行时机与参数求值规则

⏱️ 04.2 延迟调用（defer）：先进后出栈与 return 执行时机拆解

在日常开发中，我们经常需要“先打开文件再关闭”或“先加锁再解锁”。Go 提供了 defer 关键字用于注册延迟调用。要真正用好 defer，需要掌握它的三个核心机制：① 先进后出（LIFO）的栈结构、② 在 return 真正退出前执行的三步时机，以及 ③ 注册时参数当场求值规则：

🐹 defer_lifo_file.go · LIFO 栈顺序与成对释放资源 
func CopyFile(srcPath, dstPath string) error {
    src, err := os.Open(srcPath)
    if err != nil {
        return err
    }
    defer src.Close() // ① 先压入栈底（函数退出时最后关闭 src）

    dst, err := os.Create(dstPath)
    if err != nil {
        return err // 即使这里提前返回，上面已注册的 src.Close() 也会自动执行！
    }
    defer dst.Close() // ② 后压入栈顶（函数退出时最先关闭 dst，再关闭 src）

    _, err = io.Copy(dst, src)
    return err
}
🐹 defer_return_eval.go · return 前执行 defer 与参数求值时机 
// 1. 验证 return 三步拆解：defer 在 return 赋值之后、真正退出之前执行
func calc() (res int) {
    defer func() {
        res += 10 // 第 2 步执行 defer：把已经赋值为 5 的命名返回值 res 改成了 15
    }()
    return 5 // 第 1 步先执行 res = 5 ➔ 第 2 步跑 defer (res=15) ➔ 第 3 步真正返回 15
}

// 2. 参数求值时机：直接传参在注册那一行当场求值；闭包在退出时读取最新值
func evalTiming() {
    x := 1
    defer fmt.Println("直接传参 x =", x)             // 注册时当场求值，固定存下 x=1
    defer func() { fmt.Println("闭包读取 x =", x) }() // 退出时才去读变量 x，读到 x=2
    x = 2
} // 输出顺序（LIFO）：先打印 "闭包读取 x = 2"，再打印 "直接传参 x = 1"
🛡️ 04.3 · 错误处理：error 显式返回、%w 包装错误链与 errors.Is / As

🛡️ 04.3 错误处理（error）：显式返回、包装与判断

Go 语言没有采用 try / catch 抛出异常的方式，而是把错误设计为一个普通的内置接口 type error interface { Error() string }，作为函数的最后一个返回值显式传递。
这样做的好处是：看一眼函数调用代码，就能清楚知道哪一步可能出错，并当场处理或补充上下文信息往上返回：

🐹 error_handling.go · 定义错误、%w 附加上下文与 errors.Is 判断 
import (
    "errors"
    "fmt"
)

// 1. 定义可复用的预定义错误（习惯以 Err 开头）
var ErrUserNotFound = errors.New("user not found")

func queryDB(id int) error {
    if id <= 0 {
        return ErrUserNotFound
    }
    return nil
}

// 2. 往上层返回错误时，使用 fmt.Errorf("当前操作说明: %w", err) 包装原始错误
func GetUserProfile(id int) error {
    if err := queryDB(id); err != nil {
        return fmt.Errorf("查询用户(id=%d)资料失败: %w", id, err)
    }
    return nil
}

func main() {
    err := GetUserProfile(-1)
    // 3. 调用方使用 errors.Is 即可穿透多层 %w 包装，精准判断底层原因：
    if errors.Is(err, ErrUserNotFound) {
        fmt.Println("提示前端：该用户不存在 ->", err)
    }
}
