04.1 · 值传递与指针操作：传值副本机制、取地址（&）与解引用（*）

04.1 值传递与指针（& 取地址与 * 解引用）

在 JavaScript 里，对象总是按共享引用传递；而在 Go 中，一切函数传参默认都是把值复制一份交给函数（值传递）。如果希望在函数内部直接修改外部原变量，或者结构体很大不想每次传参都拷贝整块字段，就使用指针（Pointer，只占 8 字节内存地址，且不支持 C 语言那种危险的指针加减运算）：

  • &v（取地址）：拿到变量 v 在内存中的地址，类型为 *T；
  • *p（解引用）：顺着指针 p 记录的地址读写原变量（注意：对 nil 空指针解引用会触发空指针崩溃）。
pointer_basic.go · 传普通值副本 vs 传指针修改原变量 [Go 1.22+] 
package main

import "fmt"

func addByValue(x int)    { x = x + 10 }   // 改的是复印件，不影响外部
func addByPointer(p *int) { *p = *p + 10 } // 顺着地址直接修改外部原变量

func main() {
    num := 5
    addByValue(num)
    fmt.Println("传值后:", num)   // 输出: 5

    addByPointer(&num)
    fmt.Println("传指针后:", num) // 输出: 15
}

04.2 · 结构体 struct：字段定义、值/指针方法接收者与匿名组合复用

04.2 结构体（struct）：自定义类型、方法接收者与组合

Go 用 struct 聚合数据字段，通过在 func 和方法名之间加一个接收者（Receiver，相当于把普通函数的第一个参数移到了前面，类似 JS 里的 this）来绑定方法，并用匿名嵌入（组合）替代类继承：

struct_method.go · 值接收者 vs 指针接收者怎么选 [Go 1.22+] 
package main

import "fmt"

type User struct {
    ID   int64
    Name string
    Age  int
}

// 对比普通函数 func Greet(u User) string：把 (u User) 移到前面即成为方法
// • 值接收者 (u User)：只读小结构体时可用
func (u User) Greet() string { return "你好, " + u.Name }

// • 指针接收者 (u *User)：需要修改字段、含锁字段或结构体较大时必用（工程主力）
func (u *User) GrowUp() {
    u.Age++ // Go 自动解引用，直接写 u.Age 即可
}

func main() {
    u := User{ID: 1, Name: "Alice", Age: 18}
    u.GrowUp() // 编译器自动转为 (&u).GrowUp()
    fmt.Println(u.Greet(), u.Age) // 你好, Alice 19
}
struct_embed.go · 匿名组合嵌套与 JSON 标签基础 [Go 1.22+] 
package main

import (
    "encoding/json"
    "fmt"
)

type Timestamps struct {
    CreatedAt string `json:"created_at"`
}

// 字段首字母必须大写，encoding/json 包才能读取导出！
type Admin struct {
    Timestamps                 // 匿名嵌入：直接获得 CreatedAt 字段与方法，JSON 自动平铺
    Username string `json:"username"`
    Password string `json:"-"` // json:"-" 序列化时永远忽略该敏感字段
}

func main() {
    a := Admin{Timestamps: Timestamps{CreatedAt: "2026-11-28"}, Username: "root", Password: "secret"}
    b, _ := json.Marshal(a)
    fmt.Println(string(b)) // {"created_at":"2026-11-28","username":"root"}
}
04.3 · 前后端联调避坑：nil 切片变 null、omitempty 吞零值、时间格式与大整数丢精度

04.3 实战避坑：JSON（JavaScript Object Notation，JavaScript 对象表示法）四大常见误区

Go 标准库 encoding/json 与前端 JavaScript 对接时，有四个高频细节如果不提前处理，很容易在联调阶段写出隐蔽 Bug：

联调高频误区 错误现象与原因 生产标准解法
1. 空列表变成 null 只声明 var list []Order（nil 切片），查库没数据时序列化成 {"list":null}，前端调 res.list.map() 当场报错。 初始化为非 nil 空切片：list := []Order{} 或 make([]Order, 0)，序列化结果即为前端预期的 {"list":[]}。
2. omitempty 误吞合法零值 写了 Stock int `json:"stock,omitempty"` 或 Done bool `json:"done,omitempty"`，当库存卖成 0 或状态为 false 时，字段直接从 JSON 里消失了；且局部更新接口无法区分“前端没传该字段”还是“明确传了 0”。 • 返回给前端的响应结构体：数值/布尔字段不要乱加 omitempty；
• 局部更新请求（PATCH）结构体：把可选字段定义为指针类型 *int / *bool 配合 omitempty——前端没传是 nil，传了 0 则是非空指针且解引用值为 0。
3. 时间格式与参考时间 time.Time 默认按 RFC 3339（Request for Comments 3339，互联网日期时间标准）输出 "2026-11-28T15:04:05+08:00"；若新手写格式化模板误写 yyyy-MM-dd 会输出一串乱数字。 • 跨端最稳妥做法是直接传毫秒级 Unix 时间戳 int64（无时区歧义）；
• 若需自定义文本格式，Go 的 Format 必须写固定参考时间 "2006-01-02 15:04:05"（记忆：2006年1月2日下午3点4分5秒 = 6-1-2-3-4-5）。
4. 64 位大整数前端丢精度 后端用 19 位雪花 ID int64（如 1862049182736459779），而前端 JS 的 Number 最大安全整数仅为 253 - 1（16 位），JSON.parse 后末尾变成 ...800，回传查库全报 404。 在结构体标签末尾加上 ,string：写成 ID int64 `json:"id,string"`。encoding/json 序列化时会自动包上双引号变成字符串 "1862049182736459779"，反序列化时也会自动把前端传回的字符串解析回 int64。
json_pitfalls.go · 一段代码验证全部四项安全写法 [Go 1.22+] 
package main

import (
    "encoding/json"
    "fmt"
    "time"
)

type OrderResp struct {
    OrderID   int64    `json:"order_id,string"`   // 1. 19位大整数自动转 JSON 字符串防 JS 丢精度
    Stock     int      `json:"stock"`             // 2. 不加 omitempty，库存为 0 也如实输出 "stock":0
    Tags      []string `json:"tags"`              // 3. 赋值为 []string{} 保证输出 [] 而非 null
    CreatedAt string   `json:"created_at"`        // 4. 格式化使用固定参考时间 2006-01-02 15:04:05
}

// 局部更新请求体：用指针 *int 区分“没传 stock 字段(nil)”与“把库存清零(*p == 0)”
type PatchStockReq struct {
    Stock *int `json:"stock,omitempty"`
}

func main() {
    resp := OrderResp{
        OrderID:   1862049182736459779,
        Stock:     0,
        Tags:      []string{}, // 非 nil 空切片
        CreatedAt: time.Date(2026, 11, 28, 15, 30, 0, 0, time.Local).Format("2006-01-02 15:04:05"),
    }
    out, _ := json.Marshal(resp)
    fmt.Println(string(out))
    // 输出: {"order_id":"1862049182736459779","stock":0,"tags":[],"created_at":"2026-11-28 15:30:00"}

    var req PatchStockReq
    _ = json.Unmarshal([]byte(`{"stock":0}`), &req)
    if req.Stock != nil {
        fmt.Println("前端明确传入了库存:", *req.Stock) // 0
    }
}
04.4 · 接口与解耦：非侵入式 interface、安全类型断言与函数式选项模式

04.4 接口（interface）、any 与常用工程技巧

Go 的 interface 只约定一组方法签名，采用非侵入式（鸭子类型）实现——不需要写 implements，只要结构体实现了接口要求的全部方法，就自动满足该接口。工程中遵循「在调用方定义小接口（1～3 个方法），测试时直接传内存假实现做单测」的原则，并常用函数式选项（WithXxx）优雅解决 Go 没有默认参数的问题：

interface_demo.go · 非侵入式接口、编译期校验与类型断言 [Go 1.22+] 
package main

import "fmt"

type Notifier interface {
    Send(msg string) error
}

type SMSSender struct{ Phone string }

func (s *SMSSender) Send(msg string) error {
    fmt.Println("[短信->", s.Phone, "]:", msg)
    return nil
}

// 编译期静态断言：不占运行内存，若 *SMSSender 漏实现方法则编译当场报错
var _ Notifier = (*SMSSender)(nil)

func main() {
    var n Notifier = &SMSSender{Phone: "1380000"}
    _ = n.Send("验证码 8848")

    // 空接口 any (interface{} 别名) 取出具体类型时，始终带上 ok 避免断言失败 panic
    var box any = "hello"
    if str, ok := box.(string); ok {
        fmt.Println("安全取出长度:", len(str))
    }
}
functional_options.go · 用 WithXxx 选项模式替代可选配置对象 [Go 1.22+] 
package main

import "fmt"

// Go 没有函数默认参数，初始化带大量可选配置的组件时，标准写法是 Option 函数：
type Client struct {
    addr    string
    timeout int
    retries int
}

type Option func(*Client)

func WithTimeout(sec int) Option { return func(c *Client) { c.timeout = sec } }
func WithRetries(n int) Option   { return func(c *Client) { c.retries = n } }

func NewClient(addr string, opts ...Option) *Client {
    c := &Client{addr: addr, timeout: 3, retries: 1} // 先填安全默认值
    for _, opt := range opts {
        opt(c)
    }
    return c
}

func main() {
    cli := NewClient("127.0.0.1:8080", WithTimeout(10))
    fmt.Printf("%+v\n", cli) // &{addr:127.0.0.1:8080 timeout:10 retries:1}
}
04.5 · 泛型（Generics，Go 1.18+）：类型约束、通用响应结构与官方泛型标准库

04.5 泛型（Generics）：类型参数 [T 约束] 与选型边界

选型口诀：不同类型「行为逻辑不同」用 interface（如微信支付 vs 支付宝支付）；「处理逻辑完全相同、仅仅元素类型不同」用泛型 [T]（如统一分页响应 PageResp[T]、切片去重与字段提取）。常见约束有四种：any（任意类型）、comparable（可判等/作 map 键）、cmp.Ordered（可比大小，Go 1.21+），以及加波浪号 ~int64 兼容底层类型为 int64 的自定义别名类型：

generics_api.go · 泛型分页响应结构与通用提取函数 [Go 1.22+] 
package main

import "fmt"

// 1. 泛型统一分页响应包装：Data 随业务类型动态确定，告别 any 丢失类型提示
type PageResp[T any] struct {
    Total int64 `json:"total"`
    Items []T   `json:"items"`
}

// 2. 通用切片去重函数：T 受 comparable 约束，可安全作为 map 的 Key
func Uniq[T comparable](in []T) []T {
    seen := make(map[T]struct{}, len(in))
    out := make([]T, 0, len(in))
    for _, v := range in {
        if _, ok := seen[v]; !ok {
            seen[v] = struct{}{}
            out = append(out, v)
        }
    }
    return out
}

func main() {
    ids := Uniq([]int64{101, 102, 101, 103}) // 自动推导 T 为 int64
    fmt.Println(PageResp[int64]{Total: 3, Items: ids})
}
generics_stdlib.go · Go 1.21+ 内置 min/max 与 cmp.Or 默认值 [Go 1.22+] 
package main

import (
    "cmp"
    "fmt"
    "maps"
    "os"
)

func main() {
    // 1. 内置泛型函数 min / max（Go 1.21+）：直接支持所有整数、浮点数和字符串
    fmt.Println(min(12, 5, 9), max("go", "node")) // 5 node

    // 2. cmp.Or（Go 1.22+）：返回第一个非零值，非常像 JS 的 env.PORT || "8080"
    port := cmp.Or(os.Getenv("PORT"), "8080")

    // 3. maps.Clone（Go 1.21+）：一行浅克隆字典
    mCopy := maps.Clone(map[string]int{"a": 1})
    fmt.Println(port, mCopy)
}

本章即时场景题（先想答案，再点击展开）

1. 定义了结构体 type LoginResp struct { token string `json:"token"` }，为什么调用 json.Marshal 返回了空对象 "{}"？

因为字段名 token 首字母是小写（包内私有未导出），处于外部标准库包里的 encoding/json 无权通过反射读取它，于是直接跳过了该字段。把字段名改成首字母大写 Token string `json:"token"` 即可正常输出小写键名的 {"token":"..."}。

2. 搜索接口没搜到商品时返回了 {"items": null}，前端页面因为执行 res.items.length 白屏报错了，后端怎么从根源避免？

查库前初始化结果切片时，不要写零值声明 var items []Product（零值是 nil，序列化为 null），而是写成 items := make([]Product, 0) 或 items := []Product{}（长度为 0 的非 nil 空切片，序列化永远是 []）。

3. 数据库用户主键用的是 19 位雪花算法 int64，前端列表页拿到 ID 后再点进详情页，后端却查不到该用户，为什么？怎么改？

原因：前端浏览器的 JSON.parse 把 JSON 数字按双精度浮点数解析，超过 253 - 1（16 位）的大整数末几位精度会被四舍五入抹成 0。
一行修复：在响应和请求结构体的该字段标签加上 ,string，即 UserID int64 `json:"user_id,string"`，让前后端之间以 JSON 字符串无损传输 64 位整数。
