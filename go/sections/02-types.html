🍕 02.1 定长数组 [N]T 与动态切片 []T 的日常用法

当我们需要按顺序存放一组同类型的数据时，Go 提供了数组（Array）和切片（Slice）两种类型：

  • 定长数组 [N]T：方括号里带有固定数字（如 [3]int），长度在创建时就锁死了，不能追加元素。日常仅在明确固定长度（如 IPv4 地址 [4]byte）时使用。
  • 动态切片 []T（日常开发主力）：方括号里不写长度（如 []int、[]string），可以根据需要随时调用 append 动态增长。
🐹 slice_create_append.go · 切片的 3 种初始化方式与 nil 切片区别 
// 方式一：只声明不初始化 (nil 切片) —— 此时底层还没分配数组空间 (s1 == nil)
var s1 []int
// ❌ s1[0] = 10  -> 直接按下标写会崩溃: panic: index out of range [0] with length 0
// ✅ 但对 nil 切片调用 append 是合法的，append 会自动在堆上分配底层数组：
s1 = append(s1, 10, 20)         // [10 20]

// 方式二：字面量初始化 —— 声明的同时分配好底层数组并填入初始值 (nums != nil)
nums := []int{10, 20}
nums = append(nums, 30)         // [10 20 30]

// 方式三：使用 make([]T, 长度 len, 容量 cap) 显式分配底层数组内存
// • 写法 A：指定长度 3 —— 已填好 3 个零值 [0 0 0]，可直接按下标赋值：
fixed := make([]int, 3)
fixed[0] = 99                   // ✅ 合法: [99 0 0]
// • 写法 B：长度设为 0、预留容量 100 —— 适合配合 append 动态追加：
list := make([]string, 0, 100)
list = append(list, "first")    // len=1, cap=100
🐹 slice_sub_copy.go · 区间截取、独立拷贝与标准库排序 
import (
    "fmt"
    "slices"
)

s := []int{30, 10, 40, 20}

// 1. 区间截取 s[low:high]：遵循“左闭右开”（含下标 1 和 2，不含 3）
sub := s[1:3]                   // 结果: [10 40]

// 2. 独立拷贝：截取出的 sub 与原切片 s 共享同一块底层数组；
// 若希望得到互不影响的独立切片，使用 slices.Clone 或内置 copy：
independent := slices.Clone(sub)

// 3. Go 1.21+ 标准库 slices 常用工具（排序、查找是否包含）：
slices.Sort(s)                  // 升序排序后 s 变为: [10 20 30 40]
found := slices.Contains(s, 20) // true
fmt.Println(independent, found)
💡 理解切片的长度 len(s) 与容量 cap(s)（为什么推荐提前用 make 预留容量？）：
切片在底层其实是一个指向连续数组的“动态窗口”：len(s) 是当前已经放进去的元素个数，cap(s) 是底层数组目前最多能装下的个数。
• 当你不断调用 append 把当前容量装满（len == cap）时，Go 会在后台自动申请一块更大的新数组，把原来的元素全部复制过去，再放入新元素。
• 因此在平时写代码时，如果提前知道大概要放多少条数据（例如从数据库查出 500 条记录），先写 make([]int, 0, 500) 一次性预留好容量，就能省去中途多次扩容和复制数据的开销。

🗂️ 02.2 键值字典 map[K]V 的日常用法

map[KeyType]ValueType 是 Go 内置的键值对哈希表（字典），通过键（Key）查找、插入或删除值（Value）的平均时间复杂度都是 O(1)。下面展示日常开发中最常用的创建、读写、判断键是否存在以及删除遍历操作：

🐹 map_crud.go · 字典的初始化（防 nil panic）与增删改查 
// ⚠️ 重点：只声明 var m map[string]int 时，底层哈希表尚未分配 (m == nil)
var uninitMap map[string]int
fmt.Println(uninitMap["a"]) // 读 nil map 不会崩，返回零值 0
// ❌ uninitMap["a"] = 1    // 写 nil map 直接崩溃: panic: assignment to entry in nil map

// ✅ 正确初始化方式一：用 make(map[K]V, 预估容量) 在堆上分配哈希表内存
scores := make(map[string]int, 16)
scores["alice"] = 95
scores["bob"] = 0

// ✅ 正确初始化方式二：用花括号字面量初始化（空字典写 map[string]int{}）
prices := map[string]int{"apple": 5, "banana": 3}

// 查找与存在性判断（利用第二个布尔返回值 ok 区分“存了 0”还是“不存在”）：
if val, ok := scores["bob"]; ok {
    fmt.Println("bob 存在，分数为:", val) // 输出: bob 存在，分数为: 0
}

// 删除键值对：若 Key 不存在或 map 为 nil，delete 什么都不做，不会报错
delete(scores, "alice")
_ = prices
🐹 map_range_set.go · 遍历字典、按序输出与去重集合 
import (
    "fmt"
    "slices"
)

m := map[string]int{"b": 2, "a": 1, "c": 3}

// 1. 常规遍历：使用 for k, v := range m（每次遍历顺序是随机的）
for k, v := range m {
    fmt.Println(k, v)
}

// 2. 若需要按 Key 字母顺序固定输出：先把 Key 收集到切片排好序，再按序读
keys := make([]string, 0, len(m))
for k := range m {
    keys = append(keys, k)
}
slices.Sort(keys) // ["a", "b", "c"]
for _, k := range keys {
    fmt.Printf("%s:%d ", k, m[k]) // 固定输出: a:1 b:2 c:3
}

// 3. 用 map[string]bool 快速实现去重集合（Set）：
seen := make(map[string]bool)
seen["user_101"] = true
if seen["user_101"] {
    fmt.Println("已访问过")
}
⚠️ 为什么 slice 和 map 只声明不初始化时，直接写入会触发 Panic？
与 int、[3]int 这类变量本身直接装数据的类型不同，slice 和 map 的真实数据块分布在堆内存上，变量自身只保存指向底层内存的指针：
• var m map[string]int（未初始化的 nil map）：此时内部指针为 nil，堆上根本没有分配哈希桶。虽然读取 m["k"] 或调用 delete(m, "k") 不会报错，但一旦执行写入 m["k"] = 1，程序找不到存放数据的哈希桶地址，就会立即崩溃：panic: assignment to entry in nil map。因此写入前必须用 make(map[string]int) 或 map[string]int{} 完成初始化（尤其当结构体内部包含 map 字段时，创建结构体时切记一并 make 初始化该字段）。
• var s []int（未初始化的 nil slice）：此时底层数组指针为 nil、len = 0。若直接用下标写入 s[0] = 1 会报 panic: runtime error: index out of range [0] with length 0；正确做法是先用 make([]int, 3) 分配指定长度，或者直接调用 s = append(s, 1) 让 append 自动分配底层数组。
💡 日常使用 map 的两个性能与安全建议：
1. 已知数据量时传入预估容量：与切片类似，map 在装满时也会在后台自动扩容并搬迁数据。如果事先知道大概有 100 个键值对，使用 make(map[string]int, 100) 一步分配到位，性能更好。
2. 多协程共享时加锁：普通的 map 适合在单个协程内部使用；如果在并发编程（第 05 节）中需要多个协程同时读写同一个 map，配合互斥锁 sync.Mutex 或读写锁 sync.RWMutex 即可安全访问。
