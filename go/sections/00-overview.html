00.1 · 语言定位与适用边界：静态单二进制、轻量并发、完备标准库与选型边界

00.1 Go 是什么，以及为什么后端与云原生普遍选它

Go（又称 Golang）由 Google 于 2009 年开源，由 Ken Thompson（Unix 与 UTF-8 共同设计者）、Rob Pike 与 Robert Griesemer 主持设计。它的工程目标很明确：把静态编译语言的运行效率与类型安全，和动态脚本语言的开发简洁性结合起来。后端服务与云原生基础设施广泛采用 Go，主要源于三项核心特性：

① 编译成单个可执行二进制
几万行源码数秒即可编译为一个内含运行时的独立二进制文件，拷上服务器无需安装 Node 运行时或 Java 虚拟机即可直接运行，Docker 镜像可轻松压到 10 ~ 25 MB，冷启动在毫秒级。
② 并发写法直观，自动跑满多核
在任意函数前加一个 go 关键字就能启动轻量级协程（goroutine，初始栈仅 2KB），底层由 GMP（Goroutine / Machine / Processor，协程调度模型）调度到多核 CPU（Central Processing Unit，中央处理器）上并行执行，没有异步回调嵌套和函数染色。
③ 标准库完备，团队代码长相一致
生产级 HTTP（HyperText Transfer Protocol，超文本传输协议）服务、JSON 解析、数据库连接池、结构化日志、单元测试与性能剖析全部内置于官方标准库；配合 gofmt 强制统一排版，跨团队接手代码成本很低。
适合用 Go 写什么
  • 高并发 API（Application Programming Interface，应用程序接口）服务与微服务：订单、用户、支付网关、AI 流式编排后端；
  • 网络网关、反向代理与长连接推送：高吞吐请求转发、SSE 流式网关、WebSocket 服务；
  • 云原生基础设施与容器工具：Docker、Kubernetes、etcd、Prometheus、Terraform 均由 Go 编写；
  • 跨平台 CLI（Command-Line Interface，命令行界面）工具与运维 Agent：一次编译即可分发给 macOS / Linux / Windows 用户直接执行。
不太适合用 Go 写什么
  • 硬实时与零 GC（Garbage Collection，垃圾回收）停顿系统：操作系统内核、嵌入式固件、微秒级高频交易核心（更适合 C / C++ / Rust）；
  • 前端同构渲染（SSR）与纯页面聚合层：需要与前端共享同一套组件和校验逻辑时，TypeScript / Node.js 更顺手；
  • AI 模型训练、科学计算与临时数据分析脚本：矩阵计算与深度学习生态集中在 Python（Go 适合做外围推理网关与工程编排）；
  • 极度复杂的传统企业级 ERP 单体：若重度依赖运行时字节码增强与声明式切面框架，Java / Spring 生态积淀更深。
00.2 · 横向选型对照：Go vs Node.js vs Java 的运行机制、并发模型与工程权衡

00.2 和 Node.js、Java 的横向对比表

对于已经熟悉 JavaScript / Node.js 的开发者来说，把 Go 放在 Node.js 和 Java 中间做对照，最容易找准它的工程坐标（Node.js 自身的事件循环与多进程细节可对照 《 Node.js · 基础与实战篇》）：

对比维度 Go（1.22+） Node.js（TypeScript / V8） Java（JDK 21+ / Spring Boot）
编译与部署产物 静态编译单二进制文件，无外部运行时依赖，容器镜像约 10 ~ 25 MB，毫秒级启动 源码 + node_modules + Node 运行时，镜像约 120 ~ 300 MB，启动较快 字节码 JAR + JVM 虚拟机（需 JIT 预热），镜像约 200 ~ 400 MB，启动较慢、基础内存偏高
类型安全 原生编译期静态强类型，运行期依然保留真实内存类型布局，重构安全 JS 动态弱类型；TS 仅在编译期做类型擦除检查，运行期仍需防范脏数据 编译期 + 运行期强类型，泛型采用类型擦除，反射与注解能力极强
并发模型与多核 goroutine + GMP 多核并行调度，同步写法自动利用全部 CPU 核心，计算与网络 I/O 兼顾 单线程事件循环 + async/await（见 Node 原理篇 · libuv），I/O 高效，但单次 CPU 计算会卡住整个进程 传统操作系统线程池，JDK 21 起引入虚拟线程（Virtual Threads）对齐轻量协程模型
错误处理方式 (val, error) 显式多返回值，在调用处就地判断，分支路径透明 try / catch 或 Promise.catch，漏捕获易产生未处理拒绝（Unhandled Rejection） try / catch 异常栈冒泡（受检与非受检异常），配合全局异常切面拦截
首选发力场景 高并发后端服务、网关、微服务、CLI、流式与高吞吐中间件 前后端同构 SSR、BFF（服务于前端的后端）轻量聚合、实时协作原型 超大型复杂业务域建模、金融核心账务、大数据生态（Kafka / Flink）
00.3 · 写给 JS 开发者的思维切换：类型零值、显式错误、无染色协程与结构体组合

00.3 给 JS 开发者的四项「思维切换」对照

从 JavaScript / TypeScript 转写 Go，语法本身一两天就能顺手，真正需要切换的是下面四个编码习惯：

思维维度 你在 JavaScript / TS 里的习惯 切换到 Go 之后的写法与原因
1. 类型与空值 变量类型可变；未赋值是 undefined，空对象是 null，常写 a || "默认"（容易把数字 0 和空串误判为假值）。 静态类型 + 默认「零值」：声明 var n int 自动就是 0，var s string 自动就是 ""，绝无 undefined；指针、切片、字典、接口的空值统一叫 nil，且条件判断必须是严格的 bool（不能写 if count {}）。
2. 错误处理 函数内部 throw new Error()，外层包一圈大 try { ... } catch (e)，看调用处代码看不出哪一行会抛异常。 显式返回 error 值：可能失败的函数签名写成 func Load(id int) (User, error)。调用后紧跟 if err != nil { return ... }，虽然多写三行，但每一步出错怎么兜底、补什么上下文一目了然。
3. 并发执行 async / await + Promise.all。一旦底层函数变成 async，整条调用链的函数签名都要跟着加 async（函数染色）。 go 关键字 + 同步写法：所有函数都是普通同步函数；需要并发时在调用前加 go，需要同时跑一批任务并等结果时用 errgroup 或 WaitGroup + channel，没有任何 async/await 关键字传染。
4. 面向对象 用 class User extends Base 把属性、构造函数、方法包进类里，用 public / private 控制可见性。 没有 class 和继承，只有 struct + 方法 + interface：数据字段定义在 struct 里，方法通过接收者挂在类型外；首字母大写即公开导出（Exported），首字母小写即包内私有；复用靠组合嵌套而非继承链。
user.js · JavaScript 习惯写法（class + async + try/catch） 
class UserService {
  async getName(id) {
    if (id <= 0) throw new Error('invalid id');
    return `User_${id}`;
  }
}

async function main() {
  const svc = new UserService();
  try {
    const name = await svc.getName(42);
    console.log('拿到用户:', name);
  } catch (err) {
    console.error('出错:', err.message);
  }
}
main();
main.go · 等价的 Go 习惯写法（struct + 显式 error）[Go 1.22+] 
package main

import (
    "errors"
    "fmt"
)

type UserService struct{} // 结构体代替 class

// 首字母大写 GetName 表示外部包可调用；返回 (结果, error) 二元组
func (s *UserService) GetName(id int) (string, error) {
    if id <= 0 {
        return "", errors.New("invalid id")
    }
    return fmt.Sprintf("User_%d", id), nil
}

func main() {
    svc := &UserService{}
    name, err := svc.GetName(42)
    if err != nil {
        fmt.Println("出错:", err)
        return
    }
    fmt.Println("拿到用户:", name)
}
00.4 · 全篇知识地图：从跑通环境、语法避坑、业务实战到上线工程与底层原理

00.4 本笔记知识地图

整份笔记按照「全景 → 快速上手 → 语法与高频坑 → 并发与真实业务场景 → 工程上线 → 底层原理」的弧线组织。第一次学可以顺着实线从左往右读；平时写业务遇到具体需求（如连库、写中间件、推流、优雅停机）可以直接跳第 06～08 章，想深挖背后机制再顺着每节末尾的链接切到《核心原理篇》：

本章即时场景题（先想答案，再点击展开）

1. 团队要做一个需要同时请求 6 个下游接口聚合数据、并对报文做实时签名与脱敏计算的网关服务，在 Node.js 与 Go 之间怎么权衡？

优先选 Go。虽然 Node.js 处理纯网络 I/O 转发也很快，但它的主事件循环是单线程的，一旦并发高起来，报文加解密签名与大 JSON 脱敏这类 CPU 密集计算会阻塞主线程，拖慢所有并发请求的响应延迟；而 Go 的 goroutine 由 GMP 自动调度在所有 CPU 核心上并行跑，网络等待与 CPU 计算互不卡死，且单实例内存占用更平稳。

2. 写一个给客户的离线内网 Linux 服务器（无外网、未装 Python/Node/Docker）使用的数据库巡检小工具，为什么首选 Go？

交付成本几乎为零。Node.js 或 Python 脚本通常要求目标机器装有对应版本的解释器并搬运一堆离线依赖包；而 Go 支持在本地开发机上一行命令交叉编译出静态链接的 Linux 单二进制文件（见 08.6 交叉编译），直接通过 scp 传上去赋予执行权限就能跑。

3. 刚从 JS 转过来的同事写了一段 Go 代码：把方法命名为 getUserInfo() 放在 service 包里，结果在 handler 包里死活调用不到，问题出在哪？

首字母大小写决定了跨包可见性。Go 没有 export 或 public 关键字：标识符首字母小写（getUserInfo）表示包内私有，只有同一个 service 包里的文件能调；想让外部 handler 包访问，只需把首字母改成大写 GetUserInfo()（结构体名和需要 JSON 序列化的字段名也是同理）。
