📋 01.1 程序最小骨架、四种变量声明与 iota 枚举生成器

Go 的设计哲学是“一件事尽量只有一种标准写法”：没有三元运算符 ?:、没有 while/do-while（循环只有 for）、没有隐式类型转换，且所有声明的变量若未显式赋值，100% 自动初始化为对应类型的零值（Zero Value），绝不存在 C/C++ 的未初始化野内存。

🐹 main_and_vars.go · 四种变量声明形态 
package main            // 可执行程序必须属于 main 包

import "fmt"

func main() {           // 程序唯一入口（无参数、无返回值）
    var a int = 10      // ① 完整声明（显式指定类型）
    var b = 20          // ② 类型推导（自动识别为 int）
    c := 30             // ③ 短变量声明（最常用，★仅限函数内部！）
    var d int           // ④ 零值初始化：默认就是 0
    fmt.Println(a, b, c, d)
}
🔢 const_iota.go · 常量与 iota 位掩码实战 
// iota：每个 const 块从 0 开始逐行自增 1 的行计数器
type State int
const (
    StateInit    State = iota // 0
    StateRunning              // 1（沿用上一行表达式）
    _                         // 2（用 _ 跳过废弃枚举值）
    StateStopped              // 3
)

// 经典技巧：配合左移位生成权限位掩码（Bitmask）或容量单位
const (
    PermRead  = 1 << iota // 1 << 0 = 1 (0b001)
    PermWrite             // 1 << 1 = 2 (0b010)
    PermExec              // 1 << 2 = 4 (0b100)
)
⚠️ 短变量声明 := 的“变量遮蔽（Variable Shadowing）”陷阱：当 := 左边同时包含旧变量与至少一个新变量且在同一作用域时，旧变量会被直接修改；但如果写在内层代码块（如 if res, err := call(); err != nil）中，内层的同名变量会完全遮蔽外层变量，导致外层变量保持零值不变！

🧬 01.2 基本类型零值表、string / byte / rune UTF-8 底层与高性能拼接

类型分类 内置类型 默认零值 底层说明与避坑要点
整数类型 int, int8, int16, int32, int64
uint, uint8..uint64, uintptr		 0 int / uint 在 64 位架构下占 8 字节（64 位）。禁止任何隐式数值类型转换，int32 + int64 必须显式强转。
字符别名 byte（即 uint8）
rune（即 int32）		 0 byte 代表 1 个原始字节（ASCII）；rune 代表 1 个 Unicode 码点（Code Point），可装下任意汉字或 Emoji。
字符串 string ""（空串） 底层是 16 字节只读结构体 { Data *byte, Len int }，UTF-8 编码，天生不可变（Immutable）。
指针 / 引用语义 *T、slice、map、chan、func、interface nil 注意：struct 和固定数组 [N]T 是纯值类型，零值是各字段零值的组合，绝不是 nil！
🔍 utf8_rune.go · 下标取字节 vs range 解码 rune 
s := "Go语言"
fmt.Println(len(s))                    // 8（UTF-8 每个汉字占 3 字节：2+3+3）
fmt.Println(utf8.RuneCountInString(s)) // 4（真实字符数，等价于 len([]rune(s))）

// ① s[i] 按【字节 byte】取，中文会被截断成乱码
// ② for i, r := range s 自动按【UTF-8 码点 rune】解码！
for i, r := range s {
    fmt.Printf("byteIdx=%d, char=%c\n", i, r)
    // 输出下标：0('G'), 1('o'), 2('语'), 5('言')
}

🧱 01.3 · 没有 class 和 extends，Go 怎么实现面向对象？接收者该选值还是指针？

⚙️ 01.3 结构体匿名组合（Embedding）与方法接收者选择法则

Go 推崇“组合优于继承（Composition over Inheritance）”：通过在 struct 中匿名嵌入另一个结构体，直接“提升（Promote）”其字段和方法。在为结构体定义方法时，值接收者 (u User) 与指针接收者 (u *User) 的区别是面试高频考点：

🏗️ struct_embed.go · 结构体 Tag、方法与匿名嵌入 
type User struct {
    ID   int    `json:"id"`            // 大写导出(Public) + JSON 反射标签
    Name string `json:"name,omitempty"`
    age  int                           // 小写包内私有(Private)
}

// 值接收者：操作的是副本，外部原对象不受影响
func (u User) Greeting() string { return "Hi " + u.Name }

// 指针接收者：直接修改原结构体，且仅传递 8B 地址
func (u *User) Birthday() { u.age++ }

// 匿名嵌入（组合继承）：Admin 直接获得 User 的字段与方法
type Admin struct {
    User        // 匿名字段提升：可直接调 admin.Birthday()
    Level int
}
对比维度 值接收者 (t T) 指针接收者 (t *T)（★主流）
修改字段 仅改栈内副本，外部不可见 直接改原对象，外部可见
传参开销 拷贝整个 struct 仅拷贝 8 字节指针
接口方法集（★必考） T 和 *T 都能赋值给该接口 只有 *T 能赋值给接口，T 值本身未实现该接口！
💡 为什么 T 值不能调 *T 的接口方法？平时写 u.Birthday() 编译器会自动帮你取地址转成 (&u).Birthday()；但一旦把 u 塞进 interface，接口内部持有的值是不可寻址（Unaddressable）的副本，没法自动取地址！
🎯 01.4 · 面试开场灵魂二问：make 和 new 有什么区别？Go 有引用传递吗？

🔑 01.4 make vs new 对照与“Go 只有值传递”底层拆解

① new(T) vs make(T, args...)
  • new(T)（适用任意类型）：只做一件事——分配一块 T 类型的内存并清零（Zero Value），返回指向它的指针 *T（等价于 &T{}）。
  • make(T, ...)（仅限 slice / map / chan 三种内置引用类型）：这三种类型本身是带内部指针的运行时描述符（sliceHeader / hmap / hchan），只清零无法使用。make 负责分配并初始化底层数组/哈希桶/环形缓冲，直接返回初始化好的 T 值本身（而非指针）。
② 为什么说 Go 100% 只有【值传递（Pass-by-Value）】？
  • 传 int / [4]int / struct：拷贝整块数据，函数内修改与外部完全隔离。
  • 传 *T 指针：拷贝的是 8 字节内存地址值，指向同一个堆/栈对象。
  • 传 slice：拷贝的是 24 字节 {ptr, len, cap} 表头（改元素可见，扩容换底层数组外部不可见）。
  • 传 map / chan：它们在底层就是指向 hmap / hchan 的8 字节指针包装，拷贝指针值，所以函数内增删 key 外部直接可见。

🔄 包加载与 init() 执行铁律（深度优先）
递归 import 子包 → const 常量 → var 全局变量 → init() → main()
  • 匿名导入 import _ "github.com/lib/pq"：仅触发该包的 init()（常用于注册 SQL 驱动或监控插件）。
  • MVS（Minimal Version Selection 最小版本选择）：若包 A 依赖 D >= 1.1，包 B 依赖 D >= 1.3，Go 确定性地选择满足所有约束的最老版本 1.3（而非自动拉取最新版 1.9），保证 100% 可重现构建。
