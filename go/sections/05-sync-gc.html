⚡ 05.1 · 并发执行：用 go 启动轻量级协程，配合 sync.WaitGroup 等待完成

⚡ 05.1 启动协程（go）与等待完成（sync.WaitGroup）

在 Go 中发起并发任务非常简单：只需要在函数调用前加上 go 关键字，这个函数就会在一个独立的轻量级协程（Goroutine）中异步运行。
需要注意的是：如果主函数 main() 执行完毕退出，整个程序就会立即结束，不会自动等待后台还在跑的协程。因此日常开发中最常用的配合方式是使用标准库的 sync.WaitGroup（等待组）：

  • wg.Add(1)：在启动协程之前，把待完成任务计数加 1；
  • defer wg.Done()：在协程函数内部开头注册，协程执行完时自动把计数减 1；
  • wg.Wait()：在主函数中调用，会一直等待直到计数器归零（即所有协程都执行完）才继续往下走。
🐹 goroutine_waitgroup.go · 并发执行 3 个任务并等待全部完成 
package main

import (
    "fmt"
    "sync"
)

func fetchData(id int, wg *sync.WaitGroup) {
    defer wg.Done() // 2. 当前协程退出时，自动将计数器减 1
    fmt.Printf("任务 #%d 执行完成\n", id)
}

func main() {
    var wg sync.WaitGroup

    for i := 1; i <= 3; i++ {
        wg.Add(1)              // 1. 启动协程前，先登记 +1
        go fetchData(i, &wg) //    注意传入 &wg 指针，共享同一个计数器
    }

    wg.Wait() // 3. 阻塞等待，直到 3 个协程全部调用完 Done()
    fmt.Println("所有并发任务均已完成！")
}
📮 05.2 · 协程间通信：用 chan 安全传递数据与 select 多路监听

📮 05.2 通道（channel）与 select 多路监听

当一个协程算出了结果，怎么安全地交给另一个协程？Go 提供了 通道（chan），就像在两个协程之间接了一根并发安全的传送管道：

  • 无缓冲通道 make(chan T)：管道里不存东西，发送方 ch <- v 会等待接收方 <-ch 来接，适合两边严格同步交接；
  • 有缓冲通道 make(chan T, cap)：带有容量为 cap 的队列，只要队列没满，发送方放进去就能立刻继续干活，适合生产者-消费者任务队列。
🐹 channel_worker.go · 发送、接收与关闭通道 
func main() {
    // 创建一个缓冲容量为 3 的字符串通道
    jobs := make(chan string, 3)

    // 生产者协程：发送 3 个任务后关闭通道，通知接收方“发完了”
    go func() {
        jobs <- "订单A"
        jobs <- "订单B"
        jobs <- "订单C"
        close(jobs) // 由发送方负责调用 close
    }()

    // 消费者：使用 for range 自动从通道读取，通道关闭且读空后自动退出循环
    for item := range jobs {
        fmt.Println("处理:", item)
    }
}
🐹 select_timeout.go · 用 select 同时监听通道与超时 
import (
    "fmt"
    "time"
)

// select 语法类似 switch，但它专门用来同时等待多个通道操作，
// 哪个分支先准备好就执行哪个：
func waitResult(resCh chan string) {
    select {
    case data := <-resCh:
        fmt.Println("收到结果:", data)
    case <-time.After(500 * time.Millisecond):
        fmt.Println("等待超过 500ms，触发超时保护")
    }
}
🔒 05.3 · 并发锁与超时控制：互斥锁 sync.Mutex、读写锁 sync.RWMutex 与 context.Context

🔒 05.3 互斥锁（Mutex）、读写锁（RWMutex）与超时控制（Context）

当多个协程需要同时读写同一块共享内存（例如全局计数器或内存字典缓存）时，必须加锁保护。Go 标准库 sync 提供了两把最常用的锁，按业务读写比例选择：

锁类型 加锁与解锁方法 并发互斥规则 典型适用场景
互斥锁
sync.Mutex		 • 加锁：mu.Lock()
• 解锁：mu.Unlock()		 完全独占：无论读还是写，同一时刻只允许 1 个协程持有锁（读与读也互斥） 读写频率相近或每次操作都包含修改的场景（如扣减库存、累加状态计数器、更新连接池状态）
读写锁
sync.RWMutex		 • 读锁：rw.RLock() / RUnlock()
• 写锁：rw.Lock() / Unlock()		 读读共享、读写互斥、写写互斥：允许任意多个协程同时持有读锁；但写锁是独占的 读多写少（如 99% 读、1% 写）场景（如本地配置中心缓存、路由表、用户信息内存缓存），并发读取吞吐量远高于 Mutex
🐹 rwmutex_cache.go · 用读写锁 sync.RWMutex 保护读多写少的配置缓存 
type ConfigCache struct {
    rw   sync.RWMutex      // 读写锁（零值直接可用）
    data map[string]string // 记得在构造函数中用 make 初始化！
}

// 1. 高频读取：加【读锁 RLock】，允许成百上千个协程同时并发读取，互不阻塞
func (c *ConfigCache) Get(k string) string {
    c.rw.RLock()
    defer c.rw.RUnlock()
    return c.data[k]
}

// 2. 低频更新：加【写锁 Lock】，独占访问（期间其他读写协程均会等待）
func (c *ConfigCache) Set(k, v string) {
    c.rw.Lock()
    defer c.rw.Unlock()
    c.data[k] = v
}
🐹 context_timeout.go · 用 context.WithTimeout 控制请求超时 
import (
    "context"
    "fmt"
    "time"
)

// 在后端处理 HTTP 请求或查数据库时，习惯把 ctx 作为函数的第 1 个参数，
// 用来统一控制超时时间（WithTimeout）或取消信号传递：
func main() {
    // 派生一个最多允许执行 2 秒的上下文 ctx
    ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
    defer cancel() // 函数结束时自动释放底层计时器资源

    // 将 ctx 传给下游查询函数（如 db.QueryContext(ctx, "SELECT ...")）
    fmt.Println("当前上下文错误状态:", ctx.Err())
}
💡 使用 Mutex / RWMutex 的两个实用细节：
1. 方法接收者必须用指针 (c *ConfigCache)：锁变量包含内部状态，绝不能通过值传递复制；
2. 不可重入与防写饥饿：同一个协程里不能在还没解锁时再次加锁（包括持有 RLock 期间在同一协程内直接调用 Lock），否则会导致死锁；此外当有写协程调用 rw.Lock() 排队时，Go 会自动拦住后面新来的 RLock() 请求，确保写操作不会被源源不断的读请求饿死。
