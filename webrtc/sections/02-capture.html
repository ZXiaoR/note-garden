02.1 · 轨道模型：MediaStream（流容器）与 MediaStreamTrack（独立音画轨）的控制差异

02.1 流容器与独立轨道的控制规范

对应五步全景图的第 ① 步（本地采集）：调用 getUserMedia({ audio: true, video: true }) 返回的 MediaStream 是一个「流容器」，它内部通常装着两条独立的轨道（MediaStreamTrack）：一条 kind === 'audio' 的音频轨（可通过 stream.getAudioTracks() 取出），一条 kind === 'video' 的视频轨（可通过 stream.getVideoTracks() 取出）。

在社交连麦与视频会议开发中，最容易混淆的是「通话中临时闭麦/关画面」与「挂断退房彻底释放硬件」两个操作，它们对应的轨道 API 完全不同：

操作方式 硬件与指示灯状态 网络发送行为 适用业务时机与恢复方式
track.enabled = false
（软静音 / 软关画面）		 摄像头与麦克风硬件保持占用，浏览器标签页小红点仍在 WebRTC 连接不断开，底层自动替换为极小体积的纯静音帧 / 纯黑画面帧 通话中点击「闭麦 / 关闭摄像头」按钮：再次设为 track.enabled = true 时毫秒级恢复声音画面，无需重新走硬件权限与信令协商。
track.stop()
（硬停止并归还系统）		 立即释放摄像头与麦克风驱动，电脑摄像头绿灯与标签页红点熄灭 该轨道永久进入 ended 终止态，停止产生任何媒体帧 挂断通话退出房间、或组件 onBeforeUnmount 销毁时：轨道一旦 stop() 无法重新开启，下次要再开必须重新调用 getUserMedia()。
02.2 · 实战采集：ideal 弹性约束降级、enumerateDevices 设备列表与 replaceTrack 无缝切流

02.2 权限降级、前后镜头热切换与屏幕共享代码

在真实线上环境中，用户的设备千差万别（低端安卓机不支持 1080p、台式机没插摄像头、用户只给了麦克风权限拒绝了摄像头）。编写采集模块时遵循三条工程习惯，可以避免绝大多数进房报错：

  • 分辨率与帧率用 ideal 不用 exact：写 width: { ideal: 1280 } 时，若旧手机最高只支持 640×480，浏览器会自动挑最接近的档位返回；若写成硬性要求 exact: 1280，不满足时会直接抛 OverconstrainedError 导致进房失败。
  • 先授权再枚举设备名称：调用 navigator.mediaDevices.enumerateDevices() 获取麦克风/摄像头下拉列表时，为了防指纹追踪，在用户尚未授权过 getUserMedia 之前，返回的 device.label 会是空字符串；应在首次授权成功后再刷新设备列表。
  • 通话中翻转前后镜头用 sender.replaceTrack()：拿到新摄像头的 videoTrack（或 Canvas 美颜滤镜通过 canvas.captureStream(24) 生成的轨道）后，直接调用 RTCRtpSender.replaceTrack(newTrack) 即可在不断连、不重发 SDP 的情况下平滑替换画面。

// 1. 弹性采集音视频流：若无摄像头或视频受限，自动降级为纯语音流保证用户能先进房说话
export async function acquireLocalMedia(facingMode: 'user' | 'environment' = 'user') {
  if (!navigator.mediaDevices?.getUserMedia) {
    throw new Error('请使用 HTTPS 或 localhost 安全环境访问页面以启用音视频设备');
  }

  const audioConstraints: MediaTrackConstraints = {
    echoCancellation: true,  // 开启 AEC 回声消除（防外放啸叫）
    noiseSuppression: true,  // 开启 ANS 背景噪声抑制
    autoGainControl: true,   // 开启 AGC 自动增益（平衡说话音量忽大忽小）
  };

  try {
    return await navigator.mediaDevices.getUserMedia({
      audio: audioConstraints,
      video: {
        width: { ideal: 1280 },
        height: { ideal: 720 },
        frameRate: { ideal: 24, max: 30 },
        facingMode, // 移动端 'user' 为前置自拍镜头，'environment' 为后置主摄
      },
    });
  } catch (err: any) {
    // NotFoundError: 未插摄像头；OverconstrainedError: 视频参数不满足 -> 退化为纯音频连麦
    if (err.name === 'NotFoundError' || err.name === 'OverconstrainedError') {
      return await navigator.mediaDevices.getUserMedia({ audio: audioConstraints, video: false });
    }
    throw err; // NotAllowedError（用户主动点拒绝）向上抛出，由 UI 弹窗引导去浏览器设置开启权限
  }
}

// 2. 通话中无缝切换为屏幕共享（或切回前后置摄像头），无需重新协商 SDP
export async function switchToScreenShare(
  pc: RTCPeerConnection,
  localVideoEl: HTMLVideoElement,
  cameraTrackFallback: MediaStreamTrack
) {
  const screenStream = await navigator.mediaDevices.getDisplayMedia({ video: true });
  const screenTrack = screenStream.getVideoTracks()[0];

  const videoSender = pc.getSenders().find(s => s.track?.kind === 'video');
  if (videoSender) {
    await videoSender.replaceTrack(screenTrack);
  }
  localVideoEl.srcObject = screenStream;

  // 监听用户点击浏览器顶部的系统级「停止共享」按钮，自动切回原本的摄像头画面
  screenTrack.onended = async () => {
    if (videoSender) await videoSender.replaceTrack(cameraTrackFallback);
  };
}
