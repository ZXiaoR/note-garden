💚 04.1 · Vue 3 实战：封装支持候选暂存队列、断网重连、弱网提示与秒切下一位的 useWebRTCCall

💚 04.1 Vue 3 视频通话组合式函数封装（useWebRTCCall.ts）

在 Vue 3 项目（如海外 1v1 视频匹配、在线视频客服）中落地原生 WebRTC 时，有四个直接决定线上稳定性的工程细节需要封装进 Composable：

  • ① 用 shallowRef 隔离浏览器原生对象：RTCPeerConnection 与 MediaStream 带有内部 C++ 绑定插槽，不能放进 Vue 的深层 ref() / reactive() Proxy 代理，否则调用原生方法可能触发非法调用异常。
  • ② pendingCandidates 暂存队列消除信令竞态：网络异步传输时，对端发来的 ice-candidate 有可能比 offer / answer 更早到达本地，或者本地正在异步执行 setRemoteDescription 尚未完成；此时直接调用 addIceCandidate 会抛 InvalidStateError。先推入队列、待远端 SDP 就绪后统一冲刷即可彻底解决。
  • ③ 左滑「切换下一位」复用本地 MediaStream：在 1v1 随机匹配场景中，用户连续划走换人时，只关闭并重建轻量的 RTCPeerConnection，保留已打开的本地摄像头流不调用 stop()，可省去移动端每次重启硬件镜头的 400~800ms 黑屏闪烁；只有退出匹配页时才彻底关闭硬件。
  • ④ 定时采样 pc.getStats() 感知弱网：每 2 秒读取一次真实往返延迟（RTT）与视频近期丢包率，驱动 UI 弹出「当前网络较差，建议关闭视频保持语音畅通」提示条。

import { ref, shallowRef, onBeforeUnmount } from 'vue';

export interface CallQualityStats {
  rttMs: number;          // 往返延迟 (ms)
  packetLossRate: number; // 近期丢包率 (0 ~ 1)
  isWeakNetwork: boolean; // 是否触发前端弱网提示
}

export function useWebRTCCall(signalingWs: WebSocket, roomId: string, iceServers: RTCIceServer[]) {
  const localStream = shallowRef<MediaStream | null>(null);
  const remoteStream = shallowRef<MediaStream | null>(null);
  const connectionState = ref<RTCPeerConnectionState>('new');
  const isMicMuted = ref(false);
  const isCamOff = ref(false);
  const quality = ref<CallQualityStats>({ rttMs: 0, packetLossRate: 0, isWeakNetwork: false });

  let pc: RTCPeerConnection | null = null;
  let isRemoteDescSet = false;
  const pendingCandidates: RTCIceCandidateInit[] = [];
  let statsTimer: ReturnType<typeof setInterval> | null = null;
  let prevLost = 0;
  let prevRecv = 0;

  function sendSignal(type: string, payload: unknown) {
    if (signalingWs.readyState === WebSocket.OPEN) {
      signalingWs.send(JSON.stringify({ roomId, type, payload }));
    }
  }

  function initPeerConnection() {
    pc = new RTCPeerConnection({
      iceServers,
      iceCandidatePoolSize: 4, // 提前预热候选地址池，缩短海外匹配首帧等待
    });
    isRemoteDescSet = false;
    remoteStream.value = new MediaStream();

    // 1. 注入本地已采集的音视频轨道
    localStream.value?.getTracks().forEach(track => {
      pc!.addTrack(track, localStream.value!);
    });

    // 2. Trickle ICE：每收集到一个候选地址，立即通过信令发给对端
    pc.onicecandidate = ({ candidate }) => {
      if (candidate) sendSignal('ice-candidate', candidate.toJSON());
    };

    // 3. 收到对端轨道时合入 remoteStream，绑定到 <video :srcObject.prop="remoteStream" autoplay playsinline />
    pc.ontrack = ({ track }) => {
      remoteStream.value?.addTrack(track);
    };

    // 4. 网络切换恢复：用户从 Wi-Fi 走到室外切 4G 导致 failed 时，发起 ICE Restart 重新打洞
    pc.onconnectionstatechange = async () => {
      if (!pc) return;
      connectionState.value = pc.connectionState;
      if (pc.connectionState === 'failed') {
        const restartOffer = await pc.createOffer({ iceRestart: true });
        await pc.setLocalDescription(restartOffer);
        sendSignal('offer', restartOffer);
      }
    };

    startStatsMonitor();
    return pc;
  }

  // 主叫方入口：创建并发送 Offer SDP
  async function startAsCaller(stream: MediaStream) {
    localStream.value = stream;
    const peer = initPeerConnection();
    const offer = await peer.createOffer();
    await peer.setLocalDescription(offer);
    sendSignal('offer', offer);
  }

  // 处理信令服务器转发过来的协商消息
  async function handleSignalMessage(msg: { type: string; payload: any }, stream: MediaStream) {
    if (!localStream.value) localStream.value = stream;
    if (!pc) initPeerConnection();

    if (msg.type === 'offer') {
      await pc!.setRemoteDescription(new RTCSessionDescription(msg.payload));
      isRemoteDescSet = true;
      await flushPendingCandidates();
      const answer = await pc!.createAnswer();
      await pc!.setLocalDescription(answer);
      sendSignal('answer', answer);
    } else if (msg.type === 'answer') {
      await pc!.setRemoteDescription(new RTCSessionDescription(msg.payload));
      isRemoteDescSet = true;
      await flushPendingCandidates();
    } else if (msg.type === 'ice-candidate') {
      if (!isRemoteDescSet) {
        pendingCandidates.push(msg.payload); // 远端 SDP 未就绪，先暂存防报错
      } else {
        await pc!.addIceCandidate(new RTCIceCandidate(msg.payload));
      }
    }
  }

  async function flushPendingCandidates() {
    while (pendingCandidates.length > 0 && pc) {
      await pc.addIceCandidate(new RTCIceCandidate(pendingCandidates.shift()!));
    }
  }

  function startStatsMonitor() {
    if (statsTimer) clearInterval(statsTimer);
    statsTimer = setInterval(async () => {
      if (!pc || pc.connectionState !== 'connected') return;
      const reports = await pc.getStats();
      let rttMs = 0;
      let lossRate = 0;
      reports.forEach(r => {
        if (r.type === 'candidate-pair' && r.state === 'succeeded' && r.currentRoundTripTime != null) {
          rttMs = Math.round(r.currentRoundTripTime * 1000);
        }
        if (r.type === 'inbound-rtp' && r.kind === 'video') {
          const dLost = (r.packetsLost || 0) - prevLost;
          const dRecv = (r.packetsReceived || 0) - prevRecv;
          lossRate = dLost + dRecv > 0 ? Math.max(0, dLost / (dLost + dRecv)) : 0;
          prevLost = r.packetsLost || 0;
          prevRecv = r.packetsReceived || 0;
        }
      });
      quality.value = { rttMs, packetLossRate: lossRate, isWeakNetwork: rttMs > 350 || lossRate > 0.08 };
    }, 2000);
  }

  function toggleMic() {
    isMicMuted.value = !isMicMuted.value;
    localStream.value?.getAudioTracks().forEach(t => { t.enabled = !isMicMuted.value; });
  }
  function toggleCamera() {
    isCamOff.value = !isCamOff.value;
    localStream.value?.getVideoTracks().forEach(t => { t.enabled = !isCamOff.value; });
  }

  // stopHardware=false 用于右滑秒切下一位（复用摄像头流）；stopHardware=true 用于彻底挂断退出
  function cleanup(stopHardware = true) {
    if (statsTimer) { clearInterval(statsTimer); statsTimer = null; }
    if (pc) {
      pc.onicecandidate = null;
      pc.ontrack = null;
      pc.onconnectionstatechange = null;
      pc.close();
      pc = null;
    }
    if (stopHardware) {
      localStream.value?.getTracks().forEach(t => t.stop());
      localStream.value = null;
    }
    remoteStream.value = null;
    pendingCandidates.length = 0;
    isRemoteDescSet = false;
  }

  onBeforeUnmount(() => cleanup(true));

  return {
    localStream, remoteStream, connectionState, quality, isMicMuted, isCamOff,
    startAsCaller, handleSignalMessage, toggleMic, toggleCamera, cleanup,
  };
}

🤖 04.2 多人 RTC SDK 模型与 AI 实时语音交互实践

🏢 1. 商业与开源多人 SDK 的统一抽象

当业务从 1v1 升级到 8 人语聊房或派对房时，工程团队通常接入开源 LiveKit 或商业 声网（Agora）/ 即构（ZEGO）。虽然各家包名不同，但前端状态模型完全一致，都是三层树状结构：

  • Room（房间实例）：传入后端签发的 token 调用 room.connect(wsUrl, token)，SDK 内部自动搞定信令、重连与 SFU 穿透；
  • Participant（参会成员）：区分 localParticipant 与 remoteParticipants 列表，用于渲染麦位头像、说话声浪光圈（isSpeaking）；
  • TrackPublication（轨道发布）：监听 TrackSubscribed 事件把远端成员的音画轨挂载到对应麦位组件上。
🎙️ 2. WebRTC × AI 实时语音/数字人架构

早期 AI 语音聊天用「前端录音分片发 WebSocket → ASR → LLM → TTS 分片播放」，延迟常超 2 秒且外放声音容易被手机麦克风录回去自己打断自己。主流实时多模态接口（如 OpenAI Realtime API、LiveKit Agents）已全面转向 WebRTC：

  • 语音走原生音频轨：直接复用浏览器内置的 Opus 低延迟编码、JitterBuffer 抗抖动与硬件级 AEC 回声消除，随时插话不啸叫；
  • 字幕与工具调用走 RTCDataChannel：实时双语字幕流、情绪动作指令、Function Calling 结果以及用户开口打断信号（服务端 VAD 检测），全部通过同一连接的数据通道毫秒级同步。

异常现象 最常见根因 前端核查与修复方案
调用采集直接报 TypeError: Cannot read properties of undefined (reading 'getUserMedia') 局域网手机调试使用了明文 http://192.168.x.x，非安全上下文下浏览器屏蔽了媒体接口。 使用 Vite @vitejs/plugin-basic-ssl 开启本地 HTTPS，或通过 USB 端口转发映射为手机本地 localhost。
iPhone 上一接通视频，整个画面突然弹成系统全屏挡住聊天与礼物按钮 iOS Safari 的 <video> 默认全屏播放视频流。 所有 <video> 标签统一加上 playsinline 与 webkit-playsinline 属性。
对端画面出来了但没有声音，或者控制台报 NotAllowedError 浏览器自动播放策略拦截了未经用户手势交互的有声媒体播放。 尽量在用户点击「开始匹配」按钮的交互链路内预初始化播放元素；捕获 NotAllowedError 时先静音起播画面，并弹出轻触开启声音按钮。
两人一接通就传出刺耳的回声或循环啸叫 本地预览自己的 <video> 忘了加 muted，把自己麦克风的声音从本机喇叭放了出来。 渲染本机流的 <video> 永久设置 muted 属性，同时确认采集约束开启了 echoCancellation: true。
同 Wi-Fi 下测试百试百通，一换手机 4G/5G 流量就卡在 checking 后变 failed 未配置可用的公网 TURN 中继服务器（或 TURN 短期账号密码已过期），遇到运营商对称型 NAT 无法直连。 打开 chrome://webrtc-internals 检查候选列表中是否有 relay 类型候选；联系后端核对 TURN 凭证有效性与 443 端口连通性。
挂断退出通话组件后，浏览器标签页小红点或电脑摄像头绿灯依然常亮 只把 <video> 从 DOM 卸载或只调了 pc.close()，未停止底层媒体轨道。 在退房函数与 onBeforeUnmount 钩子中遍历 localStream.getTracks().forEach(t => t.stop())。
