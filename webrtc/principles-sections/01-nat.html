01.1 · 报文解剖：Offer / Answer 交换的 SDP 文本结构与五项核心协商契约

01.1 SDP（Session Description Protocol）真实报文逐行拆解

SDP（RFC 8866） 并不是传输协议，而是一种严格按 <单字母类型>=<值> 行排列的纯文本会话契约。现代浏览器统一采用 Unified Plan 格式——每一条独立的音频轨或视频轨在 SDP 中对应一个独立的 m=（Media Description）媒体段：

Offer SDP 核心字段节选（可在 chrome://webrtc-internals 中查看） 
v=0
o=- 4611731400430051336 2 IN IP4 127.0.0.1
s=-
t=0 0
# 1. BUNDLE 多路复用：声明音频轨(mid=0)与视频轨(mid=1)共用同一个 UDP 端口传输
a=group:BUNDLE 0 1

# ==================== 音频媒体段 (mid=0) ====================
m=audio 9 UDP/TLS/RTP/SAVPF 111 103
a=mid:0
a=sendrecv
a=rtcp-mux
# 2. ICE 连通探测临时账号与密码（每次 ICE Restart 都会重新生成这两行）
a=ice-ufrag:k8xP
a=ice-pwd:9vL2mQpW7nR4tY8uI1oP3aS6
# 3. DTLS 自签名证书公钥指纹（防信令服务器中间人篡改音视频密钥）
a=fingerprint:sha-256 4A:8F:2C:19:...
a=setup:actpass
# 4. 编解码器 Payload Type 映射与 Opus 带内前向纠错开关
a=rtpmap:111 opus/48000/2
a=fmtp:111 minptime=10;useinbandfec=1

# ==================== 视频媒体段 (mid=1) ====================
m=video 9 UDP/TLS/RTP/SAVPF 96 102
a=mid:1
a=sendrecv
a=rtpmap:96 VP8/90000
a=rtpmap:102 H264/90000
a=fmtp:102 level-asymmetry-allowed=1;packetization-mode=1;profile-level-id=42e01f
# 5. 声明该视频轨支持的弱网反馈机制：PLI 关键帧请求、NACK 丢包重传、TWCC 拥塞评估
a=rtcp-fb:102 nack
a=rtcp-fb:102 nack pli
a=rtcp-fb:102 transport-cc
SDP 报文中的 5 类关键协商字段
  • a=group:BUNDLE 0 1 + a=rtcp-mux：早期音轨、画轨、RTP、RTCP 要开 4 个不同端口（打 4 次洞极易失败）；开启这两项后，全连接所有音视频、控制包与 DataChannel 全部复用同一个 UDP 端口，穿透成功率大幅提升。
  • m=video 9 ... 96 102：末尾数字列表按优先级排列本端支持的编码编号（96 对应 VP8，102 对应 H.264）；被叫方在 Answer SDP 中把双方都支持的编号排在第一位即完成编码协商。
  • profile-level-id=42e01f：其中前两位 42 代表 H.264 的 Constrained Baseline 档次（不含 B 帧，所有 iOS/Android 硬件解码器 100% 兼容）。
  • a=setup:actpass：协商随后 DTLS 加密握手谁当客户端（active）、谁当服务端（passive）。
  • a=rtcp-fb:...：协商双方开启哪些抗弱网扩展能力（nack 重传、pli 关键帧恢复、transport-cc 带宽探测）。
01.2 · 网络穿透核心：四类 NAT 模型对比，图解对称型 NAT 端口重分配导致 STUN 失效的根因

01.2 四类 NAT 模型与对称型 NAT 穿透受阻推导

由于全球 IPv4 公网地址枯竭，家庭光猫与手机 4G/5G 基站都通过 NAT（Network Address Translation）让成百上千台内网设备共享少量公网 IP。根据路由器「向外发包时如何分配外部端口」与「向内收包时拦不拦截陌生外部主机」两个维度，经典 RFC 3489 将 NAT 划分为四类：

NAT 类型 出站端口映射规则 入站数据包过滤规则 STUN 打洞可否直连
1. 全锥形 NAT
(Full Cone)		 同一内网 IP:Port 访问任何外部目标均复用同一个公网端口 不限制来源，任何外部主机发往该公网端口的包均放行入内网 极易穿透（一查即通）
2. 地址受限锥形
(Address-Restricted)		 访问任何外部目标均复用同一个公网端口 仅放行内网主机曾经主动发过包的外部公网 IP（不限对方端口） 可穿透（双方同时互发探测包双向开洞）
3. 端口受限锥形
(Port-Restricted)		 访问任何外部目标均复用同一个公网端口 仅放行内网主机曾经主动发过包的精确外部 IP + Port 可穿透（若对端也是锥形 NAT，双方互知端口对发即通）
4. 对称型 NAT
(Symmetric NAT)		 按目标 IP:Port 重新分配新公网端口（发给不同目标，出口端口完全不同） 严格校验精确外部 IP + Port 五元组，陌生入站包一律丢弃 对端为对称或端口受限锥形时 STUN 穿透失败，必须走 TURN 中继

ICE（Interactive Connectivity Establishment，RFC 8445）把上述所有路径统一收拢管理：按类型权重公式 priority = 224 × type_pref + 28 × local_pref + (256 - component_id) 给候选地址打分——局域网直连 host (type_pref=126) 分最高，公网反射 srflx (100) 次之，消耗服务器带宽的 relay (0) 排最后兜底；并在极端封禁 UDP 的酒店/校园网下支持通过 TURNS（TURN over TLS 443）伪装成普通 HTTPS 流量完成穿透。
