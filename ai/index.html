03 Interactions API 四大核心升级：thinking_level、1M 超长解码与托管沙箱 API DEEP DIVE

🎛️ 1. 用 thinking_level 精准控制推理深度（默认 medium）

档位参数 推理特征与开销 官方推荐最佳适用场景
"high" 最大化思考深度与探索轮次 跨文件隐蔽 Bug 根因排查、安全漏洞修补、形式化数学证明、前期顶层架构设计
"medium" 默认 速度、成本与首轮准确率最优解 日常交互式编程、全栈应用开发、Agent 工具调用主循环（推荐默认档）
"low" 最小化延迟与 Token 消耗 高速意图分类、路由分发（Routing）、结构化定向提取

📏 2. 突破 64K 限制：1M 统一窗口超长解码 (Long Decode)

• 1M 统一池：输入 + 思考 + 输出共享 1M Token（输出预算含思考 Token）。
• 默认同步上限：同步流式/非流式默认上限仍为 65,536。
• 开启超长解码：在 Interactions API 中设 background=True 并调高 max_output_tokens（如 262144），单次即可生成超 64K 的完整多文件重构 Diff 或长篇数学证明；如需精细容错也可使用客户端手动续写。

🛡️ 3. Managed Agents：一行调起远程 Antigravity 沙箱

• 免搭本地工具链：传入 agent="antigravity-preview-09-2026" 与 environment="remote"。
• 自带云端执行环境：Carbon 在远程托管沙箱中自动联网搜索、读写代码、运行验证脚本与调用 MCP 工具（官方展示了自动联网考证族谱并生成交互式 3D 地球的 Family Historian）。

04 五大工程实践秘籍 + 官方原版 Prompt 模板 + Python / TS 完整代码 BATTLE-TESTED WORKFLOWS

🎯 Tip 1：长跑前先对齐意图

Scoping

Carbon 能独立连续跑很久，跑偏代价高：先让它主动反问边界条件与验收标准、一起脑暴架构、做 Pre-flight 工具检查，确认后再放手让它自主跑到底（仅在不可逆操作前暂停确认）。

🔬 Tip 2：给真实验证信号与基线

黄金法则

别让模型盲猜修好没！接入测试集、日志或浏览器截图。若无自动化检查，先让 Carbon 写 Headless Chrome 脚本跑出初始 Baseline 分数，按根因分簇修复并循环回归直到 0 违规。

🎨 Tip 3：多模态参考 + 前端 Skill

UI 审美

喂参考图、视频、PDF 或先提炼 DESIGN.md。搭配官方 gemini-frontend-design 技能与 gemini-api-cli（终端直接生成媒体落盘，避免 Base64 撑爆上下文）。

🐝 Tip 4：担任多 Agent 军团总指挥 (/swarm)

Multi-Agent

在 Antigravity /swarm 中，将 Carbon（medium/high）钉在总控架构师与终审员位置；把叶子模块迁移、写单测分包给高速 Gemini 3.8 Flash；图像/视频/音频调用专精模型生成。

📓 Tip 5：任务后复盘反思与可视化解说

复利增长

跑完复杂任务后让 Carbon 回看会话：① 把仓库暗坑（特殊测试 Flag、Lint 规则）写进 AGENTS.md；② 把多步排障流程打包成 Reusable Skill；③ 改动几十个文件不想生啃 Diff 时，让它生成交互式架构图或数据流动画！

1. 官方原版高价值 Prompt 模板（一键复制）

🔬 Prompt A：无自动化测试时先写脚本立 Baseline (Tip 2)
We want to fix accessibility and layout issues across our web app, but we don't have automated checks yet. First, write a headless Chrome script that crawls every route in src/routes/, inspects the live DOM and accessibility tree, and logs all violations to record our baseline score. Group the failing checks into shared root causes across our shared components, then fix them one cluster at a time. Re-run your script after each change to verify that each single fix resolves the entire cluster with zero regressions. Keep going until all routes pass with zero violations.
📓 Prompt B：任务后复盘并更新 AGENTS.md 与 Skill (Tip 5)
Investigate our current session to see where things stalled or required extra steps, and analyze why. Propose updates to our AGENTS.md or custom skills so we can improve our flow and take a more direct path next time.

💻 gemini_4_carbon_sdk.py / .ts (google-genai SDK) 
# ==================== 1. Python: 后台超长解码 (Long Decode > 64K) ====================
import time
from google import genai

client = genai.Client()

interaction = client.interactions.create(
    model="gemini-4-carbon",
    input="Write a complete, rigorous proof of the prime number theorem.",
    background=True,  # 突破 65,536 默认上限必须开启 background=True
    generation_config={
        "max_output_tokens": 262144,
        "thinking_level": "high",  # "low" | "medium" (default) | "high"
    },
)

while interaction.status in ("in_progress", "queued"):
    time.sleep(5)
    interaction = client.interactions.get(id=interaction.id)

# 每个续写分段会追加一个 model_output step，需遍历拼接全文
text = "".join(
    content.text
    for step in interaction.steps if step.type == "model_output"
    for content in step.content if content.type == "text"
)
print(text)

# ==================== 2. Python: Managed Agents (Antigravity 托管沙箱) ====================
audit_run = client.interactions.create(
    agent="antigravity-preview-09-2026",
    agent_config={"type": "antigravity", "model": "gemini-4-carbon"},
    input=(
        "Audit https://web.dev for performance, Core Web Vitals, and SEO. "
        "Query Google's PageSpeed Insights API for both Mobile and Desktop. "
        "Format the output as a side-by-side scorecard table with prioritized fixes."
    ),
    environment="remote",
)
print(audit_run.output_text)

// ==================== 3. TypeScript: Interactions API 标准调用 ====================
import { GoogleGenAI } from "@google/genai";
const ai = new GoogleGenAI({});

const res = await ai.interactions.create({
  model: "gemini-4-carbon",
  input: "Build a single-file HTML drum machine and synth using Web Audio API...",
  generation_config: { thinking_level: "medium" },
});
console.log(res.output_text);
05 迁移与生产落地的 6 大避坑指南 (Migration & Production Mitigations) BREAKING CHANGES & PITFALLS
PITFALL 01 · 参数废弃

还在传 thinking_budget

从 Gemini 3 迁移时，旧版按 Token 数量传参的 thinking_budget 已不再适用。

💊 解药：全面替换为 thinking_level（low/medium/high）。
PITFALL 02 · 采样失效

习惯性传 temperature / top_p

在 gemini-4-carbon 中，自定义 temperature、top_p、top_k 会被直接忽略。

💊 解药：从请求配置中彻底删除这三个采样参数。
PITFALL 03 · 缓存冗余

手动维护显式 cached_content

以前为了省钱需要专门调接口创建并传递显式缓存 ID，增加了状态管理复杂度。

💊 解药：移除显式缓存代码！默认隐式缓存，≥4,096 Token 命中部分享 95% 折扣。
PITFALL 04 · 超时截断

64K 同步截断与 HTTP 超时

深度推理可能思考数分钟，且默认同步最大输出仍为 65,536，长任务容易超时或截断。

💊 解药：开启 background=True 或将 HTTP Timeout 调至 15~20 分钟。
PITFALL 05 · 杀鸡牛刀

简单任务全用 Carbon 导致变慢

Carbon 倾向于深度探索，拿它跑简单 CRUD 或叶子模块单测会消耗不必要的思考时间。

💊 解药：日常开发用 Argon，并行高频切片派发给 3.8 Flash。
PITFALL 06 · 盲跑长任务

不给验证脚本就让模型盲跑

没有测试集或浏览器 DOM 检查信号，模型在几十个文件的连续修改中只能靠猜。

💊 解药：先让 Carbon 写自动化基准脚本跑出 Baseline 分数再动手。
