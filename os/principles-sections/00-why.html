🧱 00.1 操作系统核心概念地基：后面每一章都会用到的 4 组基础模型

操作系统的各个模块是互相咬合的：第 01 章讲系统调用和切换时，就会用到第 02 章的进程/线程/PCB/内核栈、第 03 章的虚拟内存/页表/TLB、以及第 07 章的Page Cache 与 fd。我们先在这里把这几组基础模型立住：

① 📦 程序 → 进程（资源盒子）→ 线程（执行流）→ PCB
• 程序 vs 进程：躺在硬盘上的二进制文件叫程序；加载到内存条里运行起来的实例叫进程。
• 进程 vs 线程：进程是“资源分配盒子”（拥有独立的虚拟内存和打开文件表）；线程是盒子里真正上 CPU 跑代码的“执行流”（共享进程内存，独享自己的栈与寄存器）。
• PCB（Linux 里叫 struct task_struct）：内核在内存条里为每个进程/线程建立的「档案结构体」，记录它的 PID、状态、寄存器保存区、页表指针（mm_struct）和打开文件表（files_struct）。
② 🗺️ 虚拟地址空间的「上下分半」与「用户栈 / 内核栈」
• 低地址用户区（各进程私有）+ 高地址内核区（所有进程共享）：每个进程的虚拟地址空间分成上下两半——下半部分是用户空间（放进程自己的代码、全局变量、堆、栈，进程间完全隔离）；上半部分是内核空间（所有进程的页表高地址区都映射到同一个操作系统内核，普通用户态 Ring 3 禁止访问）。
• 用户栈 vs 内核栈：平时跑用户代码用用户栈；一旦通过 syscall 进入内核态（Ring 0），CPU 会立刻把栈指针切换到该线程在内核区的专属内核栈（8KB/16KB）。
③ 🧭 页表（Page Table）、CR3 寄存器与文件描述符 fd
• 页表与 CR3：把虚拟内存和物理内存条按 4 KB（一页）切块。每个进程有一张页表（存放在内存条里，记录 虚拟页号 ➔ 物理页号 + 权限）；CPU 里的 CR3 寄存器存着当前进程页表的物理起始地址。
• 文件描述符 fd：进程打开文件或 Socket，内核在内部登记状态后只返回一个非负整数编号 fd（0, 1, 2, 3...）。
⚡ ④ 最容易搞混的「三大缓存」一次性分清：TLB 快表 vs CPU Cache (L1/L2/L3) vs 内核 Page Cache
缓存名称 物理位置在哪？ 由谁管理？ 里面到底缓存什么内容？ 为了解决什么慢的问题？
① TLB 快表
(地址翻译缓存)		 CPU 芯片内部
(MMU 单元里)		 CPU 硬件自动查，
换 CR3 时刷新		 最近用过的「虚拟页号 ➔ 物理页帧号」地址映射关系 因为页表本身放在内存条里，每次去内存条查 4 级页表太慢，用 TLB 省去查表访存。
② CPU Cache
(L1 / L2 / L3)		 CPU 芯片内部 CPU 硬件全自动
(按 64B 缓存行)		 内存条里最近读写过的真实变量数值与机器指令 因为内存条（~100ns）比 CPU（~0.3ns）慢上百倍，把热点变量缓存在 CPU 内部加速计算。
③ Page Cache
(内核文件页缓存)		 物理内存条 (DRAM)
(free -h 的 buff/cache)		 操作系统内核软件
(按 4KB 页管理)		 硬盘文件的数据块副本（读文件先读它，写文件先改它变脏页再异步刷盘） 因为硬盘（微秒/毫秒级）比内存条（纳秒级）慢上千倍，内核拿空闲内存条给硬盘做缓存。

🗺️ 00.2 计算机硬件底座 × 操作系统内核 全局架构总图

顺着图中编号 ① ➔ ② ➔ ③ ➔ ④，一眼看清：进程眼里的虚拟空间（左上）是怎么通过 CPU 内部的 MMU/TLB/Cache（右上），映射到 物理内存条 DRAM（中间），再通过 DMA 与硬盘/网卡（底部）完成数据交换的：

① 软件视角：进程的「虚拟地址空间」 OS 给每个进程画的独立视野
🔼 高地址半区：内核空间（Ring 0 · 所有进程共享同一份内核映射）
• 用户态代码不能直接访问，只能通过 syscall / 异常 / 中断 陷入进入
• 切换到当前线程专属的 内核栈（8KB/16KB） 执行内核代码
🔽 低地址半区：用户空间（Ring 3 · 每个进程各自独立隔离）
各线程独享：
• 用户栈 Stack（局部变量）
同进程多线程共享：
• 堆 Heap · 全局数据 · 代码段 Text · 打开的 fd
② 硬件核心：CPU 芯片内部（0.3 ~ 15 ns） 断电即空 · 极快
⚙️ 控制与运算核心
• CU + RIP：取指、译码
• ALU：算术逻辑运算
• 通用寄存器（RAX/RSP...）
• 特权级状态位 CPL (Ring 0/3)
⚡ CPU Cache (L1/L2/L3)
• 按 64B 缓存行 缓存内存条里的热点变量与指令
• 弥补 CPU(0.3ns) 与内存条(100ns) 的百倍速度差
🧭 地址翻译硬件：CR3 寄存器 + MMU + TLB 快表
• CR3：存当前进程页表在【内存条】里的起始物理地址（切进程 = 改 CR3）
• TLB 快表：在 CPU 内缓存最近查过的「虚拟页 ➔ 物理页」映射；未命中时由 MMU 顺着 CR3 去下面内存条查页表
▲▼ 内存总线（~80 - 100 ns）：MMU 去内存查页表 · CPU Cache 按 64B 读写内存变量 ▲▼
③ 物理内存条 DRAM（16GB ~ 128GB · 所有正在运行的程序和内核都住在这里） 按 4KB 物理页帧划分 · 断电即空
📦 A. 各进程的用户物理页
• 存放进程 A、进程 B 真正加载进内存的代码机器码、全局变量、堆对象、用户栈数据。
• 进程 A 和 B 的页表指向不同的物理页，实现硬件级隔离（共享内存 IPC 则指向同一物理页）。
🗂️ B. 内核管理数据（页表 / PCB / 栈）
• 四级页表（Page Tables）：页表本身住在内存条里！由 CR3 指向它的根。
• PCB (task_struct)：所有进程/线程的档案与调度红黑树。
• 内核栈 & 文件三张表（struct file / inode）。
🚀 C. 内核 Page Cache 与 Socket 缓冲区
• Page Cache（页缓存）：内核用空闲内存条缓存硬盘文件的 4KB 数据块（read 优先读它，write 先改它变脏页再异步落盘）。
• Socket 缓冲区（sk_buff）：暂存网卡收发的网络包。
▲▼ DMA 硬件直接搬运（无需 CPU 亲自逐字节拷贝）：搬完后向 CPU 发送「硬中断」通知内核 ▲▼
④-A 💽 外存硬盘（NVMe SSD `~50μs` / 机械 HDD `~8ms` · 永久保存）
• 存什么：未运行的程序文件（./a.out）、目录项与磁盘 inode、MySQL 表文件、日志、Swap 交换分区。
• 怎么跟内存条联动：程序启动或触发缺页异常时，DMA 把磁盘块读入内存条的 Page Cache / 物理页；调 fsync() 或后台回写时，把内存脏页刷回硬盘。
④-B 🌐 网卡（NIC · 外部网络通信接口）
• 怎么收包：网线收到数据包 ──▶ 网卡 DMA 直接把包写进内存条的内核 RingBuffer ──▶ 触发硬中断（上半部）+ 软中断（下半部） ──▶ 唤醒阻塞在 epoll_wait 上的进程。
• 怎么零拷贝发文件：sendfile 直接让网卡 DMA 从内存条的 Page Cache 把文件数据发走，全程不经过用户态。
