04任务怎样合作 · 先分清传数据和发通知先理解过程

📨 04.1 一个进程统计，另一个显示，结果怎么送过去？

假设把工具拆成两个进程：一个读取文字并计算，另一个显示结果。各自的私有内存通常不能让对方直接访问，因此需要一种约定好的通道。这就是进程间通信：让隔离的运行实例交换信息。

一种简单做法是让统计进程把“120个字”写入通道，显示进程再从另一端读出。内核提供和管理这类通道，并处理写满、读空时怎么办。

🚰 04.2 需要传什么，就选择什么协作方式

延续上一章的例子：进程甲（负责统计字数）想把算出来的结果交给进程乙（负责汇总显示）。既然两个进程各自的私有内存是隔离的，操作系统提供了 3 种不同形态的数据交接方式：

🗺️ 图解三种跨进程传数据方式：水管字节流 vs 独立包裹队列 vs 共享同一块物理内存
① 管道 (Pipe) · 像连在一起的水流
进程甲 ──①写──▶ [内核水管: "120\n85\n"] ──②读──▶ 进程乙
• 特点：内核在内存里开一段环形缓冲区，数据像水一样从一端流向另一端，读走就消失。
• 局限：水流里没有自带分界线（必须自己加换行符区分），且数据要进出内核搬运 2 次。
② 消息队列 · 像贴了标签的快递柜
进程甲 ──①投递──▶ [📦包1: 120] [📦包2: 85] ──②取件──▶ 进程乙
• 特点：不再是混在一起的字节流，而是把数据打包成一条条有独立边界、带类型编号的消息存进内核链表。
• 局限：接收方可以按包裹类型挑着取，但每次收发依然要经内核搬运 2 次，不适合传超大文件。
③ 共享内存 · 两本通讯录指同一个格子
甲的地址 ──▶ 【内存条 #88号物理格】 ◀── 乙的地址
• 特点：请内核把甲和乙的页表（通讯录）直接指向内存条上的同一块物理格子！甲往里写完，乙低头直接就能读，全程 0 次内核中转搬运，速度最快。
• 代价：如果甲还没写完乙就来读（或两人同时改），数据就会乱，必须配合下一章的锁或信号量。

所以不用死背“哪种最快”，选型时先问三个问题：数据量大不大？需不需要按条区分边界？如果用共享内存，双方商量好读写顺序了吗？

🔔 04.3 紧急通知与跨机器通信：信号（Signal）与套接字（Socket）

04.2 的管道、消息队列和共享内存都有两个共同前提：① 接收方需要主动去读取；② 双方运行在同一台机器上，共用同一根内存条。而在实际运行中，还会遇到另外两类协作需求：

🚨 场景 ①：对方正埋头猛算，根本没空看管道，怎么立刻叫停它？ ──▶ 靠「信号 (Signal)」
• 为什么前三种不管用：假设进程甲正在埋头统计一个 10GB 的大文件，代码一直卡在循环里算字数，根本没去读管道或看消息队列。这时你在键盘按了 Ctrl + C 想让它停下来，往管道里塞字它是看不见的。
• 怎么解决：需要一种“不经过管道、由内核直接拍肩膀打断它”的异步事件通知——这就是信号（Signal）。它不传大段文章，只传一个编号（例如 2号 SIGINT = 你按了 Ctrl+C、15号 SIGTERM = 请保存好进度优雅退出、9号 SIGKILL = 内核直接强制终结）。
🌐 场景 ②：统计进程在远端服务器，显示界面在你的笔记本上，怎么传？ ──▶ 靠「套接字 (Socket)」
• 为什么前三种不管用：管道、消息队列和共享内存，全都是靠“同一台电脑上的同一根内存条”中转或共享的；隔着网线的两台电脑根本没有共用内存条。
• 怎么解决：操作系统提供了统一的网络通信插口叫套接字（Socket）。进程甲把“120个字”写进自己的 Socket，由内核网络协议栈和网卡通过网线发给另一台电脑的 Socket，从而把通信范围从“本机”扩展到了“全世界”（顺便也支持本机进程之间高速通信）。
🧩 想一想：两个进程共享了同一块内存，是否就能随便同时修改？

不能。共享只解决“能访问同一份数据”，还要解决修改顺序和相互配合的问题，否则同样可能覆盖结果。
