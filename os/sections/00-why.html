00先补四个基础 · 电脑硬件、指令与变量、地址与等待先理解过程
不用先背英文名词。这一篇先讲一个程序怎样在真实电脑硬件上运行起来。例子始终是：读一份文字文件，统计字数，再输出结果。每章先弄懂一件事，最后能解释这个小程序就够了。

🧰 00.1 拆开电脑机箱：硬盘、内存条、CPU 与网卡各自负责什么？

在看操作系统之前，先在脑子里建立真实电脑的硬件画面。不管你是用笔记本还是云服务器，拆开机箱，程序跑起来全靠下面这 4 样硬件配合：

① 💽 硬盘（机械 HDD / 固态 SSD）
定位：永久大仓库（断电不丢 · 便宜 · 慢）
你写的程序文件和要统计的文字文件，平时全都保存在硬盘上。机械硬盘靠磁头移动寻道（约 5~10 毫秒，极慢）；固态硬盘用闪存芯片（约 20~100 微秒，快上百倍）。
② 🧠 内存条（DRAM 物理内存）
定位：临时工作台（断电即空 · 较贵 · 快）
硬盘对处理器来说太慢了。所以中间加了一层快上千倍的内存条（约 80~100 纳秒）。程序运行前，必须先把硬盘里的代码和文字加载到内存条里；但内存条一断电就会清空。
③ ⚙️ 处理器（CPU + 内部高速缓存）
定位：计算核心（断电即空 · 极贵 · 极快）
负责从内存条取出指令和数据做计算（一次仅 0.3 纳秒）。因为内存条（100ns）还是比 CPU 慢上百倍，CPU 芯片内部又造了极快的寄存器与 L1/L2/L3 高速缓存（1~15ns）存放手头刚用到的变量。
④ 🌐 网卡（NIC）与 DMA 搬运工
定位：网络收发口 + 后台搬运芯片
网卡负责收发网络数据。为了不让宝贵的 CPU 亲自去慢速硬盘或网卡一个字节一个字节搬数据，主板上配有 DMA 硬件：它在后台自动把硬盘/网卡的数据拷进内存条，搬完发个通知（中断）告诉 CPU。

🔬 好奇追问：把 CPU 芯片拆开，里面到底装了哪 4 样部件？

很多人容易把“CPU 里面的东西”和“内存条里的东西”搞混。其实 CPU 芯片内部主要装了这 4 个部件：

  1. 控制器 (CU) + 指令指针 (RIP/PC)：记住“下一条指令在内存的哪个地址”，负责把指令取进来解码。
  2. 运算器 (ALU) + 通用寄存器：负责加减乘除和逻辑判断。注意：运算器只能对 CPU 内部寄存器里的数字做运算，不能直接算内存条里的数字。
  3. 三级高速缓存 (CPU Cache L1/L2/L3)：为了弥补 CPU（0.3ns）与内存条（100ns）之间的百倍速度差，读内存时顺手把相邻 64 字节的数据块搬进 CPU 内部缓存起来。
  4. 地址翻译器 (MMU + TLB)：把程序里的虚拟地址自动翻译成内存条上的真实物理位置，并把最近查过的映射缓存在 CPU 内部的 TLB 快表里。

🧾 00.2 代码、指令和变量是什么关系？

流程示意 · 用中文描述，不需要执行
打开文字文件
读出一段文字
数一数字数，把结果记下来
输出结果

人写的代码表达这些步骤。像 C 语言程序，会先由编译工具把代码转换成机器能执行的指令；其他语言也可能通过解释器或运行时执行。处理器最终执行的是机器指令。

统计途中要记住“目前数到多少”，就需要存数据。代码里给数据取的名字叫变量。例如“字数”这个变量保存整数 120；它的名字、它的值，以及它存放的位置，是三个不同概念。

📍 00.3 地址和指针：名字、内容、位置要分开

想象超市门口一排带门牌号的储物格：格子里放的是内容（值），格子门上的编号是位置（地址）。内存条也是这样按字节编号的。变量既可以直接保存一个数字，也可以专门保存另一个格子的编号——这种专门存地址、用来顺藤摸瓜找到另一份数据的变量，就叫「指针」：

🗄️ 一张储物柜图分清：「变量名 · 地址 · 里面的值 · 指针」
📍 地址：#101号格 标签名：字数 (count)
120
• 普通变量：盒子里直接装着数字 120（这是它的值），盒子在内存里的门牌号是 #101（这是它的地址）。
📍 地址：#102号格 标签名：文字指针 (p)
📄 纸条：去 #500号格 找 ──▶
• 指针变量：它自己住在 #102 格，但它里面不装长篇文章，只装一张写着 #500 的地址纸条！
📍 地址：#500号大格 （指针 p 指向的目标）
"hello linux..."
• 指针指向的内容：顺着 #102 格里的纸条找到 #500 格，里面放的才是真正读出来的文字内容。
先记住这个区别就够了：“字数是 120”说的是格子里装的值；“去 #500 号格子找”说的是地址；而专门用来装这张地址纸条的小盒子（#102）就是指针。

⏳ 00.4 执行一条命令，为什么有时要等？

处理器执行计算，硬盘和网卡完成读写。程序请求的数据不一定已经准备好。等待数据的时间，可以远长于处理器做一次简单计算的时间。

操作系统可以记下当前任务的进度，让它等待，再安排另一个任务使用处理器。数据准备好后，原任务重新获得继续执行的机会。因此，窗口没立刻给结果，并不代表处理器一直在替它计算。

操作系统就是协调这些资源的系统软件：它安排任务、管理内存、提供文件和设备的使用方式。后面每一个机制，都要回到“它解决哪个具体问题”来理解。
