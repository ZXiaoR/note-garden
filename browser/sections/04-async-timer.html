⏱️ 04.1 · 异步调度入门：主线程单线程执行模型与 setTimeout / Promise 的执行次序

⏱️ 04.1 主线程异步调度：setTimeout 与 Promise 的日常配合

在浏览器的渲染进程中，负责执行页面 JavaScript 的主线程同时还要负责处理用户点击输入和更新屏幕画面。如果一段脚本在主线程里执行一个长达 3 秒的死循环，这 3 秒内整个网页将无法点击、无法滚动，动画也会完全冻结。
因此，对于延时操作、网络请求等需要等待的任务，浏览器提供了非阻塞的异步回调机制：先把任务登记给浏览器，主线程继续向下执行；等条件满足且当前同步代码跑完后，再回来执行登记好的回调函数。

⚡ async_order.js · 同步代码、Promise 微任务与 setTimeout 定时器的执行顺序 
console.log('1. 同步脚本开始');

// 登记一个 0 毫秒后执行的定时器任务（进入任务队列等待下一轮调度）
setTimeout(() => {
  console.log('4. setTimeout 定时器回调执行');
}, 0);

// 登记一个已完成的 Promise 回调（进入微任务队列，本轮同步代码一结束立刻清空）
Promise.resolve().then(() => {
  console.log('3. Promise.then 微任务回调执行');
});

console.log('2. 同步脚本结束');
// 控制台实际输出顺序：1 ➔ 2 ➔ 3 ➔ 4
📖 为什么 Promise.then 比 setTimeout(..., 0) 先执行？
  • 第一步（跑完当前同步脚本）：从上到下依次打印 1、向浏览器登记定时器、向微任务队列放入 then 回调、最后打印 2。
  • 第二步（立即清空微任务 Microtasks）：每当一段主线程脚本执行结束，浏览器在去拿下一个普通任务之前，会先把当前积累的所有 Promise.then / catch / finally（及 await 后面的代码）全部执行完，因此输出 3。
  • 第三步（执行下一轮普通任务 Task）：微任务清空后，事件循环才从任务队列中取出到期的 setTimeout 回调执行，最后输出 4。
🎞️ 04.2 · 画面更新与多线程：使用 requestAnimationFrame 驱动动画与使用 Web Worker 拆分重计算

🎞️ 04.2 requestAnimationFrame 动画对齐与 Web Worker 后台线程

在日常开发中，除了 setTimeout 和 Promise，还有两类非常实用的浏览器调度工具：

  • 视觉动画更新用 requestAnimationFrame(callback)：普通 setTimeout(fn, 16) 无法与屏幕的硬件刷新时刻对齐，容易出现两帧之间执行两次或漏帧卡顿；而 requestAnimationFrame 会在浏览器准备绘制下一帧画面之前精确调用一次，且当用户切走标签页时会自动暂停以节省电量。
  • 纯 CPU 密集型计算用 Web Worker：如果需要对几万条表格数据做前端排序、解析超大 JSON 或计算文件哈希，直接放在主线程会卡死页面；启动一个独立的 Worker 线程可以在后台并行计算，算完再通过 postMessage 把结果发回主线程。
🎞️ smooth_progress.js · 用 requestAnimationFrame 实现平滑进度条动画 
const barEl = document.getElementById('progress-bar');
let progress = 0;

function stepFrame() {
  progress += 2; // 每一帧前进 2%
  // 使用 transform 缩放替代直接改 width，渲染开销更低
  barEl.style.transform = `scaleX(${progress / 100})`;

  if (progress < 100) {
    // 还没到 100% 时，继续预约下一帧渲染前执行 stepFrame
    window.requestAnimationFrame(stepFrame);
  }
}

// 启动第一帧动画
window.requestAnimationFrame(stepFrame);
🧵 worker_demo.js · 主线程将耗时计算交给 Web Worker 后台线程 
// ===== 主线程代码 (main.js) =====
const worker = new Worker('./heavy-task.js');

// 1. 向 Worker 线程发送需要处理的数据
worker.postMessage({ count: 50000000 });

// 2. 监听 Worker 算完后发回的消息（期间主线程依然流畅响应点击）
worker.addEventListener('message', (event) => {
  console.log('收到后台计算结果：', event.data.total);
});

// ===== Worker 线程代码 (heavy-task.js) =====
// 注意：Worker 处于独立线程，不能访问 document / window 等 DOM 对象
self.addEventListener('message', (event) => {
  let total = 0;
  for (let i = 0; i < event.data.count; i++) total += i;
  self.postMessage({ total }); // 算完发回主线程
});
