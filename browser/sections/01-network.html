01.1 标准 URL 的六个组成部分与解析方法

浏览器访问任何网络资源都从解析统一资源定位符（URL）开始。以访问地址 https://store.example.com:8443/products/detail?id=42&from=nav#reviews 为例，一个完整的 URL 由六个部分按固定语法拼接而成：

在日常开发中，如果需要在脚本里安全地读取或拼接 URL 参数，推荐使用浏览器内置的 URL 与 URLSearchParams 构造函数，而不必手写复杂的字符串分割：

url_parse.js · 使用内置 URL 与 URLSearchParams 解析和构造网址参数 
// 1. 解析任意 URL 字符串（若要解析当前页面地址，可传入 window.location.href）
const targetUrl = new URL('https://store.example.com:8443/products/detail?id=42&from=nav#reviews');

console.log(targetUrl.origin);   // "https://store.example.com:8443"（协议 + 主机 + 端口）
console.log(targetUrl.pathname); // "/products/detail"
console.log(targetUrl.hash);     // "#reviews"（仅在浏览器端生效，不会随 HTTP 请求发往服务端）

// 2. 通过 searchParams 安全读取、修改或新增查询参数（自动处理中文 URL 编码）
console.log(targetUrl.searchParams.get('id')); // "42"
targetUrl.searchParams.set('keyword', '机械键盘');
console.log(targetUrl.toString());
// 输出："https://store.example.com:8443/products/detail?id=42&from=nav&keyword=%E6%9C%BA%E6%A2%B0%E9%94%AE%E7%9B%98#reviews"
01.2 · 通信格式：HTTP 请求方法、响应状态码分类与关键首部字段

01.2 HTTP 请求方法、状态码分类与关键首部字段

解析出目标主机和路径后，浏览器会向服务器发起 HTTP（或加密的 HTTPS）请求。一次完整的 HTTP 通信包含浏览器发出的请求报文（Request）和服务器返回的响应报文（Response）：

📤 HTTP 请求报文结构（Request） 
# ① 请求行：请求方法 + 路径与查询参数 + 协议版本
GET /products/detail?id=42 HTTP/1.1
# ② 请求头（Headers）：描述客户端环境与内容格式
Host: store.example.com:8443
Accept: application/json
Content-Type: application/json
# ③ 空行后可跟请求体（Body，GET 请求通常无请求体）
HTTP 响应报文结构（Response） 
# ① 状态行：协议版本 + 三位数字状态码 + 状态短语
HTTP/1.1 200 OK
# ② 响应头（Headers）：告知浏览器响应类型与缓存规则
Content-Type: application/json; charset=utf-8
Cache-Control: max-age=60
# ③ 空行后为响应体（Body）：实际返回的 HTML 或 JSON 数据
{"id": 42, "name": "无线机械键盘", "stock": 18}
状态码区间 代表性状态码 含义与日常排障判断
2xx 成功 200 OK · 201 Created · 204 No Content 服务器成功处理了请求。200 表示正常返回响应体；204 常用于删除或更新成功且无需返回正文的接口。
3xx 重定向 / 缓存 301 永久重定向 · 302 临时重定向 · 304 Not Modified 301/302 会让浏览器自动跳转到响应头 Location 指向的新网址；304 表示本地缓存经服务器验证仍然有效，无需重新下载响应体。
4xx 客户端错误 400 参数错误 · 401 未登录 · 403 无权限 · 404 未找到 先检查前端传参、请求路径（URL 拼写）以及是否漏传了登录身份凭证（如 Authorization 请求头或 Cookie）。
5xx 服务端错误 500 内部错误 · 502 网关错误 · 504 网关超时 请求格式正确，但后端服务抛出未捕获异常、进程未启动或下游数据库查询超时，需结合后端服务日志排查。
01.3 · 接口调用：使用浏览器原生 fetch 发送 JSON 请求与处理非 2xx 状态

01.3 使用原生 fetch 发送请求与异常处理

在网页脚本中向后端请求数据，现代浏览器统一提供了基于 Promise 的原生 fetch(url, options) 接口。使用 fetch 时有两个最核心的细节需要注意：

  1. 读取响应体是第二步异步操作：await fetch(url) 在收到服务器响应头时就会完成，此时响应体可能还在传输中；需要再调用一次 await response.json()（或 response.text()）才能拿到解析后的数据。
  2. 404 / 500 状态码不会自动触发 catch：只有当网络断开或域名无法解析时，fetch 才会直接抛出异常；对于服务器返回的 404 或 500，必须主动检查 response.ok（状态码在 200~299 之间时为 true）。
fetch_example.js · 发送 POST JSON 请求并包含超时控制与状态码检查 
// 定义一个异步函数（async 关键字允许在函数内部使用 await 等待异步结果）
async function createOrder(productId, count) {
  try {
    const response = await fetch('/api/orders', {
      method: 'POST', // 指定请求方法（不写时默认为 GET）
      headers: {
        'Content-Type': 'application/json' // 告知服务器请求体是 JSON 格式字符串
      },
      body: JSON.stringify({ productId, count }), // 将 JS 对象序列化为 JSON 字符串
      signal: AbortSignal.timeout(5000) // 超过 5000 毫秒（5 秒）自动取消请求
    });

    // 关键检查：HTTP 4xx / 5xx 不会自动进 catch，需判断 response.ok（即 status 为 200~299）
    if (!response.ok) {
      throw new Error(`请求失败，HTTP 状态码：${response.status}`);
    }

    // 等待完整响应体接收完毕并解析为 JavaScript 对象
    const data = await response.json();
    return data;
  } catch (err) {
    console.error('下单请求出错：', err.message);
    return null;
  }
}
