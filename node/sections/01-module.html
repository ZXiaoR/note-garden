📦 01.1 · 模块化语法：CommonJS（require / module.exports）与 ES Module（import / export）日常写法

📦 01.1 模块化日常写法：CommonJS 与 ES Module 对照

在实际项目中，我们不会把所有代码都塞进一个文件，而是按功能拆分成多个模块文件。Node.js 支持两套模块化语法：

  • CommonJS（简称 CJS，传统默认规范）：使用 module.exports 导出、require() 同步导入；在不配置 package.json 的情况下，.js 和 .cjs 文件默认使用此规范。
  • ES Module（简称 ESM，现代官方标准）：使用 export 导出、import 导入，与前端浏览器及 TypeScript 语法完全一致；只需在 package.json 中添加一行 "type": "module"（或使用 .mjs 扩展名）即可启用。
📦 CommonJS 写法 · module.exports 与 require() 
// --- math.cjs（导出模块）---
function add(a, b) {
  return a + b;
}
const PI = 3.14159;

// 将需要对外公开的函数和常量放到 module.exports 对象上
module.exports = { add, PI };

// --- app.cjs（导入模块）---
// 1. 导入内置模块：带上 node: 前缀更清晰
const path = require('node:path');

// 2. 导入本地文件：必须以 ./ 或 ../ 开头
const { add, PI } = require('./math.cjs');
console.log(add(2, 3), PI); // 输出: 5 3.14159
⚡ ES Module 写法 · export 与 import（现代项目推荐） 
// --- math.js（在声明前直接加 export 即可命名导出）---
export function add(a, b) {
  return a + b;
}
export const PI = 3.14159;

// 也可以设置一个默认导出（每个文件最多一个 export default）
export default function multiply(a, b) {
  return a * b;
}

// --- app.js（在 ES Module 中导入本地文件须写完整 .js 后缀）---
import multiply, { add, PI } from './math.js';
console.log(add(2, 3), multiply(4, 5)); // 输出: 5 20
导入路径写法分类 代码示例 Node.js 的查找规则说明
1. 内置核心模块 import fs from 'node:fs/promises' 以 node: 开头，直接加载 Node.js 编译在可执行文件内的系统模块，优先级最高，不会与同名第三方包冲突。
2. 本地相对路径文件 import { add } from './utils/math.js' 以 ./ 或 ../ 开头，按相对于当前文件的路径查找；在 ES Module 模式下要求显式写出文件扩展名（如 .js）。
3. 第三方依赖包 import express from 'express' 不带路径前缀的裸包名，Node.js 会自动在当前目录及上级目录的 node_modules/ 文件夹中查找对应的包。
📋 01.2 · 工程配置与依赖管理：package.json 常用字段、语义化版本号与 npm / pnpm 命令

📋 01.2 package.json 核心字段解析与 npm / pnpm 日常命令

每个 Node.js 项目的根目录下都有一个 package.json 文件，它是整个项目的“说明书”——既记录了项目名称、模块类型和快捷启动脚本（scripts），也记录了项目所依赖的所有第三方库及其版本范围：

📄 package.json · 标准项目配置文件逐行详解 
{
  "name": "user-service",
  "version": "1.0.0",
  // 声明当前项目下所有 .js 文件默认采用 ES Module (import/export) 语法
  "type": "module",
  // 自定义快捷脚本：通过 npm run <脚本名> 即可执行
  "scripts": {
    "dev": "node --watch --env-file=.env src/server.js",
    "start": "node src/server.js",
    "test": "node --test"
  },
  // 生产环境运行必需的依赖包（npm install <包名>）
  "dependencies": {
    "zod": "^3.23.8"
  },
  // 仅在本地开发、格式化或测试时用到的工具包（npm install -D <包名>）
  "devDependencies": {
    "eslint": "^9.14.0"
  }
}
💻 Terminal · 初始化项目与管理依赖常用命令 
# 1. 在新目录中快速生成默认的 package.json
$ npm init -y

# 2. 安装生产环境依赖（自动写入 dependencies 并更新 package-lock.json）
$ npm install zod

# 3. 安装仅开发阶段使用的依赖（写入 devDependencies）
$ npm install -D eslint

# 4. 执行 package.json 中 scripts 定义的脚本
$ npm run dev
$ npm test

# 5. 团队协作拉取代码后，根据锁文件精确还原一模一样的依赖版本
$ npm ci
💡 日常管理依赖的两个实用小贴士：
1. 读懂版本号前的符号（Major.Minor.Patch）："^3.23.8" 中的插入符 ^ 表示允许自动升级次版本号与补丁号（即 >=3.23.8 且 <4.0.0）；波浪号 "~3.23.8" 则只允许升级最后一位补丁号（<3.24.0）。
2. 一定要把锁文件（package-lock.json 或 pnpm-lock.yaml）提交到 Git 仓库：锁文件记录了每个依赖包的精确版本号与哈希校验值，能保证所有同事和线上服务器装出来的依赖完全一致。
