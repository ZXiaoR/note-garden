05.1 · 进程控制与配置：process.env 环境变量、--env-file 与优雅停机信号监听

05.1 读取环境变量（process.env）、命令行参数与优雅停机

在实际开发中，数据库密码、端口号和密钥绝不能硬编码在源码里，而是通过环境变量传入。全局对象 process 提供了读取配置与控制当前进程生命周期的全部能力：

  • process.env（环境变量字典）：自 Node.js 20.6+ 起，无需安装第三方 dotenv 库，启动时加上 node --env-file=.env app.js 即可将本地 .env 文件中的配置自动加载到 process.env 中；
  • process.argv（命令行参数数组）：数组前两项固定为 Node 可执行文件路径与当前脚本路径，因此用户传入的参数从 process.argv.slice(2) 开始获取；
  • 监听退出信号（SIGTERM / SIGINT）：当在终端按下 Ctrl + C（发送 SIGINT）或容器平台准备重启服务（发送 SIGTERM）时，可以监听信号先关闭 HTTP 服务与数据库连接，再安全退出进程。
.env 与 config.js · 原生加载环境变量配置 
# --- .env 配置文件 ---
PORT=4000
DB_URL=postgres://localhost:5432/mydb

// --- config.js（使用 node --env-file=.env config.js 启动）---
// 注意：process.env 里的值全部是字符串，端口号需用 Number() 转换
export const config = {
  port: Number(process.env.PORT || 3000),
  dbUrl: process.env.DB_URL || '',
  args: process.argv.slice(2), // 获取命令行额外参数
};
console.log('监听端口:', config.port); // 输出: 4000
graceful_exit.js · 监听停止信号实现优雅停机 
function setupGracefulShutdown(server) {
  const shutdown = (signal) => {
    console.log(`收到 ${signal} 信号，停止接收新请求并等待存量请求完成...`);
    // server.close 会拒绝新连接，并在已有请求处理完毕后触发回调
    server.close(() => {
      console.log('HTTP 服务已安全关闭，进程退出');
      process.exit(0); // 退出码 0 表示正常退出，非 0 表示异常退出
    });
  };

  process.on('SIGINT', () => shutdown('SIGINT'));
  process.on('SIGTERM', () => shutdown('SIGTERM'));
}
05.2 · 调用外部程序：execFile、spawn、exec 与 fork 四种方法对比与使用

05.2 子进程（node:child_process）：调用外部命令与脚本的四种方法

当我们需要在 Node.js 代码里调用服务器上的其他程序（如调用 git 查提交记录、调用 ffmpeg 转码视频、运行 Python 脚本或启动另一个 Node 子进程）时，使用内置的 node:child_process 模块。它提供了 4 个常用方法，核心区别在于“输出是一次性返回还是流式返回”以及“是否启动 Shell”：

方法名 输出返回方式 是否启动 Shell 日常适用场景与选型建议
1. execFile(file, args, cb)
（日常调用命令首选）		 等命令执行完，一次性返回完整字符串 / Buffer 否（直接运行程序） 适合输出较短的外部命令（如查 git 版本、调用小工具）。参数以数组形式独立传入，安全防命令注入。
2. spawn(file, args)
（长任务 / 大输出首选）		 通过 stdout 流实时一块块返回 否（默认不启动） 适合持续运行或输出体积巨大的任务（如实时读取日志流、ffmpeg 视频转码、打包构建进度输出）。
3. exec(command, cb) 一次性返回完整结果（默认上限 1MB） 是（先启动 /bin/sh） 支持 Shell 管道符（ls | grep js）与通配符，但切勿拼接用户输入参数（会有命令注入风险）。
4. fork(script.js) 自带 send() / on('message') 通信通道 否（专用于跑 JS 文件） 专门用于启动另一个 Node.js 子进程，父子进程之间可以直接收发 JSON 对象消息。
场景 A：短输出命令用 promisify(execFile) 
import { execFile } from 'node:child_process';
import { promisify } from 'node:util';

const execFileAsync = promisify(execFile);

// 参数放在独立数组中传入，不经过 Shell，安全可靠
const { stdout } = await execFileAsync('git', [
  'rev-parse',
  '--short',
  'HEAD',
]);
console.log('当前 Commit:', stdout.trim());
场景 B：持续输出的大任务用 spawn 流式读取 
import { spawn } from 'node:child_process';

// 启动子进程实时监控日志，每产生一行输出就流式打印，不占内存
const child = spawn('tail', ['-f', './app.log']);

child.stdout.on('data', (chunk) => {
  process.stdout.write(`[日志流] ${chunk}`);
});
child.on('close', (code) => {
  console.log(`子进程退出，状态码: ${code}`);
});
05.3 · 多核并发实战：worker_threads 后台计算线程与 cluster 多进程 Web 扩展

05.3 榨干多核 CPU：worker_threads（算力卸载）与 cluster（多进程服务）

默认情况下，一个 Node.js 进程只运行在 1 个 CPU 核心上。为了充分利用 8 核或 16 核服务器的性能，Node.js 提供了两套分工明确的内置模块：

  • 遇到耗时 CPU 计算（如生成大报表、图片压缩、密码哈希）➔ 用 node:worker_threads：在当前进程内部开启一个轻量后台线程专门算数据，算完通过 postMessage 把结果发回主线程，确保主线程绝不卡顿；
  • 想让 HTTP 服务跑满所有 CPU 核心 ➔ 用 node:cluster（或生产环境的 PM2）：由主进程根据 CPU 核数复制出多个独立的 Worker 子进程，共同接收同一个 8080 端口的请求，成倍提升并发吞吐量。
worker_demo.js · 用 worker_threads 在后台线程跑耗时计算 
import { Worker, isMainThread, parentPort, workerData } from 'node:worker_threads';

if (isMainThread) {
  // 【主线程】创建后台线程并传入初始参数 workerData
  const worker = new Worker(new URL(import.meta.url), {
    workerData: { limit: 1_000_000 },
  });
  worker.on('message', (res) => console.log('计算结果:', res));
} else {
  // 【Worker 线程】独立执行耗时循环，不阻塞主线程请求
  let sum = 0;
  for (let i = 1; i <= workerData.limit; i++) sum += i;
  parentPort.postMessage(sum); // 算完发回主线程
}
cluster_basic.js · 按 CPU 核数启动多进程共享 8080 端口 
import cluster from 'node:cluster';
import http from 'node:http';
import os from 'node:os';

if (cluster.isPrimary) {
  // 【主进程】有几个 CPU 核心，就派生几个 Worker 子进程
  for (let i = 0; i < os.availableParallelism(); i++) {
    cluster.fork();
  }
} else {
  // 【Worker 子进程】每个进程启动 HTTP 服务，共同处理 8080 端口请求
  http.createServer((req, res) => {
    res.end(`由子进程 PID ${process.pid} 响应`);
  }).listen(8080);
}
