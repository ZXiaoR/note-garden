04.1 · 路径与文件操作：node:path 跨平台路径拼接与 node:fs/promises 异步读写

04.1 跨平台路径（node:path）与异步文件读写（node:fs/promises）

在读写本地文件之前，首先要处理好路径：Windows 使用反斜杠 \ 分隔目录，而 macOS 与 Linux 使用正斜杠 /；同时 fs.readFile('./a.json') 中的相对路径是相对于执行命令时的终端工作目录（process.cwd()），而非当前源码文件所在目录。因此日常开发中统一使用 node:path 配合 import.meta.dirname（当前源码文件所在目录的绝对路径，Node.js 20.11+ 原生支持）来拼接路径：

path_demo.mjs · 跨平台路径拼接与文件名拆解 [Node.js 20.11+] 
import path from 'node:path';

// 1. import.meta.dirname 获取当前源码文件所在目录的绝对路径
const currentDir = import.meta.dirname;

// 2. path.join 自动按当前操作系统分隔符拼接路径，并规范化多余的 ../ 或 /
const filePath = path.join(currentDir, 'data', 'users.json');

// 3. 提取文件名、扩展名或拆解路径结构
console.log(path.basename(filePath));   // 输出: users.json
console.log(path.extname(filePath));    // 输出: .json
console.log(path.parse(filePath).name); // 输出: users
fs_promises.mjs · 异步创建目录、读写与追加小文件 [Node.js 20.11+] 
import fs from 'node:fs/promises';
import path from 'node:path';

const dir = path.join(import.meta.dirname, 'logs');
const logFile = path.join(dir, 'app.log');

// 1. 确保目录存在：recursive: true 表示父目录不存在时自动递归创建，已存在也不报错
await fs.mkdir(dir, { recursive: true });

// 2. 写入文本文件（覆盖写入）与追加内容
await fs.writeFile(logFile, '[INFO] 服务启动\n', 'utf8');
await fs.appendFile(logFile, '[INFO] 收到请求\n', 'utf8');

// 3. 读取文件内容并查看文件字节大小
const content = await fs.readFile(logFile, 'utf8');
const info = await fs.stat(logFile);
console.log('文件大小(Bytes):', info.size, '行数:', content.trim().split('\n').length);
04.2 · 二进制数据处理：Buffer 的创建、字符串互转与 Base64 / Hex 编码转换

04.2 二进制字节容器（Buffer）：创建、拼接与编码转换

当调用 fs.readFile(path) 不传第二个编码参数 'utf8' 时，返回的就是一个 Buffer 对象。Buffer 是 Node.js 专门用来在内存中存放原始二进制数据（图片、压缩包、TCP 字节分片、加密摘要）的定长字节数组；在默认 UTF-8（8-bit Unicode Transformation Format，可变长万国码编码）下，一个英文字母占 1 个字节，一个常用汉字通常占 3 个字节：

buffer_encoding.mjs · Buffer 创建、拼接与 UTF-8 / Base64 / Hex 互转 [Node.js 全版本] 
// 1. 从字符串创建 Buffer（默认按 UTF-8 编码，1 个中文字符占 3 个字节）
const buf1 = Buffer.from('你好 Node', 'utf8');
console.log(buf1.length);            // 输出: 11 (2个汉字×3字节 + 5个ASCII字符×1字节)

// 2. 创建指定长度且全部初始化为 0 的安全空白 Buffer
const buf2 = Buffer.alloc(4);       // 输出: <Buffer 00 00 00 00>

// 3. 编码转换：在 UTF-8 文本、Base64 编码与十六进制 Hex 之间互转
const base64Str = buf1.toString('base64');
console.log('Base64:', base64Str);  // 输出: 5L2g5aW9IE5vZGU=

const decoded = Buffer.from(base64Str, 'base64').toString('utf8');
console.log('还原文本:', decoded);  // 输出: 你好 Node

// 4. 拼接多个二进制分片：统一使用 Buffer.concat([块1, 块2])，不要用 + 号拼接（+ 号会强转字符串弄乱多字节中文）
const merged = Buffer.concat([Buffer.from('Hello '), Buffer.from('World')]);
console.log(merged.toString());      // 输出: Hello World
04.3 · 大文件流式处理：四种 Stream 类型与 pipeline 管道传输

04.3 流式读写（Stream）：用 pipeline 边读边写大文件

fs.readFile 会把整个文件一次性装进内存，读几 KB 的配置文件很省事；但如果遇到一个 2GB 的视频或备份压缩包，一次性读入内存就会吃掉 2GB 空间，并发一两个请求就会把容器内存撑爆（OOM，Out Of Memory，内存溢出）。
处理大文件或持续数据流时应使用 流（Stream）——像接水管一样，每次只从磁盘读出 64KB 的小块，加工完立刻写向下一站，全程内存占用稳定在几十 KB：

Stream 四种类型 定位类比 常见内置示例
1. Readable（可读流） 产出数据的“水龙头”（数据源） fs.createReadStream('input.mp4')、HTTP 服务端收到的请求对象 req
2. Writable（可写流） 接收数据的“蓄水池”（数据终点） fs.createWriteStream('output.mp4')、HTTP 服务端发出的响应对象 res
3. Duplex（双工流） 既可读又可写的双向通道（读写独立） net.Socket（底层 TCP 网络连接）
4. Transform（转换流） 中间加工站：边读入、边加工、边输出 zlib.createGzip()（边读边压缩）、crypto.createCipheriv()（边读边加密）
stream_pipeline.mjs · 用 pipeline 将大文件边读取、边 Gzip 压缩、边落盘 [Node.js 20+] 
import { createReadStream, createWriteStream } from 'node:fs';
import { writeFile } from 'node:fs/promises';
import { createGzip } from 'node:zlib';
import { pipeline } from 'node:stream/promises';

// 准备一个示例日志文件用于本地直接运行测试
await writeFile('./access.log', '2026-11-28 GET /api/orders 200\n'.repeat(1000));

// pipeline 会将「可读流 → Gzip 转换流 → 可写流」安全串联：
// 1. 自动背压控速（写得慢时自动暂停上游读取，防内存积压）
// 2. 任意一环报错或中断时，自动关闭并销毁所有打开的文件句柄（优于裸 .pipe()）
await pipeline(
  createReadStream('./access.log'),
  createGzip(),
  createWriteStream('./access.log.gz')
);
console.log('流式 Gzip 压缩完成: access.log.gz');
背后的原理：小 Buffer 是怎么在 8KB Slab 共享内存池里按 8 字节对齐切出来的？当磁盘读取速度是 500MB/s、而用户弱网下载速度只有 1MB/s 时，Stream 的背压（Backpressure）水位线状态机是怎么喊停上游的？详见 《核心原理篇 · 03 Buffer 8KB 内存池与 Stream 背压状态机》 ↗。

本章即时场景题（先想答案，再点击展开）

1. 在 src/config.js 里写了 fs.readFile('./cert.pem')，在项目根目录执行 node src/config.js 时报文件不存在，进到 src/ 目录执行却正常，为什么？

fs 模块中的所有相对路径（./）都是相对于启动命令时所在的当前工作目录（process.cwd()），而不是代码文件自身所在的文件夹。稳妥写法是用 path.join(import.meta.dirname, 'cert.pem') 将路径锚定在当前源码文件所在目录上，这样无论从哪一级目录启动进程都能准确找到文件。

2. 分块接收二进制流时，有人习惯写 let str = ''; stream.on('data', chunk => { str += chunk; })，传纯英文正常，传长篇中文为什么偶尔会出现乱码符号 �？

在 UTF-8 编码中，一个汉字占 3 个字节。网络或文件分块按固定字节边界切分时，很容易把某个汉字的前 1 个字节切在上一块末尾、后 2 个字节切在下一块开头。str += chunk 会把每一块单独强转为字符串，被劈开的半个汉字无法解码就会变成替换符 �。正确做法是用数组收集 chunks.push(chunk)，流结束后统一执行 Buffer.concat(chunks).toString('utf8')（或预先调用 stream.setEncoding('utf8') 启用内置的 StringDecoder 多字节拼接器）。

3. 为什么老代码里的 readStream.pipe(writeStream) 在生产环境不推荐再写，而应统一换成 await pipeline(readStream, writeStream)？

原生 .pipe() 只管数据转发和背压，不管异常清理：如果下游客户端下载到一半直接关掉了浏览器（writeStream 提前中断），上游打开的磁盘文件流 readStream 不会自动关闭销毁，日积月累会耗尽操作系统的文件描述符上限（报 EMFILE: too many open files）。node:stream/promises 提供的 pipeline 会在任一环节出错或关闭时自动销毁整条管道上的全部流，并支持直接用 try / catch 捕获异常。
