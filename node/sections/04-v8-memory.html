04.1 · HTTP 服务端基础：请求对象 req、响应对象 res 与 URL 查询参数解析

04.1 请求对象（req）、响应对象（res）与 URL 解析

无论是 Express、Koa 还是 NestJS 框架，它们的最底层都建立在内置的 node:http 模块之上。当调用 http.createServer((req, res) => {}) 时，每次有客户端访问服务器，回调函数就会收到两个核心对象：

  • req（http.IncomingMessage，可读流）：代表客户端发来的请求，包含请求方法 req.method（如 'GET' / 'POST'）、原始路径 req.url、请求头对象 req.headers（键名已全部自动转为小写）以及请求体字节流。
  • res（http.ServerResponse，可写流）：代表服务器将要发回给客户端的响应，通过 res.writeHead(状态码, 响应头) 设置状态与头部，通过 res.end(响应内容) 完成发送。
http_query.js · 解析 URL 路径与 ?page=1&size=10 查询参数 
import http from 'node:http';

const server = http.createServer((req, res) => {
  // 1. 使用标准 URL 类解析 req.url（第二个参数传入基础域名用于补全相对路径）
  const urlObj = new URL(req.url, `http://${req.headers.host}`);
  const pathname = urlObj.pathname;                // 如 '/api/articles'
  const page = Number(urlObj.searchParams.get('page') || 1); // 读取 ?page= 参数

  // 2. 匹配 GET /api/articles 路由并返回 JSON 数据
  if (req.method === 'GET' && pathname === '/' || pathname === '/api/articles') {
    res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
    res.end(JSON.stringify({ code: 0, page, list: ['Node.js 入门', 'HTTP 实战'] }));
    return;
  }

  // 3. 未匹配到任何路由时，返回 404 Not Found
  res.writeHead(404, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({ code: 404, message: '接口不存在' }));
});

server.listen(3000);
04.2 · 读取请求体：使用 for await...of 收集 POST JSON 请求体

04.2 读取 POST 请求体：用异步遍历拼接 JSON 数据

当客户端发起 POST 或 PUT 请求提交表单或 JSON 数据时，请求体可能很大，因此 Node.js 不会把请求体直接塞在某个属性上，而是将 req 设计为一个可读流（Readable Stream）。
在现代 Node.js 中，所有的可读流都支持 for await (const chunk of req) 异步迭代语法——只需几行代码就能把分块到达的 Buffer 收集起来并解析为 JSON 对象：

read_json_body.js · 封装通用的 JSON 请求体读取函数 
// 辅助函数：从请求流 req 中完整读取并解析 JSON 请求体
async function readJsonBody(req) {
  const chunks = [];
  // 逐块收集客户端发来的二进制 Buffer 分片
  for await (const chunk of req) {
    chunks.push(chunk);
  }
  const rawText = Buffer.concat(chunks).toString('utf8');
  return rawText ? JSON.parse(rawText) : {};
}

04.3 · 发起外部请求：使用全局内置 fetch 调用第三方接口与超时保护

04.3 客户端请求：使用全局内置 fetch 与 AbortSignal.timeout

当我们的 Node.js 服务需要作为客户端去调用其他微服务或第三方 API（如支付接口、大模型接口）时，自 Node.js 18+ 起无需再安装第三方请求库，全局已经内置了与浏览器完全一致的 fetch() 函数，并可配合 AbortSignal.timeout(毫秒) 设置请求超时时间：

🌍 fetch_client.js · 发起带超时保护的 POST JSON 请求 
async function createRemoteOrder(orderData) {
  const response = await fetch('https://api.example.com/v1/orders', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer my-secret-token',
    },
    body: JSON.stringify(orderData),
    // 设置 3000ms (3秒) 超时保护：超时后自动中断请求并抛出 TimeoutError
    signal: AbortSignal.timeout(3000),
  });

  // 注意：fetch 在遇到 404 / 500 状态码时不会自动报错，需检查 response.ok
  if (!response.ok) {
    throw new Error(`远程接口返回异常状态码: ${response.status}`);
  }
  return await response.json();
}
