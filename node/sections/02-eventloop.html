⏳ 02.1 · 异步语法演进：错误优先回调（Error-First Callback）、Promise 与 async / await

⏳ 02.1 异步编程写法：从回调函数到 async / await

在 Node.js 中，读取文件、查询数据库或请求外部接口都是非阻塞异步操作——发起调用后主线程不会停在原地干等，而是先去处理其他任务，等结果准备好后再执行后续逻辑。
Node.js 的异步写法经历了两个阶段的演进：

  • 早期传统写法（Error-First Callback 错误优先回调）：把一个回调函数作为最后一个参数传入，回调函数固定接收两个参数 (err, data) => {}——如果操作出错，第一个参数 err 为错误对象；如果成功，err 为 null，第二个参数 data 为返回结果。
  • 现代标准写法（Promise + async / await）：Node.js 标准库如今均已内置 Promise 版本（如 node:fs/promises）。配合 async / await 关键字，可以用接近同步代码的线性顺序编写异步逻辑，并用标准的 try / catch 捕获错误。
📜 callback_vs_promisify.js · 传统错误优先回调与转换 
import fs from 'node:fs';
import { promisify } from 'node:util';

// 1. 传统错误优先回调：第一个参数永远是 err，第二个参数是结果
fs.readFile('./config.json', 'utf8', (err, text) => {
  if (err) {
    console.error('读取失败:', err.message);
    return;
  }
  console.log('读取成功，字符数:', text.length);
});

// 2. 若遇到老旧第三方库只提供回调函数，可用 util.promisify 一键转为 Promise
const readFileAsync = promisify(fs.readFile);
⚡ async_await.js · 现代 async/await 与并发组合写法 
import fs from 'node:fs/promises';
import { setTimeout as sleep } from 'node:timers/promises';

async function loadDashboardData() {
  try {
    // 1. 两个互不依赖的异步读取：用 Promise.all 同时发起，总耗时取最慢的那个
    const [userRaw, orderRaw] = await Promise.all([
      fs.readFile('./users.json', 'utf8'),
      fs.readFile('./orders.json', 'utf8'),
    ]);

    // 2. 内置 timers/promises 提供无需手写 new Promise 的异步等待
    await sleep(100); // 非阻塞等待 100 毫秒
    return { users: JSON.parse(userRaw), orders: JSON.parse(orderRaw) };
  } catch (err) {
    console.error('加载数据出错:', err.message);
  }
}
🔀 02.2 · 并发任务编排：Promise.all / allSettled / race / any 四种组合方法对比

🔀 02.2 多个异步任务同时发起时，四种 Promise 组合方法怎么选

当我们需要同时发起多个异步请求（如批量查询多个接口或读取多个文件）时，如果在一个循环里逐个写 await，会变成“前一个跑完才开始跑下一个”的串行等待。根据对失败任务的处理需求，Node.js 提供了四种标准的并发组合方法：

组合方法 成功与失败触发规则 典型适用场景
Promise.all([...]) 全部成功才返回结果数组；只要有 1 个失败，整体立即抛出异常（一荣俱荣，一损俱损）。 页面初始化同时拉取多個必需的数据源（缺一不可）。
Promise.allSettled([...]) 永远不会抛出异常；等待所有任务结束后，返回每个任务的状态对象（{ status: 'fulfilled', value } 或 { status: 'rejected', reason }）。 批量发送通知、批量导入数据（允许部分成功、部分失败，最后汇总报告）。
Promise.race([...]) 哪个任务最先完成（无论成功还是失败），就采用哪个任务的结果。 配合超时计时器给某个慢操作加上超时限制。
Promise.any([...]) 哪个任务最先成功就返回谁；只有当全部任务都失败时才抛出 AggregateError。 同时向多个镜像源或备用节点发起请求，取最快响应的那个。
📡 02.3 · 事件发布与订阅：EventEmitter 的常用方法（on / once / emit / off）

📡 02.3 事件发布与订阅：node:events（EventEmitter）日常用法

除了 Promise，Node.js 还有一个贯穿整个标准库的核心设计模式——事件发布与订阅（EventEmitter）。当一个对象会在运行过程中持续发生多次状态变化（比如 HTTP 服务器不断收到新请求、文件流不断读出新数据块）时，就会继承自 node:events 模块的 EventEmitter：

  • emitter.on(事件名, 处理函数)：注册监听器，每次该事件被触发时都会执行；
  • emitter.once(事件名, 处理函数)：注册单次监听器，触发一次后自动移除，适合监听“连接建立”或“初始化完成”；
  • emitter.emit(事件名, ...参数)：触发指定事件，并把参数依次传给所有已注册的监听函数；
  • emitter.off(事件名, 处理函数)：在不需要时移除指定的监听函数，释放内存。
📡 order_events.js · 使用 EventEmitter 实现订单状态通知解耦 
import { EventEmitter } from 'node:events';

// 1. 创建一个事件中心实例
const orderBus = new EventEmitter();

// 2. 使用 on 注册持续监听：每当有 'paid' 事件发生时，依次执行库存扣减与积分发放
orderBus.on('paid', (orderId, amount) => {
  console.log(`[库存服务] 订单 ${orderId} 支付 ￥${amount}，已扣减库存`);
});

// 3. 使用 once 注册一次性监听：仅在首单支付时触发一次，之后自动解绑
orderBus.once('paid', (orderId) => {
  console.log(`[首单奖励] 恭喜完成首笔订单: ${orderId}`);
});

// 4. 始终为 EventEmitter 注册 'error' 事件监听，防止出错时未捕获导致进程退出
orderBus.on('error', (err) => {
  console.error('[事件异常]:', err.message);
});

// 5. 触发两次 'paid' 事件：
orderBus.emit('paid', 'ORD-101', 99); // 输出: [库存服务]... 和 [首单奖励]...
orderBus.emit('paid', 'ORD-102', 58); // 输出: 仅打印 [库存服务]...（once 监听器已自动移除）
