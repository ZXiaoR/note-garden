01.1 · 环境准备：Node.js LTS 版本选择、nvm 版本管理与国内镜像配置

01.1 选对 LTS 版本，用 nvm 三分钟装好开发环境

安装前先认准版本号规则：Node.js 偶数年大版本为 LTS（Long-Term Support，长期支持版，提供 30 个月稳定与安全维护），生产环境与日常开发始终只选 LTS。
截至 2026 年底，Node.js 18（2025-04 停止维护）与 Node.js 20（2026-04 停止维护）均已结束官方生命周期（EOL，End of Life，停止安全更新），不再作为推荐版本；新项目推荐安装 Node.js 26 LTS（当前 Active LTS，活跃长期支持版）或 Node.js 24 LTS（Maintenance LTS，维护期长期支持版），最低建议不低于 Node.js 22.18+ LTS（从该版本起默认支持直接运行 .ts 文件）。

为了方便在同一台电脑上随时切换不同项目的 Node 版本，主推使用社区最通用的版本管理器 nvm（Node Version Manager，Node 版本管理器）（其余工具如 n、fnm、Volta 收录于本章末尾折叠附录）：

Step 1 · 使用 nvm 安装并激活 Node.js 24 / 26 LTS 
# 1. macOS / Linux 安装 nvm（Windows 用户可直接安装同名 nvm-windows 安装包）
$ curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash

# 2. 重新打开终端后，安装并切换到 Node.js 24 LTS（也可写 nvm install --lts 装最新 26 LTS）
$ nvm install 24 && nvm use 24

# 3. 设为新开终端的默认版本，并验证 node 与内置包管理器 npm 版本
$ nvm alias default 24
$ node -v && npm -v
v24.11.0
11.0.0
Step 2 · 配置国内镜像源（npmmirror）与启用 pnpm 
# 1. 配置 npm 国内镜像源，大幅加快第三方依赖包下载速度
$ npm config set registry https://registry.npmmirror.com

# 2. （可选）若 nvm 下载 Node 本体较慢，可在 ~/.zshrc 中加上国内二进制镜像
$ export NVM_NODEJS_ORG_MIRROR=https://npmmirror.com/mirrors/node

# 3. 启用内置的 Corepack（Node.js 16.9+ 自带），免额外全局安装直接使用 pnpm
$ corepack enable && pnpm -v
编辑器断点调试小技巧（告别满屏 console.log）：使用 VS Code 开发时，无需手写复杂的 launch.json——点击底部终端面板右上角「+」旁边的下拉箭头，选择 JavaScript Debug Terminal，在代码行号左侧点出红点断点后直接运行 node hello.mjs，请求进来时就会自动停在断点处查看变量与调用栈。
01.2 · 第一个程序：编写最小 HTTP 服务，用内置 --watch 与 --env-file 启动

01.2 第一个程序：用内置 --watch 和 --env-file 跑起来

在早期教程里，刚建项目就要先装 nodemon（改代码自动重启）和 dotenv（读取本地配置文件）两个第三方包。现代 Node.js 已经把这两项高频能力直接做进了运行时命令行参数里：

  • --watch（最低要求 Node.js 18.11+ 引入，v20.13+ / v22.0+ 标记稳定）：监听入口文件及其导入的所有本地模块，按下保存键后毫秒级自动重启服务。
  • --env-file=.env（最低要求 Node.js 20.6+ 引入，v22.21+ / v24.10+ 标记稳定）：在代码执行前先把 .env 文件里的键值对注入 process.env；若某些环境没有该文件，可改用 --env-file-if-exists=.env（Node.js 22.9+）避免报错。
.env 与 hello.mjs · 第一个可复制运行的 HTTP 服务 [Node.js 20.6+] 
// 先在同目录新建 .env 文件（注意：真实项目中务必把 .env 加入 .gitignore）：
// PORT=3000
// APP_NAME=note-garden-api

// --- hello.mjs（使用 .mjs 后缀可直接写标准 import 语法，无需先建 package.json）---
import http from 'node:http';

// process.env 读取出的值一律是字符串，端口号需用 Number() 转为数字
const port = Number(process.env.PORT || 3000);
const appName = process.env.APP_NAME || 'default-app';

const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'application/json; charset=utf-8' });
  res.end(JSON.stringify({
    app: appName,
    node: process.version,
    url: req.url,
    time: new Date().toISOString(),
  }));
});

server.listen(port, () => {
  console.log(`[${appName}] 已启动: http://localhost:${port}`);
});
Terminal · 启动开发模式、验证响应与 REPL 交互试验 [Node.js 20.13+] 
# 1. 同时开启文件保存自动重启（--watch）与环境变量加载（--env-file）
$ node --watch --env-file=.env hello.mjs
[note-garden-api] 已启动: http://localhost:3000

# 2. 另开一个终端窗口，用 curl 请求本地 3000 端口验证返回结果
$ curl http://localhost:3000/hello
{"app":"note-garden-api","node":"v24.11.0","url":"/hello","time":"..."}

# 3. 交互式解释器 REPL（Read-Eval-Print Loop）：直接敲 node 回车可随手试一行 API
$ node
> Buffer.from('hello').toString('hex')
'68656c6c6f'
> .exit

📎 附录 A：其他主流版本管理工具（n / fnm / Volta）与镜像切换工具（nrm）对比速查
工具名 支持系统 核心特点与常用命令 适用人群

本章即时场景题（先想答案，再点击展开）

1. 在项目根目录新建了 .env 写入 PORT=4000，直接运行 node hello.mjs 却发现服务还是监听在了默认的 3000 端口，哪里漏了？

Node.js 默认不会自动扫描和读取目录下的 .env 文件。需要在启动命令显式加上 --env-file=.env（即 node --env-file=.env hello.mjs），或者在代码入口处主动调用 process.loadEnvFile()。此外要注意 process.env.PORT 读出来是字符串 "4000"，参与数值比较或配置校验时记得做类型转换。

2. 本地把项目跑通后顺手执行 git add . 提交代码，在环境变量管理上最容易酿成什么安全事故？标准做法是什么？

最常见的事故是把装有真实数据库密码、JWT 密钥和第三方 API Key 的 .env 文件直接推送到了 Git 仓库。标准工程规范是：建仓库第一件事把 .env 写进 .gitignore；同时提交一份去掉真实密钥、只保留变量名说明的模板文件 .env.example（如 DB_PASSWORD=your_password_here），方便其他同事拉代码后照着创建自己的本地 .env。

3. 接手维护一个历史仓库时看到文档写着「推荐安装 Node.js 18」，现在建新后端服务还能继续照着选 Node 18 吗？

不能。Node.js 18 已于 2025 年 4 月停止官方维护（Node.js 20 也已于 2026 年 4 月停止维护），不再接收任何安全漏洞补丁，而且缺少默认直跑 TypeScript（22.18+）等现代内置能力。老仓库排障可以用 nvm install 18 && nvm use 18 临时切过去跑，但新服务应直接选用处于活跃或维护周期内的 Node.js 24 / 26 LTS，并在项目根目录放一个写着 24 的 .nvmrc 文件统一团队版本。
