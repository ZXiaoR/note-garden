03 文件系统、路径处理与二进制流：path、fs/promises、Buffer 与 Stream PATH × FS/PROMISES × BUFFER × STREAM
03.1 · 路径与文件操作：node:path 跨平台路径拼接与 node:fs/promises 异步读写

03.1 跨平台路径（node:path）与异步文件读写（node:fs/promises）

在读写本地文件之前，首先要处理好文件路径：Windows 系统使用反斜杠 \ 分隔目录，而 macOS 与 Linux 使用正斜杠 /。如果直接用字符串加号拼接路径，跨系统运行时很容易出错。因此日常开发中统一使用内置的 node:path 模块，配合 import.meta.dirname（当前源码文件所在目录的绝对路径）来拼接稳健的文件路径：

path_demo.js · 跨平台路径拼接与文件名解析 
import path from 'node:path';

// 1. import.meta.dirname 获取当前文件所在的目录（Node.js 20.11+ 原生支持）
const currentDir = import.meta.dirname;

// 2. path.join 自动按当前操作系统拼接路径，并规范化多余的 ../ 或 /
const filePath = path.join(currentDir, 'data', 'users.json');

// 3. 提取文件名、扩展名或拆解路径结构
console.log(path.basename(filePath)); // 输出: users.json
console.log(path.extname(filePath));  // 输出: .json
console.log(path.parse(filePath).name); // 输出: users
fs_promises.js · 异步创建目录、读写与追加文件 
import fs from 'node:fs/promises';
import path from 'node:path';

const dir = path.join(import.meta.dirname, 'logs');
const logFile = path.join(dir, 'app.log');

// 1. 确保目录存在：recursive: true 表示父目录不存在时自动递归创建，且已存在时不报错
await fs.mkdir(dir, { recursive: true });

// 2. 写入文本文件（覆盖写入）与追加内容
await fs.writeFile(logFile, '[INFO] 服务启动\n', 'utf8');
await fs.appendFile(logFile, '[INFO] 收到请求\n', 'utf8');

// 3. 读取文件内容并查看文件字节大小
const content = await fs.readFile(logFile, 'utf8');
const info = await fs.stat(logFile);
console.log('文件大小(Bytes):', info.size);
03.2 · 二进制数据处理：Buffer 的创建、字符串互转与 Base64 / Hex 编码转换

03.2 二进制字节容器（Buffer）：创建、拼接与编码转换

当使用 fs.readFile(path) 不传第二个编码参数 'utf8' 时，返回的就是一个 Buffer 对象。Buffer 是 Node.js 专门用来在内存中存放原始二进制数据（如图片、压缩包、加密字节流）的定长字节数组，一个汉字在 UTF-8 编码下通常占用 3 个字节：

buffer_encoding.js · Buffer 创建、拼接与 UTF-8 / Base64 / Hex 互转 
// 1. 从字符串创建 Buffer（默认按 UTF-8 编码，1 个中文字符占 3 个字节）
const buf1 = Buffer.from('你好 Node', 'utf8');
console.log(buf1.length);            // 输出: 11 (2个汉字×3字节 + 5个英文字符×1字节)

// 2. 创建指定长度且全部初始化为 0 的安全空白 Buffer
const buf2 = Buffer.alloc(4);       // 输出: <Buffer 00 00 00 00>

// 3. 编码转换：在 UTF-8 文本、Base64 编码与十六进制 Hex 之间轻松互转
const base64Str = buf1.toString('base64');
console.log('Base64:', base64Str);  // 输出: 5L2g5aW9IE5vZGU=

const decoded = Buffer.from(base64Str, 'base64').toString('utf8');
console.log('还原文本:', decoded);  // 输出: 你好 Node

// 4. 拼接多个 Buffer 数据块：使用 Buffer.concat([块1, 块2])
const merged = Buffer.concat([Buffer.from('Hello '), Buffer.from('World')]);
console.log(merged.toString());      // 输出: Hello World
03.3 · 大文件流式处理：四种 Stream 类型与 pipeline 管道传输

03.3 流式读写（Stream）：用 pipeline 边读边写大文件

fs.readFile 会把整个文件一次性装进内存，非常适合几 KB 到几 MB 的配置文件；但如果要拷贝或压缩一个 2GB 的视频或日志文件，一次性读入内存就会占用高达 2GB 的空间。
这时就应该使用 流（Stream）——像接水管一样，每次只从磁盘读出 64KB 的小数据块，处理完立刻写入目标文件，整个过程内存占用始终保持在几十 KB 以内。Node.js 共有四种流基类：

Stream 四种类型 通俗定位 常见内置示例
1. Readable（可读流） 产出数据的“水龙头”（数据源） fs.createReadStream('input.mp4')、HTTP 服务端收到的请求对象 req
2. Writable（可写流） 接收数据的“蓄水池”（数据终点） fs.createWriteStream('output.mp4')、HTTP 服务端发出的响应对象 res
3. Duplex（双工流） 既可读又可写的双向通道（读写相互独立） net.Socket（TCP 网络套接字连接）
4. Transform（转换流） 中间加工站：读入原始数据，实时加工后输出 zlib.createGzip()（边读边压缩）、crypto.createCipheriv()（边读边加密）
stream_pipeline.js · 使用 pipeline 将大文件边读取、边 Gzip 压缩、边写入磁盘 
import { createReadStream, createWriteStream } from 'node:fs';
import { createGzip } from 'node:zlib';
import { pipeline } from 'node:stream/promises';

async function compressLargeLog() {
  // pipeline 会自动将「可读流 → Gzip 转换流 → 可写流」串联起来：
  // 不仅自动协调上下游读写速度，而且任意一环出错时会自动关闭所有文件句柄
  await pipeline(
    createReadStream('./access.log'),
    createGzip(),
    createWriteStream('./access.log.gz')
  );
  console.log('大文件流式压缩完成');
}
