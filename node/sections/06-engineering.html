🗂️ 06.1 · 工程目录架构：企业级 Node.js 项目的标准分层目录（routes / controllers / services / middlewares）

🗂️ 06.1 实际开发中，一个标准 Node.js 项目的目录是怎么搭建的

在写小脚本时，我们可以把代码都放在一个 app.js 里；但在实际团队开发中，一个后端或 BFF 服务往往包含几十个业务接口、参数校验、权限拦截和数据库访问。Node.js 工程普遍采用职责清晰的四层标准目录结构（入口与路由层 → 控制器层 → 业务逻辑层 → 数据访问层）：

📂 order-service/ · 真实 Node.js 项目的标准目录树 
order-service/
├── package.json            # 项目依赖与启动脚本（声明 "type": "module"）
├── package-lock.json       # 依赖版本精确锁定文件
├── .env                    # 本地环境变量配置（不提交到 Git）
├── src/
│   ├── server.js           # 【启动入口】读取端口配置，启动 HTTP Server 并绑定优雅停机
│   ├── app.js              # 【应用组装】挂载全局中间件与路由表（便于单元测试直接引入）
│   ├── config/
│   │   └── index.js        # 统一收敛 process.env 环境变量并提供默认值
│   ├── middlewares/
│   │   └── logger.js       # 【中间件层】请求耗时日志、身份鉴权、统一异常兜底
│   ├── routes/
│   │   └── order.route.js  # 【路由层】将 URL 路径映射给对应的 Controller 方法
│   ├── controllers/
│   │   └── order.ctrl.js   # 【控制器层】解析 req 参数，调用 Service，组装 res JSON
│   ├── services/
│   │   └── order.svc.js    # 【业务逻辑层】核心订单计算、库存检查、事务编排
│   └── repositories/
│       └── order.repo.js   # 【数据访问层】负责读写 MySQL / PostgreSQL / Redis
└── test/
    └── order.test.js       # 【测试目录】使用内置 node:test 编写接口与单元测试
🧭 核心目录的职责边界与拆分原因
  • server.js 与 app.js 分离：app.js 只定义请求处理逻辑而不直接调用 listen(端口)，这样跑自动化测试时可以直接引入 app.js 而不必担心端口冲突。
  • middlewares/（横切关注点）：把每个接口都要做的公共操作（打印日志、校验登录 Token、捕获未处理异常）抽成中间件，避免在业务代码里重复编写。
  • controllers → services → repositories 三层解耦：controller 只管 HTTP 协议的入参和状态码；service 只管纯业务规则；repository 只管 SQL 或缓存读写，哪一层需要修改都不会牵连其他层。

💻 06.2 端到端代码实战：从业务逻辑层、HTTP 入口到单元测试

下面我们把前面学到的模块化、async / await、node:http 与错误处理串联起来，实现一个包含业务逻辑层（order.svc.js）、HTTP 应用入口（app.js）以及内置单元测试（order.test.js）的完整可运行项目：

🟢 src/services/order.svc.js & src/app.js · 业务层与接口层实现 
// --- 1. src/services/order.svc.js（纯业务逻辑层）---
const orders = [{ id: 1, item: '机械键盘', price: 299 }];

export async function listOrders() {
  return orders;
}

export async function createOrder({ item, price }) {
  if (!item || typeof price !== 'number' || price <= 0) {
    throw new Error('商品名称不能为空且价格必须大于 0');
  }
  const newOrder = { id: orders.length + 1, item, price };
  orders.push(newOrder);
  return newOrder;
}

// --- 2. src/app.js（HTTP 路由与统一异常兜底）---
import http from 'node:http';

export function createApp() {
  return http.createServer(async (req, res) => {
    const start = Date.now();
    res.setHeader('Content-Type', 'application/json; charset=utf-8');

    try {
      if (req.method === 'GET' && req.url === '/api/orders') {
        const data = await listOrders();
        res.writeHead(200);
        res.end(JSON.stringify({ code: 0, data }));
        return;
      }
      res.writeHead(404);
      res.end(JSON.stringify({ code: 404, message: 'Not Found' }));
    } catch (err) {
      res.writeHead(400);
      res.end(JSON.stringify({ code: 400, message: err.message }));
    } finally {
      console.log(`[${req.method}] ${req.url} - ${res.statusCode} (${Date.now() - start}ms)`);
    }
  });
}
🧪 test/order.test.js · 使用内置 node:test 编写单元测试 
// Node.js 20+ 内置测试运行器 node:test 与严格断言库 node:assert/strict
import { test, describe } from 'node:test';
import assert from 'node:assert/strict';
import { createOrder, listOrders } from '../src/services/order.svc.js';

describe('订单服务单元测试 (order.svc.js)', () => {
  test('正常创建订单并返回递增 ID', async () => {
    const created = await createOrder({ item: '无线鼠标', price: 129 });
    assert.equal(created.item, '无线鼠标');
    assert.equal(created.price, 129);

    const all = await listOrders();
    assert.equal(all.length, 2);
  });

  test('传入非法价格时应抛出参数校验异常', async () => {
    await assert.rejects(
      async () => await createOrder({ item: '测试商品', price: -10 }),
      { message: '商品名称不能为空且价格必须大于 0' }
    );
  });
});

// 终端直接执行: $ node --test
// ✔ 正常创建订单并返回递增 ID (1.2ms)
// ✔ 传入非法价格时应抛出参数校验异常 (0.5ms)
// ℹ pass 2 / fail 0
