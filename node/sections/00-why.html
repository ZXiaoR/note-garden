00.1 · 运行时定位：Node.js 的设计特点与常见应用领域

00.1 Node.js 的设计特点与常见应用领域

在早期 Web 开发中，JavaScript 只能在浏览器里运行，用来操作页面 DOM 和发起网络请求。2009 年，Ryan Dahl 基于 Google Chrome 的 V8 引擎与跨平台异步 I/O 库 libuv 构建了 Node.js——它是一个让 JavaScript 脱离浏览器、直接在服务器和本地操作系统上运行的跨平台 JavaScript 运行时（Runtime）：

① 前后端统一使用 JavaScript / TypeScript
前端与服务端共享同一套语法、类型定义（interface / type）与参数校验逻辑，天然适合全栈开发与服务端渲染（SSR）。
② 非阻塞异步 I/O，擅长高并发网络服务
遇到文件读写、数据库查询或外部 HTTP 调用时不会原地阻塞主线程，单个进程即可同时维护数万个并发网络连接。
③ 丰富的标准库与 npm 开源生态
内置文件（node:fs）、网络（node:http）、流（node:stream）等系统级 API，并拥有全球规模最大的 npm 包生态。

💼 在实际开发中，我们通常用 Node.js 来写什么？
1. Web 后端接口与 BFF（Backend For Frontend）聚合中间层（如 NestJS / Koa / Fastify 接口服务、SSR 服务端渲染、AI 流式网关）；
2. 前端工程化与命令行工具（CLI）（Vite、Webpack、ESLint、TypeScript 编译器以及各类自动化构建脚手架均运行在 Node.js 上）；
3. 实时通信服务与跨平台桌面客户端（WebSocket 实时推送、在线协作文档、基于 Electron 的 VS Code 桌面应用）。

00.2 · 环境搭建：Node.js 版本管理工具（n / nvm / fnm / Volta）、国内镜像源（nrm）与开发工具准备

00.2 开发环境安装、多版本管理工具与国内镜像配置

在实际开发中，一台电脑往往要同时维护多个时期的项目（例如老项目依赖 Node.js 18，新项目使用 Node.js 22 LTS）。因此除了去官网（nodejs.org）直接下载安装包外，工程师通常会使用多版本管理工具（n、nvm、fnm 或 Volta）来随时安装和切换不同版本的 Node.js：

Step 1 · 使用版本管理工具安装与切换 Node.js 22 LTS 
# 【工具一：n】极简交互式版本管理（macOS / Linux 常用，无需配复杂 Shell 钩子）
$ npm install -g n                    # 若已有 node 可直接通过 npm 全局安装（或 brew install n）
$ sudo n lts                          # 一键下载并激活最新 LTS 长期支持版（或 sudo n 22）
$ n                                   # 直接输入 n，用键盘上下方向键交互式切换已安装的各个版本

# 【工具二：nvm】最经典的多版本管理器（各版本全局包完全隔离）
$ nvm install 22 && nvm use 22        # 安装并切换到 Node.js 22
$ nvm alias default 22                # 将 22 设为新终端默认版本

# 【工具三：fnm】Rust 编写的跨平台极速管理器（支持 macOS / Windows / Linux）
$ fnm install 22 && fnm default 22
Step 2 · 配置国内镜像源（npmmirror / nrm）与启用 pnpm 
# 1. 验证 node 与内置 npm 是否安装成功
$ node -v && npm -v
v22.11.0
10.9.0

# 2. 配置 npm 国内镜像源（或使用 nrm 工具在淘宝源/官方源/公司私服间一键切换）
$ npm config set registry https://registry.npmmirror.com
$ npx nrm use taobao                  # 也可使用 nrm 快速切换源（npx nrm ls 查看所有源）

# 3. 配置 n / nvm 下载 Node.js 本体时的国内二进制加速镜像
$ export N_NODE_MIRROR=https://npmmirror.com/mirrors/node

# 4. 启用 Node.js 内置的 Corepack，无需额外安装即可直接使用 pnpm / yarn
$ corepack enable && pnpm -v
工具 / 概念 支持系统 核心设计特点与常用命令 选型与使用建议
1. n macOS / Linux / WSL • 由 Express 作者 TJ 编写，无需修改终端启动脚本，直接覆盖更新系统目录（默认 /usr/local）下的 node 二进制文件。
• 常用命令：n lts、n 20、输入 n 回车上下键切换、n rm 18.19.0。		 喜欢极简命令行交互的 macOS / Linux 开发者首选；可通过设置环境变量 export N_PREFIX=$HOME/.n 免去每次输入 sudo。
2. nvm macOS / Linux（Windows 用 nvm-windows） • 社区历史最久，将每个 Node 版本安装在独立目录（~/.nvm/versions/node/v22.x），不同版本的全局 npm -g 包彼此隔离。
• 常用命令：nvm ls、nvm install 22、nvm use 22。		 需要严格隔离不同 Node 版本全局依赖包时非常适合；缺点是每次打开新终端加载 Shell 脚本稍慢（约 0.2~0.5 秒）。
3. fnm 全平台（macOS / Windows / Linux） • 使用 Rust 编写的现代替代方案，终端启动耗时在毫秒级，同时兼容读取项目根目录的 .nvmrc 与 .node-version 文件。
• 常用命令：fnm install 22、fnm use 22、fnm default 22。		 追求终端秒开速度、或者同时使用 Windows 与 macOS 开发的工程师推荐选用。
4. Volta 全平台（macOS / Windows / Linux） • 基于垫片（Shim）机制的团队版本锁定工具：执行 volta pin node@22 pnpm@9 会将版本号直接写入项目 package.json。 非常适合多人协作团队：新同事拉下代码进入目录运行命令时，Volta 会自动按 package.json 切换到一致的 Node 与包管理器版本。
5. nrm 与 Corepack 全平台通用 • nrm（镜像源管理器）：通过 nrm ls / nrm use taobao / nrm test 一键测速并切换 npm 镜像源；
• Corepack（内置包管理器桥接）：Node.js 16.9+ 自带，执行 corepack enable 即可激活 pnpm 与 yarn。		 日常装包用国内 taobao (npmmirror) 源；当需要执行 npm publish 发布自己的开源包时，用 nrm use npm 切回官方源即可。
6. LTS vs Current 版本号规范 • 偶数年号（如 v20 / v22）为 LTS（长期支持版），提供长达 30 个月的安全与稳定维护；
• 奇数年号（如 v21 / v23）为 Current 尝鲜版，维护期仅 6 个月。		 个人学习与企业生产环境请始终选择偶数年号的 LTS 版本，第三方 C++ 原生插件与框架兼容性最好。
代码编辑器（IDE）与调试工具建议：
• VS Code（免费首选）：自带完整的 JavaScript / TypeScript 智能提示与内置断点调试器（打开终端面板旁边的下拉箭头，选择 JavaScript Debug Terminal，直接在代码行号旁点击打上红点并运行 node app.js 即可单步调试）；推荐安装 ESLint（代码检查）与 Prettier（保存自动格式化）两个扩展。
• JetBrains WebStorm：开箱即用，内置了对多版本 Node.js 切换、npm / pnpm 脚本树与单元测试的图形化支持。
00.3 · 第一个程序：最小脚本与原生 HTTP 服务的编写及运行命令

00.3 第一个 Node.js 程序：最小脚本与运行命令

安装好 Node.js 后，只需新建一个 .js 文件，即可在终端通过 node 文件名.js 直接执行。下面展示最基础的脚本与一个 10 行代码的内置 HTTP 服务：

hello.js · 第一个 Node.js 脚本与 HTTP 服务 
// 1. 导入 Node.js 内置的 http 模块（推荐带上 node: 官方前缀）
import http from 'node:http';

// 2. 打印当前运行环境的 Node.js 版本与操作系统平台
console.log(`运行版本: ${process.version}, 平台: ${process.platform}`);

// 3. 创建一个最小 HTTP 服务并监听本地 3000 端口
const server = http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain; charset=utf-8' });
  res.end('Hello, Node.js\n');
});

server.listen(3000, () => {
  console.log('服务已启动: http://localhost:3000');
});
Terminal · 常用运行与开发调试命令 
# 1. 直接运行脚本文件
$ node hello.js
运行版本: v22.11.0, 平台: darwin
服务已启动: http://localhost:3000

# 2. 开发模式：使用内置 --watch 参数，保存文件后自动重启进程
$ node --watch hello.js

# 3. 交互式命令行（REPL）：不带文件名直接输入 node，可随时测试一行 JS 表达式
$ node
> Buffer.from('hello').toString('hex')
'68656c6c6f'
00.4 · 环境全景：浏览器与 Node.js 环境差异、全局对象与核心内置模块速查

00.4 运行环境全景：全局对象与核心内置模块分类表

从浏览器转向 Node.js 开发时，首先需要明确运行环境的边界：Node.js 中没有浏览器的 window、document 等 DOM / BOM 对象，取而代之的是控制进程、内存和系统底层资源的全局对象与内置核心模块：

分类 常用全局对象 / 核心内置模块 主要功能与日常使用场景
1. 全局对象（无需导入） globalThis、process、Buffer、console、fetch、setTimeout / setImmediate • process：读取环境变量（process.env）、命令行参数、当前工作目录与进程退出控制；
• Buffer：在内存中直接存放和操作原始二进制字节数据；
• fetch / URL：与现代浏览器保持一致的 Web 标准网络请求与 URL 解析接口。
2. 文件与路径模块 node:fs（及 node:fs/promises）、node:path、node:os • node:fs/promises：基于 Promise 异步读写文件、创建目录、查看文件大小；
• node:path：自动抹平 Windows（\）与 macOS/Linux（/）路径分隔符差异；
• node:os：查询服务器 CPU 核数、可用内存与临时目录。
3. 事件与流式传输 node:events、node:stream、node:zlib • node:events：提供 EventEmitter 事件发布/订阅基类（Node.js 中大量对象的底层基石）；
• node:stream：以小块字节流的方式边读边写大文件或网络数据，避免撑爆内存。
4. 网络与安全加密 node:http、node:https、node:net、node:crypto • node:http：创建 HTTP 服务端或客户端；node:net 处理底层 TCP 套接字；
• node:crypto：生成随机 UUID、计算 SHA-256 哈希摘要、加解密与签名校验。
5. 多进程、多线程与测试 node:child_process、node:worker_threads、node:cluster、node:test • child_process 执行外部 Shell/系统命令；worker_threads 开启多线程处理耗时计算；
• node:test + node:assert：无需安装第三方测试框架即可直接运行单元测试。
