🧭 00.1 · 架构定位：内存键值状态层与磁盘关系型数据库的协同分工

🧭 00.1 Redis 解决的核心问题与系统分工

Redis（Remote Dictionary Server，远程字典服务）是一个基于内存运行、支持可选磁盘持久化的键值（Key-Value）数据存储系统。在实际工程架构中，MySQL 或 PostgreSQL 等关系型数据库承担着持久化账本、多表关联查询与严格 ACID 事务的职责，每次修改都需要维护磁盘页结构与事务日志，单实例通常面向数千至上万 QPS 的复杂读写；而当系统面临商品详情页、会话登录态、实时排行榜、计数器限流等每秒数万至十万级的低延迟简单读写时，直接将所有流量压向磁盘数据库会导致连接池耗尽与响应延迟升高。

因此，现代后端系统普遍采用「Redis 内存加速与状态协调层 + 关系型数据库持久化底座」的分层协同架构：由 Redis 在内存中以亚毫秒级（通常 < 1ms）响应高频读写与跨进程原子协调，由 MySQL / PostgreSQL 负责数据的最终持久化落盘与复杂统计分析。

应用维度 Redis 典型业务角色 与关系型数据库的分工边界
① 高速旁路缓存 商品详情、用户信息、首页配置、热点资讯列表缓存 Redis 存高频读取的热点数据并设置过期时间（TTL）；MySQL 保存全量历史数据作为唯一事实来源（Source of Truth）。
② 共享会话与状态 分布式登录 Session、短信验证码（5 分钟自动失效）、OAuth 令牌黑名单 多台无状态应用实例共享同一份带自动过期能力的内存状态，避免将短生命周期临时数据频繁写入磁盘表。
③ 原生排行榜与聚合 直播间礼物实时榜、游戏战力排名、亿级 UV 去重统计、附近门店搜索 借助 ZSet、HyperLogLog、GEO 在内存中以 O(log N) 或 O(1) 完成实时计算，免去高成本的 ORDER BY 与 COUNT(DISTINCT) 扫表。
④ 跨进程并发协调 接口滑动窗口限流、秒杀库存预扣减、防重复提交互斥锁、轻量异步队列 利用单线程串行执行命令与 Lua 脚本的原子性充当前置流量漏斗；核心账务最终结果仍落盘至关系型数据库。

🛠️ 00.2 环境安装与核心配置规范

日常本地开发与测试推荐使用 Docker Compose 或系统包管理器安装 Redis 7.2 LTS（长期支持版，向下完整兼容 6.x 语法）。下面列出三种主流环境的安装启动方式：

🐳 docker-compose.yml · 容器化启动 Redis 7.2 
services:
  redis:
    image: redis:7.2-alpine
    container_name: local-redis
    ports:
      - "6379:6379"
    volumes:
      - ./redis-data:/data
    command: >
      redis-server
      --requirepass DevPass_2026
      --appendonly yes
      --aof-use-rdb-preamble yes
      --maxmemory 512mb
      --maxmemory-policy allkeys-lru
    restart: unless-stopped
💻 macOS Homebrew / Ubuntu APT 本地安装 
# === macOS (Homebrew) ===
brew install redis
# 后台服务启动（配置文件位于 /opt/homebrew/etc/redis.conf）
brew services start redis

# === Ubuntu / Debian Linux ===
sudo apt-get update && sudo apt-get install -y redis-server
sudo systemctl enable --now redis-server
sudo systemctl status redis-server

核心配置文件 redis.conf 生产必检参数表

无论是裸机部署还是容器挂载自定义配置文件，上线前都应重点核对以下 6 项基础安全与资源边界参数：

配置指令与推荐示例 默认值 参数含义与工程注意事项
bind 127.0.0.1 10.0.1.15 127.0.0.1 -::1 指定允许接收连接的本机网卡地址。生产环境仅绑定内网网卡 IP，切勿在无防火墙保护的公网机器上配置 bind 0.0.0.0。
protected-mode yes yes 安全保护模式：当未显式绑定 IP 且未设置访问密码时，拒绝一切外部机器连接，仅允许本机回环地址访问。
requirepass <强密码>
或 6.0+ ACL SETUSER		 空（无密码） requirepass 设置默认用户 default 的连接密码；Redis 6.0+ 支持细粒度 ACL 权限控制，可为不同微服务创建独立账号并限制允许执行的命令类别（例如禁止业务账号调用 FLUSHALL / KEYS）。
databases 16 16 单实例默认提供编号 0 ~ 15 共 16 个逻辑数据库（默认进入 db0）。生产环境推荐不同业务使用不同 Key 业务前缀或独立实例隔离，而非依赖 SELECT 切换逻辑库（Redis Cluster 集群模式仅支持 db0）。
maxmemory 4gb 0（64位不限） 实例最大可用物理内存上限。生产环境必须显式配置，一般设为机器可用内存的 70% 左右，为操作系统、主从复制缓冲区与后台子进程预留安全余量。
daemonize no / supervised systemd no 裸机后台运行设为 daemonize yes；在 Docker 容器内运行必须保持 daemonize no（以前台主进程方式运行，否则容器启动后会立即退出）。

🚀 00.3 使用 redis-cli 与编写第一个客户端程序

安装启动完成后，可以先使用官方自带的命令行客户端 redis-cli 验证连通性、配置业务专用 ACL 只读/读写账号，再通过应用程序连接池访问 Redis。注意命令行添加 --raw 参数可以让包含中文 UTF-8 字符的返回值直接原样显示，而非十六进制转义序列（如 \xe5\xbc\xa0）。

⌨️ redis-cli · 连接验证、ACL 细粒度建号与第一次键值读写 
# 1. 连接本地实例并启用 UTF-8 中文原样输出 (--raw)
redis-cli -h 127.0.0.1 -p 6379 --raw

# 2. 身份认证与连通性探活（返回 PONG 表示服务就绪）
127.0.0.1:6379> AUTH DevPass_2026
OK
127.0.0.1:6379> PING
PONG

# 3. Redis 6.0+ 创建最小权限业务账号 order_svc：
#    on(启用) >密码 ~order:*(仅允许访问 order: 前缀的 Key) +@read +@write -@dangerous(禁用高危管理命令)
127.0.0.1:6379> ACL SETUSER order_svc on >OrderSvc_Secret ~order:* +@read +@write -@dangerous
OK

# 4. 写入一条 300 秒后自动过期的订单缓存并读取验证
127.0.0.1:6379> SET order:10001 "待支付-张小荣" EX 300
OK
127.0.0.1:6379> GET order:10001
待支付-张小荣
127.0.0.1:6379> TTL order:10001
296

在实际后端服务中，客户端通过 TCP 长连接池与 Redis 通信（底层使用文本结构清晰的 RESP 序列化协议）。禁止每次请求临时新建和销毁 TCP 连接。以下是使用 Go 官方维护的 github.com/redis/go-redis/v9 初始化生产级连接池并完成读写、过期判断的最小可运行示例：

🐹 main.go · 使用 go-redis/v9 连接池完成键值读写与 redis.Nil 空值判定 
package main

import (
    "context"
    "errors"
    "fmt"
    "log"
    "time"

    "github.com/redis/go-redis/v9"
)

func main() {
    // 1. 创建进程级全局单例 Client（内部自带协程安全的 TCP 连接池，切勿每次请求重新 NewClient）
    rdb := redis.NewClient(&redis.Options{
        Addr:         "127.0.0.1:6379",
        Username:     "order_svc",       // 若未启用独立 ACL 账号，留空即可
        Password:     "OrderSvc_Secret", // 对应 requirepass 或 ACL 密码
        DB:           0,                 // 默认使用 db0
        PoolSize:     32,                // 连接池最大并发连接数
        MinIdleConns: 8,                 // 保活的最小空闲连接数，避免突发流量冷建连延迟
        DialTimeout:  2 * time.Second,
        ReadTimeout:  500 * time.Millisecond,
        WriteTimeout: 500 * time.Millisecond,
    })
    defer rdb.Close()

    ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
    defer cancel()

    // 2. 启动时探活校验连接池配置
    if err := rdb.Ping(ctx).Err(); err != nil {
        log.Fatalf("连接 Redis 失败: %v", err)
    }

    // 3. 写入键值并绑定 5 分钟过期时间（等价于 SET order:10002 "已支付" EX 300）
    if err := rdb.Set(ctx, "order:10002", "已支付", 5*time.Minute).Err(); err != nil {
        log.Fatalf("写入失败: %v", err)
    }

    // 4. 读取键值：必须严格区分「键不存在 (redis.Nil)」与「真正的网络/超时错误」
    val, err := rdb.Get(ctx, "order:10002").Result()
    if errors.Is(err, redis.Nil) {
        fmt.Println("缓存未命中，准备回源查询数据库")
    } else if err != nil {
        log.Fatalf("读取 Redis 发生异常: %v", err)
    } else {
        fmt.Printf("缓存命中: order:10002 = %s\n", val)
    }
}
