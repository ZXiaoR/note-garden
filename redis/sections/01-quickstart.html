01.1 · 最小环境搭建：Docker 一行启动 Redis 7.x、redis-cli 命令行与 RedisInsight 可视化

01.1 一行命令启动 Redis 与连接工具准备

本地开发最省心的方式是用 Docker 直接启动官方 Redis 7.2 LTS（Long-Term Support，长期支持版，完全兼容 6.x 常用命令）镜像；若未安装 Docker，macOS 也可直接执行 brew install redis && brew services start redis。细粒度权限与生产配置文件参数我们留到 07 · 上线前必知 再展开，现在先把服务跑起来：

quickstart_docker.sh · 一行启动 Redis 并进入交互式命令行 [Redis 6.x / 7.x] 
# 1. 后台启动 Redis 7.2 容器，映射本机 6379 端口，设置开发环境密码 DevPass_2026
docker run -d --name local-redis -p 6379:6379 redis:7.2-alpine \
  redis-server --requirepass DevPass_2026 --appendonly yes

# 2. 使用容器自带的命令行工具 redis-cli 连接（--raw 让中文直接原样显示，不转成 \xe5 十六进制）
docker exec -it local-redis redis-cli -a DevPass_2026 --raw

# 3. 输入 PING 测试连通性，收到 PONG 即说明服务已就绪
127.0.0.1:6379> PING
PONG

搭配可视化工具调试更直观：除了终端里的 redis-cli（CLI，Command-Line Interface，命令行界面），推荐安装 Redis 官方免费的桌面图形界面工具 RedisInsight（GUI，Graphical User Interface，图形用户界面）。新建连接填入 127.0.0.1、端口 6379 和密码 DevPass_2026，它会自动把以冒号 : 分隔的键折叠成树状目录，实时展示每个键的数据类型、内容与倒计时过期秒数。

01.2 · 最小命令闭环：SET / GET / EXISTS / EXPIRE / TTL / DEL 动手实操

01.2 先敲通最核心的 6 条命令

不用一上来背上百个命令，先把「写入、读取、判断存在、设置过期时间、查看剩余寿命、删除」这 6 条每天都会用到的基础命令在 redis-cli 里敲一遍：

first_six_cmds.redis · 最小命令闭环实操 [Redis 6.x / 7.x] 
# 1. SET：写入键值对（把用户 1001 的昵称存进去）
SET user:1001:name "林晓"
# -> OK

# 2. GET：按键名读取值（若键不存在，--raw 模式下返回空行，普通模式下显示 (nil)）
GET user:1001:name
# -> 林晓

# 3. EXISTS：判断键是否存在（1 表示存在，0 表示不存在）
EXISTS user:1001:name
# -> 1

# 4. EXPIRE：为已存在的键设置 60 秒过期时间（到期后 Redis 自动删除它）
EXPIRE user:1001:name 60
# -> 1
# 提示：日常开发更推荐一步写完：SET user:1001:name "林晓" EX 60

# 5. TTL（Time To Live，过期时间）：查看还剩多少秒过期
TTL user:1001:name
# -> 57（正数代表剩余秒数；-1 代表键存在但永不过期；-2 代表键不存在或已过期）

# 6. DEL：主动删除键，返回实际删除的键个数
DEL user:1001:name
# -> 1

01.3 在业务代码里连接并读写 Redis

应用程序通过 TCP（Transmission Control Protocol，传输控制协议）长连接池，使用轻量的文本协议 RESP（REdis Serialization Protocol，Redis 序列化协议）与服务端通信。无论用哪种语言，都应在进程启动时创建一个全局复用的客户端连接池实例，不要在每次接口请求里重复新建和关闭连接。

main.go · Go go-redis/v9 连接示例 [Redis 6.x / 7.x] 
// 安装依赖: go get github.com/redis/go-redis/v9
package main

import (
    "context"
    "errors"
    "fmt"
    "log"
    "time"

    "github.com/redis/go-redis/v9"
)

func main() {
    ctx := context.Background()
    // 1. 创建全局单例 Client（内部自带协程安全连接池）
    rdb := redis.NewClient(&redis.Options{
        Addr:     "127.0.0.1:6379",
        Password: "DevPass_2026",
        DB:       0,
    })
    defer rdb.Close()

    // 2. 写入键值并设置 5 分钟过期（SET ... EX 300）
    err := rdb.Set(ctx, "order:1001:status", "待支付", 5*time.Minute).Err()
    if err != nil {
        log.Fatal(err)
    }

    // 3. 读取键值：注意区分「键不存在 (redis.Nil)」与网络报错
    val, err := rdb.Get(ctx, "order:1001:status").Result()
    if errors.Is(err, redis.Nil) {
        fmt.Println("键不存在或已过期")
    } else if err != nil {
        log.Fatal(err)
    } else {
        fmt.Println("读取结果:", val)
    }
}
demo.mjs · Node.js ioredis 连接示例 [Redis 6.x / 7.x] 
// 安装依赖: npm install ioredis
import Redis from 'ioredis';

// 1. 初始化全局客户端（自动维护长连接与断线重连）
const redis = new Redis({
  host: '127.0.0.1',
  port: 6379,
  password: 'DevPass_2026',
  db: 0,
});

async function main() {
  // 2. 写入键值并设置 300 秒过期（SET key val EX 300）
  await redis.set('order:1001:status', '待支付', 'EX', 300);

  // 3. 读取键值：键不存在时 ioredis 直接返回 null
  const val = await redis.get('order:1001:status');
  const ttl = await redis.ttl('order:1001:status');

  if (val === null) {
    console.log('键不存在或已过期');
  } else {
    console.log(`读取结果: ${val}，剩余 ${ttl} 秒`);
  }

  await redis.quit();
}

main().catch(console.error);

背后的原理：执行 SET ... EX 与 GET 时，Redis 在内存里同时维护了一张「主键值对字典」和一张「过期时间字典」，并让它们共享同一个键名对象以节省内存——详见 《 核心原理篇 · 00.2 redisDb 全局字典与过期字典寻址链路》。
