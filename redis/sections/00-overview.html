00.1 Redis 是什么，以及为什么系统需要它

一句话定义：Redis（Remote Dictionary Server，远程字典服务）是一个主要在内存（RAM，Random Access Memory，随机存取内存）中读写数据的键值（Key-Value）数据库。

用餐厅打个比方：关系型数据库 MySQL 就像后厨的大型冷库与总账本——容量大、分门别类、断电不丢账，但每次进库翻找和登记都要花几毫秒到几十毫秒；当大促或热门帖子涌入每秒几万次查询（QPS，Queries Per Second，每秒查询率）时，所有请求都挤进冷库会把后厨彻底堵死。而 Redis 就像收银台手边的保温备菜架——把最常点的热销商品、当前剩余库存、用户登录牌直接摆在伸手就能拿到的内存里，不到 1 毫秒（ms） 即可响应。

2. 什么时候不该用 Redis（三类不适用边界）

  • 需要多条件筛选与多表关联的复杂查询：Redis 只能通过精确的 Key 拿数据，无法原生执行类似 WHERE status = 1 AND city = '上海' AND amount > 100 的组合过滤或关联统计，这类需求必须用 MySQL / PostgreSQL 索引或 Elasticsearch。
  • 绝对不能丢一分钱的强一致账本与复杂回滚事务：关系型数据库具备完整的 ACID（Atomicity, Consistency, Isolation, Durability，原子性、一致性、隔离性、持久性）事务与预写日志同步落盘；而 Redis 断电或主从切换可能丢失最后约 1 秒数据，且事务报错不支持回滚（Rollback），因此账户余额、已支付订单等权威账本必须落在关系型数据库。
  • 历史冷数据体量远超内存预算：例如几 TB 的全年操作日志或历史归档订单。内存每 GB 成本远高于磁盘，Redis 只应存放近期高频访问的热点数据并配合过期淘汰。
